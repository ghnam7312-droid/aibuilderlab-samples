# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버 작업 정의([ai-task.json](ai-task.json))의 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 5개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 4주 | 개인정보 | 설문 응답에서 학번(20으로 시작하는 8자리), 휴대전화, 이메일을 찾아 [학번]처럼 바꿔 줘. 연도 같은 숫자는 건드리지 말고. |
| 4주 | 기준 고정 | 분류 이름을 매번 새로 만들지 말고, 내가 주는 기준 5개(이름·정의·예시) 중 하나만 고르게 지시문을 다시 써 줘. 안 맞으면 ‘검토 필요’. |
| 5주 | 규칙 분류 | 같은 기준 표에 핵심어를 붙여서 점수로 분류하는 함수를 만들어 줘. 강한 핵심어 2점, 약한 건 1점, 동점이면 기준 순서가 앞선 쪽. |
| 5주 | 응답 검사 | AI 응답에서 id가 입력에 없거나 category가 기준 이름이 아니면 그 항목만 버리고, 쓸 만한 게 절반도 안 되면 전체를 버려 줘. |
| 5주 | 일치율 | 사람이 검수한 것 중 자동 분류와 같은 비율을 계산하고, 순서를 섞어 여러 번 분류해도 같은지 확인하는 함수도. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### survey.classify
```
학과 설문 서술형 응답을 input.criteria의 고정 기준 5개로 분류한다. 기준마다 이름(name), 정의(definition), 예시(examples)가 있다.
input.items의 응답마다 id를 그대로 돌려주고, category는 기준 이름 5개 또는 '검토 필요' 중 정확히 하나를 고른다.
두 기준에 걸치면 응답이 가장 바라는 것(고쳐 달라는 대상)을 기준으로 고르고, 어느 기준에도 맞지 않거나 너무 짧으면 '검토 필요'.
같은 글에는 언제나 같은 분류를 낸다. reason은 판단 근거를 응답 속 말을 인용해 20자 안팎 한 구절로.
새 기준 이름을 만들거나 응답에 없는 사실을 지어내지 않는다. 모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"items":[{"id":"","category":"","reason":""}]}
```
- 입력: `aiInput()` — `{ criteriaVersion, criteria:[{name, definition, examples}], items:[{id, text}] }` (개인정보 가린 글, 민감 응답 제외) · 최대 1,500토큰
- 화면 검사: `normalizeAi()` → 통과한 항목만 덮어쓰기

## 3. 왜 이렇게 썼나

- **기준은 지시문이 아니라 입력으로 보낸다.** 기준 표(`CRITERIA` v3)를 규칙 분류와 Claude가 함께 쓰므로, 기준을 고치면 양쪽이 같이 바뀐다.
- **‘정확히 하나’와 ‘검토 필요’.** 고를 곳이 없을 때 빠져나갈 자리가 있어야 새 이름을 만들지 않는다.
- **걸칠 때의 규칙.** “시험 범위 공지가 늦어요”처럼 두 기준에 걸치는 응답이 실행마다 갈렸다. ‘고쳐 달라는 대상’ 기준으로 정했다.
- **reason은 인용으로.** 사람이 검수할 때 근거를 바로 원문에서 찾을 수 있게.

## 4. 실패했던 이전 버전

| 버전 | 지시문 | 무엇이 문제였나 |
|---|---|---|
| v1 | “설문 응답을 주제별로 분류해 줘.” | 실행마다 분류 이름이 달라짐(‘수업’ / ‘강의 방식’ / ‘교육 방법’). 같은 응답이 다른 갈래로 가서 두 번 돌린 결과가 70% 정도만 같았음 |
| v2 | 기준 이름 5개만 주고 고르게 | 이름은 고정됐지만 경계 응답이 흔들림, ‘기타’를 만들어 냄 |
| v3 (지금) | 기준 이름 · 정의 · 예시 + ‘검토 필요’ + 걸칠 때 규칙 + 화면 검사 | 같은 응답에 같은 결과, 사람 검수 일치율 91% (목표치) |
