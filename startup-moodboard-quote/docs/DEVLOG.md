## 2주차 — 사흘이 어디서 새는지부터

**한 일**
- 상담 후 회신까지 사흘을 나눠 보니: 레퍼런스 사진 모으기 1일, 견적 엑셀 맞추기 1일, 문장 다듬기·검토 반나절, 나머지는 다른 현장 일로 밀림.
- 견적은 항목이 늘 같다(철거·도배·바닥·조명·욕실·주방…). 면적 × 단가 표로 바로 나오게 만들었다. 단가는 공개 데모용 **가상의 샘플 단가**로 바꿔 넣었다.

**막힌 것 → 해결**
- 도배 면적을 바닥 면적으로 계산해 너무 싸게 나옴 → 벽·천장 면적을 바닥 × 2.6으로 추정하고, 표에 ‘추정’ 표시.
- 합계가 1원 단위까지 나와 고객이 오히려 의심함 → 만 원 단위로 반올림하고 ±10% 범위로 안내.

## 3주차 전반 — 사진 모으는 하루를 없애기

**한 일**
- 스타일 4가지(따뜻한 우드 · 화이트 미니멀 · 모던 그레이 · 그린 내추럴)마다 벽·바닥·포인트·패브릭·금속·상판 견본 6개를 정했다.
- 견본은 사진 대신 색 + 재질 결(나뭇결·타일 줄눈·직물·금속 광·돌 알갱이)로 그렸고, 같은 색으로 샘플 공간 그림을 칠했다. 상담 중에 스타일 버튼을 눌러 고객과 같이 바꿔 본다.

**막힌 것 → 해결**
- 메모에 “너무 하얀 건 차가워 보여서 싫다고”라고 적었는데 화이트 미니멀이 골라짐 → 구절 단위로 나누고, ‘싫·말고·빼고’가 있는 구절의 단어는 빼서 세게 고침. 테스트로 고정.

## 3주차 후반 — 견적이 두 배로 나온 날

**한 일**
- 실제 상담에서 거실·방 크기를 고객은 평으로, 도면은 ㎡로 말해 그대로 받아 적었다. 둘을 더한 값으로 계산해 **견적이 두 배**로 나갈 뻔했다.
- 해결: **면적은 들어오는 순간 ㎡ 하나로 통일**(`toM2`), 견적 계산은 ㎡만 받는다. 화면·회신·인쇄 어디서나 `112.4㎡ (34.0평)`처럼 두 단위를 함께 보여 준다.
- 단위 버튼을 바꾸면 같은 면적이 유지되도록 숫자가 따라 바뀐다.

**막힌 것 → 해결**
- 단위를 잘못 고르는 실수는 여전히 남음(34를 넣고 ㎡를 누름) → 공간 유형별 보통 면적을 벗어났는데 다른 단위로 읽으면 맞으면 경고하고 ‘34평 적용’ 버튼으로 바로잡게 함.
- 메모의 면적과 입력이 다른 경우 → 메모에서 `34평`, `59㎡`를 읽어 15% 넘게 다르면 알림.
- “평으로 넣든 ㎡로 넣든 같은 집이면 같은 견적” 테스트 추가.

## 4주차 — 고객에게 나가는 문장

**한 일**
- `moodboard.brief`로 Claude가 메모의 뉘앙스를 읽어 스타일·색·회신 첫 문단을 쓰게 했다. 규칙 결과가 먼저 나오고, Claude 결과가 오면 바뀐다.
- 회신 문장: 가린 이름(`한*윤`), 면적 두 단위, 공사 범위, 금액 범위, 실측 안내. 인쇄용 견적서.
- 연락처·메일은 AI로 보내기 전에 지운다(`scrub`).

**막힌 것 → 해결**
- Claude가 첫 문단에 “약 3,500만 원 선”처럼 금액을 씀 → 지시문에 “금액·단가는 쓰지 않는다”, 화면 검사에서 금액이 있으면 응답 전체를 버림. 금액은 견적표만 말한다.
- 색 코드가 `brown`처럼 올 때 → `#RRGGBB`가 아니면 그 색을 버리고, 3개가 안 남으면 규칙 결과 유지.

**결과 (1기 목표치)**
- 견적 회신 3일 → 당일, 상담→계약 18% → 31%
