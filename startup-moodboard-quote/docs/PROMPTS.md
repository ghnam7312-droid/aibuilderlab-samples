# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 2주 | 견적표 | 철거·도배·바닥·조명·욕실·주방 항목으로 견적 초안을 만들어 줘. 도배는 벽·천장 면적이라 바닥 × 2.6으로 추정하고 표에 ‘추정’이라고 써 줘. 합계는 만 원 단위, ±10% 범위도. |
| 3주 | 무드보드 | 사진 없이 색·재질 견본을 CSS로 그려 줘. 나뭇결, 타일 줄눈, 직물, 금속 광, 돌 알갱이 다섯 가지. 같은 색으로 거실 샘플 그림(SVG)도 칠해 줘. |
| 3주 | 단위 버그 | 면적을 평이나 ㎡로 받는데 계산은 ㎡ 하나로만 하게 바꿔 줘. 화면에는 늘 두 단위를 같이 보여 주고, 34를 넣고 ㎡를 고르면 아파트치고 너무 작다고 경고해 줘. |
| 4주 | 응답 검사 | Claude 응답에서 스타일이 4개 중 하나가 아니거나, 색 코드가 #RRGGBB가 아니거나, 문장에 금액이 있으면 버리는 함수를 만들어 줘. 테스트도. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### moodboard.brief
```
인테리어 첫 상담 메모를 읽고 무드보드 방향을 정한다. style은 input.styles 중 하나를 그대로 고른다.
palette는 3~6개로 벽·바닥·포인트·패브릭·금속·상판 같은 역할(role), 색 이름(name), 색 코드(hex, #RRGGBB),
재질(material: paint, wood, tile, fabric, metal, stone 중 하나)을 쓴다. keywords는 메모에서 고객이 원한
분위기를 2~5개 짧은 말로 쓴다. 고객이 싫다고 한 것은 고르지 않는다. message는 고객에게 보낼 회신의
첫 문단(2문장 이내)으로, 고객이 말한 내용을 어떻게 반영했는지 쓴다. 금액·단가·공사 기간은 쓰지 않는다
(견적표가 따로 있다). input에 없는 사실(가족 구성, 예산, 일정 등)을 지어내지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"style":"","keywords":[""],"palette":[{"role":"","name":"","hex":"#000000","material":""}],"message":""}
```
- 입력: `{ memo, space, area, scope, styles }` — memo는 연락처·메일을 지운 뒤 2,000자까지 · 최대 600토큰
- 화면 검사: `normalizeBrief()` — 스타일 4개 중 하나, 색 3개 이상, 색 코드 형식, 문장에 금액 없음. 하나라도 어기면 규칙 결과 유지

## 3. 왜 이렇게 썼나

- **스타일을 고르게만 한다.** 새 스타일 이름을 지어내면 견본·샘플 그림을 칠할 수 없어서, 준비된 4개 중 하나를 고르게 했다.
- **금액은 쓰지 못하게 한다.** 금액은 견적표가 같은 입력이면 늘 같은 값으로 계산한다. 문장 속 금액이 견적표와 다르면 고객이 헷갈린다.
- **싫다고 한 것은 고르지 않는다.** 규칙도 이 부분에서 틀렸던 적이 있어(“하얀 건 싫다고”) 지시문에 따로 적었다.

## 4. 실패했던 이전 버전

| 버전 | 지시문 | 결과 |
|---|---|---|
| v1 | “상담 메모를 보고 어울리는 인테리어 스타일과 예상 견적을 알려 줘.” | 줄글로 와서 화면에 칠할 수 없었고, “30평대 기준 4천만 원 내외”처럼 견적표와 다른 금액을 씀. 메모에 없는 “신혼부부”를 지어냄 |
| v2 (지금) | 스타일은 고르기만, 색은 #RRGGBB, 금액 금지, 없는 사실 금지 + 화면 검사 | 견적표와 문장이 어긋나지 않고, 틀린 응답은 화면에 나오지 않음 |
