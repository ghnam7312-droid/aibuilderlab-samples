## 1주차 전반 — 아홉 번은 어디서 겹쳤나

**한 일**
- 단톡방 한 달 치 예약 메시지를 표로 옮겼다. 겹친 9건 중 6건은 “누가 먼저 말했는지” 문제, 3건은 거의 같은 시각에 두 사람이 올린 경우였다.
- 장비 6대 × 하루 09~21시를 30분 칸으로 나눈 시간표 화면을 만들었다. 빈 칸을 누르면 예약 칸이 채워진다.

**막힌 것 → 해결**
- 10:00~12:00 예약 뒤에 12:00~14:00 예약이 ‘겹침’으로 막힘 → 구간을 `[시작, 끝)` 반열린 구간으로 바꾸고 맞닿는 경우 테스트 추가.

## 1주차 후반 — 저장하고, 로그인하고

**한 일**
- Supabase에 `equipment`, `bookings` 테이블. 학교 메일로만 로그인하게 했다.
- 저장 전에 화면에서 검사: 지난 시간, 운영 시간 밖, 30분 단위, 최대 4시간, 그리고 ‘같은 시간에 예약이 있나’.

**막힌 것 → 해결**
- 오늘 날짜인데 이미 지난 오전 시간이 예약됨 → 오늘이면 지금 시각보다 이른 시작을 막는 검사 추가.
- 로그인 뒤 다른 사람 예약까지 지워짐 → 행 단위 보안(RLS)에서 삭제는 본인 예약만 되게 고침.
- 시간대가 9시간 밀려 저장됨 → 저장은 `timestamptz`, 화면은 한국 시간으로 바꿔 보여 주기.

## 2주차 전반 — 동시 예약, 테스트로 먼저 재현

**한 일**
- 화면 검사를 넣었는데도 첫 주에 충돌이 1건 났다. 로그를 보니 두 사람이 0.01초 차이로 같은 시간을 저장했다.
- 원인: 두 사람 모두 ‘비어 있나’를 확인한 시점에는 비어 있었다. 확인과 저장 사이에 틈이 있다.
- 이 상황을 그대로 재현하는 테스트(`simulateRace`)를 먼저 만들었다: 같은 사본으로 둘 다 확인 → 둘 다 저장 → 충돌 1건. 테스트가 실패하는 것을 확인한 뒤 고쳤다.
- **해결: DB에서 겹치는 예약을 막는 제약**(`exclude using gist`, 장비가 같고 시간 구간이 겹치면 저장 거절). 늦은 쪽은 `23P01` 오류를 받고 “방금 다른 분이 예약했어요” 안내가 뜬다.

**막힌 것 → 해결**
- `exclude using gist`가 `equipment_id with =`에서 오류 → `btree_gist` 확장을 먼저 켜야 했다.
- 취소한 예약 자리에 새 예약이 안 들어감 → 제약에 `where (status <> 'cancelled')` 조건 추가.
- 프론트에서 오류 메시지가 영어 원문 그대로 노출 → 오류 코드 `23P01`만 보고 한국어 안내로 바꿈.

## 2주차 후반 — 사람이 판단할 것, AI가 도울 것

**한 일**
- SEM·CNC는 안전교육 이수자만 쓸 수 있다. 예약은 받되 ‘승인 대기’로 넣고, 실험실 관리자가 이수 여부를 확인해 승인·반려한다. 이 판단은 AI에 맡기지 않는다.
- “내일 오후 2시부터 3시간 SEM” 같은 문장으로 칸을 채우는 기능. 규칙으로 먼저 채우고, Claude(`labbooking.parse`)가 돌아오면 덮어쓴다.
- 조교 공유용 CSV. 예약자 이름은 가린다.
- 로직을 `logic.js`로 분리하고 테스트 13개.

**막힌 것 → 해결**
- Claude가 목록에 없는 장비 이름(“레이저 절단기”)을 돌려줌 → id 목록에 없으면 비우는 검사(`normalizeParse`) 추가.
- ‘2시’를 새벽 2시로 읽음 → 실험실은 9시에 여니 오전·오후가 없는 1~8시는 오후로 본다(규칙과 지시문 둘 다).

**결과 (1기 목표치)**
- 연구실 3곳 사용, 예약 충돌 월 9건 → 0건
