# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버에 합칠 원문([ai-task.json](ai-task.json))입니다.

## 1. 만들 때 쓴 프롬프트 (대표 5개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 5주 | 표 읽기 | 구글 시트에서 복사한 탭 구분 표를 게시물 배열로 바꿔 줘. 첫 줄이 머리글이면 건너뛰고, 좋아요는 1.2만·3.4k·1,234를 숫자로. 링크는 http로 시작할 때만. |
| 5주 | 날짜 맞추기 | 날짜 칸에 2026. 10. 20. / 10/21 / 24 Oct 2026 / 2026년 10월 19일 오후 3:12 / 46318 / 어제 가 섞여 있어. 전부 YYYY-MM-DD로 바꾸고, 못 읽으면 빈 값과 이유를 돌려줘. 오늘 날짜는 인자로. |
| 6주 | 주간 집계 | 월~일 한 주만 걸러서 브랜드별 게시물 수, 좋아요+댓글 합계, 반응 1위 게시물을 구해 줘. 그 주에 0건인 브랜드도 표에 남겨. |
| 6주 | 요약 검사 | AI 요약 문장마다 refs(게시물 id)가 있어. 그 주 게시물에 없는 id는 지우고, 남은 근거가 없으면 문장을 버려. 남은 문장이 2개 미만이면 null. |
| 6주 | 내보내기 | 리포트를 마크다운으로. 요약 문장 끝에 [원문1](링크) 형식으로 근거 링크, 브랜드 표는 마크다운 표로. |

## 2. 서비스가 쓰는 지시문

### snsreport.summary
```
경쟁 브랜드 SNS 게시물 한 주치(input.posts)로 마케터용 주간 리포트 요약을 쓴다.
lines는 3~5문장: 가장 활발한 브랜드, 반응이 가장 큰 게시물과 그 이유로 보이는 점,
여러 브랜드에 공통된 주제·형식, 우리 팀이 참고할 점.
문장마다 refs에 근거가 된 게시물 id(input.posts의 id 그대로)를 1~3개 넣는다.
근거 게시물이 없는 문장은 쓰지 않는다. 숫자·날짜는 input에 있는 값만 쓰고,
게시물에 없는 사실이나 브랜드 의도를 지어내지 않는다.
watch는 다음 주에 확인할 점 한 문장(없으면 빈 문자열).
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"lines":[{"text":"","refs":["p1"]}],"watch":""}
```
- 입력: `{ week:{start,end}, brands:[{name, posts, engagement}], posts:[{id, brand, date, channel, text, likes, comments}] }` (링크는 보내지 않고 id로만 연결) · 최대 900토큰
- 화면 검사: `normalizeSummary()` → 그 주 게시물 id만 남기고 근거 없는 문장 버림, 2문장 미만이면 규칙 요약 유지

### 왜 이렇게 썼나
- **문장마다 근거 id** — 리포트를 받는 사람이 “정말?” 하고 바로 원문을 열어 볼 수 있어야 한다. 링크는 화면이 id로 붙이므로 AI가 주소를 틀리게 쓸 일이 없다.
- **‘그 이유로 보이는 점’** — 이유는 추정이므로 단정하지 않게 표현을 정했다. 사실은 input에 있는 것만.
- **링크를 보내지 않는다** — 입력 길이를 줄이고, 주소를 지어내거나 바꿔 쓰는 실수를 막는다.

## 3. 실패했던 이전 버전

```
아래 경쟁사 게시물들을 요약해서 이번 주 트렌드를 알려 줘.
```
- 결과: “업계 전체가 제로 음료로 옮겨 가는 중”, “Z세대의 건강 관심 증가” 같은 그럴듯한 문장이 나왔지만 어느 게시물에서 나온 말인지 알 수 없었다. 팀장이 근거를 물었을 때 답할 수 없었다.
- 고친 점: 문장마다 근거 게시물 id를 받고, 근거가 없는 문장은 화면에서 버린다.
