# 커밋일지 개발 일지 (커리어 트랙 3~4주차)

> **1기 목표 모델**: 가상의 수강생 ‘커밋하는곰’이 이렇게 진행하는 것을 목표로 쓴 일지입니다. 실제 수강생의 기록이 아닙니다.
> 숫자는 COVI 학습 기록 기준이며, 포트폴리오에 적은 합계와 같습니다.

| 시기 | 만든 것 | 프롬프트 | 디버깅 | 시간 |
|---|---|---|---|---|
| 3주차 전반 | GitHub API로 커밋·PR·이슈 모으기 | 8 | 2 | 1.5h |
| 3주차 후반 | 사람별 일지, 마크다운 | 9 | 1 | 1.0h |
| 4주차 전반 | AI 요약 → 비공개 저장소 사고 → 저장소 고르기 | 8 | 2 | 1.5h |
| 4주차 후반 | 민감 정보 가리기, 8주 축적, 테스트 | 6 | 1 | 1.0h |
| **합계** | | **31** | **6** | **5h** |

## 3주차 전반 — 활동 모으기

**한 일**
- 지난 회고 준비에 걸린 시간을 재 보니 1시간. 대부분이 저장소 4개를 돌며 커밋을 다시 읽는 시간이었다.
- GitHub API로 팀원이 쓴 커밋·병합된 PR·닫힌 이슈를 한 주 단위로 모았다. 한 줄 형식(`날짜 저장소 @이름 내용`)으로 정리해 두면 테스트하기 쉽다.

**막힌 것 → 해결**
- API가 한 번에 30개만 줌 → 페이지 넘김(`page`)을 끝까지 돌도록 고침.
- 커밋 작성자가 깃 설정 이름(영문)으로 나와 팀원 이름과 안 맞음 → 깃허브 아이디 → 이름 표를 따로 둠.

---

## 3주차 후반 — 사람별로 묶기

**한 일**
- `feat:`, `fix:`, `docs:` 같은 커밋 종류와 `PR #14 병합:`, `이슈 #9 닫음:`을 읽어 사람별로 묶었다.
- 같은 일이 커밋과 PR로 두 번 나오면 한 번만 적는다.
- 마크다운으로 내보내 노션·위키에 붙인다.

**막힌 것 → 해결**
- 커밋 끝의 `(#12)`가 일지마다 붙어 지저분함 → 끝의 PR 번호 표기는 떼고, PR 줄에만 번호를 남김.

---

## 4주차 전반 — 요약에 섞인 비공개 저장소

**한 일**
- Claude(`devlog.summary`)로 사람별 한 일을 결과 중심 문장으로 묶었다.
- 첫 일지를 팀 노션에 올렸는데, 팀원 한 명의 **인턴 회사 비공개 저장소** 커밋(“거래처 정산 쿼리 수정”)이 요약에 섞여 있었다. 내 계정 토큰으로 볼 수 있는 저장소를 전부 모았기 때문이다.
- **해결: 공개할 저장소만 고르는 설정.** 저장소마다 `내용 포함 · 건수만 · 제외`. 비공개 저장소는 ‘내용 포함’을 고를 수 없고, 설정에 없는 저장소는 자동 제외(모르면 내보내지 않는다).
- 비공개 줄은 Claude에게도 보내지 않는다. 그래도 응답에 비공개 저장소 이름이 보이면 통째로 버리는 검사를 붙였다.

**막힌 것 → 해결**
- 처음엔 ‘비공개 저장소 빼기’ 목록 방식으로 만들었는데, 새 저장소가 생기면 그대로 섞임 → 거꾸로 ‘넣을 저장소를 고르는’ 방식으로 바꿈.
- Claude가 입력에 없는 사람(“PM”)을 만들어 냄 → 응답의 이름이 입력 작성자 목록에 없으면 버림.

---

## 4주차 후반 — 가리기, 쌓기

**한 일**
- 공개 저장소 커밋에도 메일 주소가 섞인 적이 있어, 메일·토큰·내부 주소·IP·전화번호를 가리고 몇 곳을 가렸는지 보여 준다.
- 주 1회 GitHub Actions로 일지를 만들어 저장소 `devlog/`에 쌓는다. 8주 치를 거슬러 볼 수 있다.
- 로직을 `logic.js`로 분리하고 테스트 11개.

**막힌 것 → 해결**
- 토큰 패턴이 너무 넓어 커밋 해시까지 가림 → `ghp_`, `github_pat_`, `sk-`처럼 앞머리가 정해진 것만 가림.

**결과 (1기 목표치)**
- 회고 준비 1시간 → 10분, 8주 일지 자동 축적
