# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버에 합칠 원문([ai-task.json](ai-task.json))입니다.

## 1. 만들 때 쓴 프롬프트 (대표 5개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 3주 | 활동 읽기 | `2026-10-20 capstone-web @하늘 feat: 로그인 화면 (#12)` 형식의 줄을 읽어서 날짜, 저장소, 작성자, 종류(commit·pr·issue), 커밋 종류, 내용으로 나눠 줘. 틀린 줄은 줄 번호만 모아서 돌려줘. |
| 3주 | 사람별 일지 | 한 주 활동을 사람별로 묶어서 커밋·PR·이슈 개수와 한 일 목록을 만들어 줘. 같은 내용이 커밋과 PR로 두 번 나오면 한 번만. |
| 4주 | 저장소 고르기 | 저장소마다 내용 포함·건수만·제외 정책을 두고 싶어. 비공개 저장소는 내용 포함이 될 수 없고, 설정에 없는 저장소는 제외로 봐. 테스트에 ‘설정이 비어 있으면 아무것도 안 나간다’를 넣어 줘. |
| 4주 | 응답 검사 | Claude 요약에 비공개 저장소 이름이 들어 있거나, 입력에 없는 사람이 있거나, 가렸던 메일이 다시 나오면 null을 돌려줘. |
| 4주 | 가리기 | 커밋 메시지에서 메일, 깃허브·API 토큰, 사내 주소, IP, 전화번호를 [메일 가림]처럼 바꾸고 몇 곳 바꿨는지 세 줘. 커밋 해시는 건드리지 말고. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

공통 꼬리말: `모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.`

### devlog.summary
```
팀의 한 주 깃허브 활동 목록(input.items: 날짜, 저장소, 작성자, 종류 commit·pr·issue, 커밋 종류, 내용)으로
주간 개발 일지 요약을 쓴다. headline은 이번 주 팀 전체가 한 일을 한 문장으로. members는 input에 나온
작성자마다 하나씩, name은 작성자 이름 그대로, did는 그 사람이 한 일을 비슷한 커밋끼리 묶어 2~4개의
짧은 문장으로(커밋 메시지를 그대로 옮기지 말고 결과 중심으로). next는 WIP, 이어서, TODO처럼 끝나지 않은
일만 최대 3개. input에 없는 사람·저장소·작업을 지어내지 않는다. '[메일 가림]', '[토큰 가림]'처럼 가린
부분은 되살리거나 추측하지 않는다.
출력 형식: {"headline":"","members":[{"name":"","did":[""]}],"next":[""]}
```
- 입력: `{ week, items: [{ date, repo, author, kind, type, ref, text }] }` — ‘내용 포함’ 저장소의 가린 뒤 줄만, 80줄까지 · 최대 900토큰
- 화면 검사: `normalizeSummary()` → 비공개 저장소 이름·입력에 없는 사람·되살아난 메일·토큰이 있으면 버림

## 3. 왜 이렇게 썼나

- **보내기 전에 거른다.** 지시문에 “비공개 내용은 쓰지 마”라고 적는 것으로는 막을 수 없다. 비공개 줄은 아예 보내지 않고, 지시문은 받은 것만 쓰게 한다.
- **돌아온 뒤에도 본다.** 저장소 이름이 커밋 내용에 들어 있을 수 있어서, 응답에 막힌 이름이 보이면 통째로 버린다.
- **작성자 이름 그대로.** 화면은 사람별 카드에 덮어쓰므로 이름이 바뀌면 붙일 곳이 없다.

## 4. 실패했던 이전 버전

| 버전 | 지시문 | 무엇이 틀렸나 |
|---|---|---|
| v1 | “이번 주 커밋 목록을 보고 팀 개발 일지를 써 줘.” (토큰으로 볼 수 있는 모든 저장소의 커밋을 그대로 보냄) | 인턴 회사 비공개 저장소의 “거래처 정산 쿼리 수정”이 요약에 들어감. 줄글이라 사람별로 나눌 수 없었고, 없는 “PM 리뷰”를 지어냄. |
| v2 | 위 지시문 + 보내기 전 저장소 고르기 + 응답 검사 | 공개 저장소 내용만 사람별로 정리되고, 비공개 이름이 보이면 버린다. |
