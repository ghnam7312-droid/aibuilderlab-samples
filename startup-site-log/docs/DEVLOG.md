## 5주차 전반 — 사진은 있는데 일지가 없다

**한 일**
- 하루 40분을 재 보니: 사진 넘겨 보며 무슨 공정인지 떠올리기 15분, 메신저에 설명 쓰기 20분, 사진 고르기 5분.
- 사진마다 공정과 한 줄 메모만 달면, 공정별로 묶어 시간순 일지를 쓰게 했다. 메모나 파일 이름에 ‘타일’, ‘배선’이 있으면 공정을 짐작한다.

**막힌 것 → 해결**
- 같은 공정이 여러 장이면 일지가 같은 줄로 길어짐 → 공정별로 묶고 메모를 쉼표로 이었다.

## 5주차 후반 — 고객이 보는 화면

**한 일**
- ‘고객에게 보이는 화면’ 미리보기: 공유 문구 + 사진 묶음. 이름은 `한*윤`처럼 가린다.
- 공유 링크는 현장·날짜로 만든 8자리 토큰만 담는다. 주소에 이름이나 현장 위치가 들어가지 않는다.
- 공정 진행 막대로 ‘어디까지 왔고 다음은 무엇인지’를 한눈에 보이게 했다.

**막힌 것 → 해결**
- 처음엔 링크에 현장 이름을 넣었다가, 주소가 메신저 미리보기에 그대로 보인다는 걸 알고 토큰으로 바꿈.

## 6주차 전반 — 다른 현장 사진이 고객에게 갔다

**한 일**
- 같은 날 두 현장을 돌고 사진을 한꺼번에 올렸더니, B현장 도배 사진이 A현장 고객에게 공유됐다.
- 해결: **현장별 폴더로 나눠 업로드**하게 바꿨다. 업로드는 지금 연 폴더로만 들어간다.
- 파일 이름 앞에 현장 코드를 붙여 찍는 습관(`B현장_도배_1420.jpg`)을 살려, 코드가 폴더와 다르면 보류하고 공유에서 뺀다. ‘B현장 폴더로 옮기기’ 버튼으로 바로잡는다.

**막힌 것 → 해결**
- 보류한 사진이 공정 진행 계산에는 들어가 ‘다음 작업’이 한 단계 건너뜀 → 진행 계산에서도 다른 현장 의심 사진을 뺌. 테스트로 고정.
- `BATH.jpg`가 B현장으로 읽힘 → 현장 코드는 글자 하나 뒤에 `현장`이나 `_`, `-`, 공백이 올 때만 인정.

## 6주차 후반 — 문장은 Claude, 판단은 사람

**한 일**
- `sitelog.write`로 Claude가 메모를 고객용 문장으로 다듬는다. 규칙 일지가 먼저 나오고, 결과가 오면 바뀐다.
- 누수·균열·누전 같은 메모는 AI가 판단하지 않게 했다. 내용 대신 ‘안전 확인 필요’로 보내고, 고객에게는 담당자가 직접 연락한다는 문장만 나간다.
- 로직을 `logic.js`로 분리하고 테스트 12개.

**막힌 것 → 해결**
- (디버깅 없이 지시문과 검사로 해결) Claude가 사진에 없는 ‘바닥’ 공정을 일지에 넣던 초안 → 그날 사진에 있는 공정만 남기는 검사를 처음부터 넣었다.
