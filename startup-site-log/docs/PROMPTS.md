# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 5주 | 규칙 일지 | 사진마다 시간·공정·메모가 있어. 같은 날 사진을 공정별로 묶어 시간순으로 일지를 써 줘. 공정 계획 순서를 받아서 다음 작업도 정해 줘. |
| 5주 | 공유 링크 | 고객 공유 링크를 만들 건데 주소에 이름이나 현장 위치가 들어가면 안 돼. 현장·날짜로 8자리 토큰을 만들어 줘. |
| 6주 | 섞임 버그 | 업로드를 지금 연 현장 폴더로만 받게 바꿔 줘. 파일 이름이 'B현장_'처럼 다른 현장이면 보류하고 공유에서 빼고, 옮기기 버튼도. |
| 6주 | 안전 | 메모에 누수·균열·누전 같은 말이 있으면 AI가 판단하지 않게 해 줘. AI 입력에는 내용 대신 '안전 확인 필요', 응답에 '문제없다'가 있으면 버려. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### sitelog.write
```
인테리어 현장의 하루 사진 기록(시간, 공정, 한 줄 메모)을 읽고 고객에게 보낼 공정 일지를 쓴다.
summary는 오늘 진행한 일을 1~2문장으로 쓴다. items는 input.photos에 있는 공정만 하나씩,
done에 그 공정에서 한 일을 메모 내용 그대로 다듬어 쓰고, next는 메모에 다음 할 일이 적혀 있을 때만
쓴다(없으면 빈 문자열). ask는 고객이 정하거나 확인해야 할 것이 메모에 있을 때만 쓴다(없으면 빈 문자열).
'안전 확인 필요'로 표시된 사진은 내용을 짐작하지 않고, 안전하다·문제없다 같은 판단을 쓰지 않는다.
그 판단은 담당자가 한다. input에 없는 사실(작업 내용, 자재, 일정, 금액)을 지어내지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"summary":"","items":[{"process":"","done":"","next":""}],"ask":""}
```
- 입력: `{ site, date, photos:[{time, process, note}], next, safety }` — 사진 파일은 보내지 않음, 안전 메모는 내용 생략 · 최대 700토큰
- 화면 검사: `normalizeLog()` → `mergeAi()` (안전 표시와 다음 공정은 규칙 값)

## 3. 왜 이렇게 썼나

- **사진에 있는 공정만.** 고객은 일지에 적힌 공정이 실제로 했다고 믿는다. 없는 공정이 들어가면 바로 문의가 온다.
- **안전은 판단하지 않는다.** “누수 의심 자국”을 AI가 “경미한 흔적으로 문제없습니다”라고 쓰면 책임질 수 없다. 지시문 + 입력 가리기 + 응답 검사 세 겹으로 막았다.
- **next·ask는 비워도 된다.** 비우라고 하지 않으면 그럴듯한 다음 일정을 지어낸다.

## 4. 실패했던 이전 버전

| 버전 | 지시문 | 결과 |
|---|---|---|
| v1 | “오늘 현장 사진 메모로 고객에게 보낼 진행 상황 메시지를 친절하게 써 줘.” | “내일은 바닥 시공 예정입니다”처럼 없는 일정을 씀. 누수 메모에 “큰 문제는 아닌 것으로 보입니다”라고 씀 |
| v2 (지금) | 공정별 JSON, 사진에 있는 공정만, 안전 판단 금지, next·ask는 메모에 있을 때만 + 화면 검사 | 지어낸 일정·안전 판단이 화면에 나오지 않음 |
