# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 이 서비스가 서버에 등록하는 원문([ai-task.json](ai-task.json))입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 5주 | 가리기 | 설문 응답에서 전화번호, 메일, 사번(영문 1자+숫자)을 [전화번호]처럼 바꾸는 함수. AI에 보내기 전과 화면에 그리기 전에 둘 다 쓴다. |
| 5주 | 구절 나누기 | “좋았지만 실습이 짧았다”처럼 한 응답에 좋은 점과 아쉬운 점이 섞이면 둘 다 세고 싶어. ‘지만’, ‘는데’에서 끊어서 구절마다 주제와 결을 정해 줘. |
| 5주 | 소수 의견 대조 | AI가 준 묶음과 규칙 묶음을 비교해서, 규칙에서 3명 이상인데 AI 묶음 어디에도 응답 번호가 절반 이상 겹치지 않으면 되살려 줘. 이름은 달라도 돼. |
| 5주 | 검수표 | 묶음마다 원문 보기 버튼과 검수 체크를 넣고, 보고서를 복사할 때 검수 안 한 묶음은 ‘미검수’라고 남겨 줘. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### survey.summary
```
교육 만족도 서술형 응답(input.responses: id, score, text)을 의견 묶음으로 요약한다.
themes는 같은 주제·같은 결의 응답을 묶은 것으로, topic은 2~8자 주제 이름,
tone은 '좋음' 또는 '아쉬움', ids는 그 의견을 말한 응답 id 전부, summary는 대표 의견 한 문장.
한 응답이 좋은 점과 아쉬운 점을 함께 말하면 두 묶음에 모두 넣는다.
input.minCount명 이상이 말한 의견은 인원이 적어도 하나도 빠뜨리지 않는다.
많은 의견만 남기고 나머지를 합치거나 버리지 않는다.
lines는 3문장(전체 분위기, 가장 많은 의견, 소수지만 기준 이상인 의견).
improvements는 아쉬움 의견에서 나온 다음 교육 개선 항목 최대 5개.
응답에 없는 의견·숫자를 지어내지 않고, 개인을 짐작하지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"themes":[{"topic":"","tone":"아쉬움","ids":[0],"summary":""}],"lines":[""],"improvements":[""]}
```
- 입력: `{ course, minCount, responses: [{ id, score, text }] }` — text는 가린 뒤 300자까지, 120건까지 · 최대 1500토큰
- 화면 검사: `normalizeSummary()`(결 · 응답 번호 검사, 인원은 ids로 다시 셈) → `ensureKept()`(기준 이상 의견 대조·되살림)

## 3. 왜 이렇게 썼나

- **인원 대신 ids** — AI가 “5명”이라고 쓴 숫자는 검증할 수 없다. 응답 번호를 받으면 화면이 직접 세고, 원문을 바로 열 수 있다.
- **기준을 숫자로** — “소수 의견도 챙겨 줘”는 해석이 갈린다. `minCount`명 이상은 빠뜨리지 않는다고 숫자로 주고, 화면에서 한 번 더 대조한다.
- **개인을 짐작하지 않는다** — 익명 설문에서 “영업팀 누구 같다” 같은 추정을 막는다.

## 4. 실패했던 이전 버전

```
아래 만족도 응답을 읽고 주요 의견 5개로 요약해 줘.
```
- 많은 순 5개만 남아 ‘교육장 모니터’(3명) · ‘금요일 오후 시간대’(3명)가 사라짐.
- “실습이 부족했다는 의견이 많았다”처럼 인원이 없어 보고서에 쓸 수 없음.
- 좋음/아쉬움이 섞인 응답이 한쪽에만 들어감.
→ 묶음마다 응답 번호를 받고, 기준 이상 의견은 모두 남기게 바꾸고, 화면에서 대조한다.
