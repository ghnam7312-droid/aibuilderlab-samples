# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 이 서비스가 서버에 등록해 쓰는 원문입니다([ai-task.json](ai-task.json)).

## 1. 만들 때 쓴 프롬프트 (대표 5개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 5주 | 시안 → 코드 | 병원 예약을 진료과 → 날짜·시간 → 본인 정보 → 확인 4단계로, 한 화면에 질문 하나씩 보여 주는 화면을 만들어 줘. 글자는 18px 이상, 버튼 높이 56px, ‘다음’은 늘 아래 같은 자리. |
| 5주 | 시간표 | 평일 9~18시(13~14시 점심), 토요일 9~13시, 일요일 휴진, 30분 단위 시간 칸을 만드는 함수. 이미 예약된 칸과 지난 시간은 막고, 오늘 날짜는 인자로 받아서 테스트할 수 있게. |
| 6주 | 버튼 겹침 | 화면 폭과 글자 크기를 받아서 시간 칸을 몇 칸으로 나눌지 계산하고, 글자가 버튼보다 넓거나 버튼이 44px보다 작으면 문제 목록을 돌려주는 함수를 만들어 줘. 320~430px에서 테스트. |
| 6주 | 테스트 기록 | 참가자 코드·시안·완료 여부·멈춘 단계·메모로 사용성 테스트를 기록하고, 시안별 완료율과 단계별 이탈 수를 계산해 줘. 이름과 연락처는 받지 않게. |
| 6주 | 응답 검사 | AI가 정리한 문제 목록에서 단계가 4단계 이름이 아니면 ‘전체’, 문제 글이 비었거나 진단·처방 같은 의료 판단이 들어 있으면 버리고, 남는 게 없으면 null. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### clinicbooking.issues
```
병원 예약 화면 사용성 테스트 기록을 디자이너용으로 정리한다. input.trials의 결과(완료, '단계에서 멈춤')와 관찰 메모만 근거로, 막힌 문제를 단계별로 묶는다. step은 input.steps 중 하나(진료과, 날짜·시간, 본인 정보, 확인)이거나 여러 단계에 걸치면 '전체'. problem은 화면에서 무엇이 문제였는지 짧게, evidence는 참가자 코드와 메모 요약, fix는 화면 배치·글자·버튼·문구로 고칠 방법 한 문장, count는 그 문제가 나온 기록 수. 많은 순서로 최대 6개. 어느 진료과가 맞는지, 증상·진단 같은 의료 판단은 하지 않는다. input에 없는 사실이나 참가자 정보는 지어내지 않는다. summary는 가장 큰 문제 한 문장. 모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"issues":[{"step":"","problem":"","evidence":"","fix":"","count":0}],"summary":""}
```
- 입력: `{ version, trials: [{ pid, result, memo }], steps }` — 참가자 코드·결과·메모뿐 · 최대 900토큰
- 화면 검사: `normalizeIssues()` → 통과하면 규칙 결과를 덮어씀

## 3. 왜 이렇게 썼나

- **근거를 메모로 한정** — 테스트 정리는 ‘있었던 일’만 다뤄야 합니다. 그래서 evidence에 참가자 코드와 메모를 붙이게 하고, 없는 사실을 지어내지 말라고 적었습니다.
- **단계 이름을 고정** — 화면의 단계 표와 맞춰 보려고 step을 input.steps 중 하나로 제한했습니다. 아니면 화면에서 ‘전체’로 바꿉니다.
- **고칠 방법을 화면 언어로** — fix를 ‘배치·글자·버튼·문구’로 제한해 디자이너가 바로 시안에 옮길 수 있게 했습니다.
- **의료 판단 금지** — “두통이면 내과” 같은 추천이 섞인 적이 있어, 지시문에서 막고 화면 검사에서도 한 번 더 거릅니다. 진료과를 모르는 분은 접수처 전화로 넘깁니다.

## 4. 실패했던 이전 버전

| 버전 | 지시문 | 문제 |
|---|---|---|
| v1 | “사용성 테스트 메모를 요약하고 개선점을 알려 줘” | 줄글 요약이 와서 단계 표와 맞출 수 없었고, 메모에 없는 ‘로딩이 느렸다’ 같은 문제를 지어냄. ‘두통 환자는 내과를 먼저 보여 주라’는 의료 판단도 섞임 |
| v2 | 위 지시문 + JSON 형식 + 검사 | 단계별로 묶이고, 근거가 참가자 코드로 붙음. 의료 판단 항목은 화면에서 버려짐 |
