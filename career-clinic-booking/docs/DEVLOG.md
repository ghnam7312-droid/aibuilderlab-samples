## 5주차 전반 — 어디서 포기하는지부터

**한 일**
- 부모님이 쓰던 예약 화면을 옆에서 지켜보며 멈춘 곳을 적었다: 진료과 이름, 작은 시간 칸, 본인 인증 문자 대기.
- 한 화면에 한 가지씩 묻는 4단계(진료과 → 날짜·시간 → 본인 정보 → 확인)로 Figma 시안을 다시 그렸다.

**막힌 것 → 해결**
- 시안 리뷰에서 ‘쉬워 보인다’는 말만 듣고 실제로 쉬운지는 알 수 없었다 → 그림 대신 눌러 보는 화면으로 검증하기로 했다.

---

## 5주차 후반 — 그림을 눌러지는 화면으로

**한 일**
- Claude에게 Figma 시안 구성을 설명하고 Next.js 시제품으로 옮겼다. 진료 시간표(평일·토요일·휴진·점심시간)와 이미 찬 시간을 막는 로직을 따로 뺐다.
- 본인 인증을 빼고 이름·휴대폰만 받기, 숫자 자판(`inputmode="numeric"`).
- 틀린 입력은 “휴대폰 번호 10~11자리를 숫자로 적어 주세요”처럼 무엇을 고칠지 말해 준다.

**막힌 것 → 해결**
- 같은 시간을 두 번 예약할 수 있었다 → 예약 넣을 때 같은 칸·같은 날 같은 사람을 검사(`book`)하고 테스트 추가.
- 지난 시간이 오늘 칸에 열려 있었다 → 현재 시각 이전 칸을 막음.

## 6주차 전반 — 휴대폰에서 버튼이 겹친다

**한 일**
- 첫 테스트에서 50~60대 참가자가 ‘다음’ 버튼을 못 찾거나 옆 시간을 눌렀다. 데스크톱 시안의 4칸 고정 배치와 긴 버튼 문구를 휴대폰에 그대로 줄여 넣은 탓이었다.
- **화면 폭별 배치를 다시 지정**: 시간 칸 수를 폭과 글자 크기로 계산(2~4칸), 버튼 높이 56px, 휴대폰 폭에서는 ‘다음 단계로’를 맨 위 한 줄로.
- 처음 시안/고친 시안 × 320·375·430px × 보통·큰 글자를 바꿔 보는 도구와 ‘배치 점검’을 붙였다.

**막힌 것 → 해결**
- CSS를 고쳐도 다른 폭에서 다시 겹쳤다(디버깅 3회) → 폭마다 눈으로 확인하는 대신, 글자 폭을 어림해 겹침을 계산하는 `layoutIssues`를 만들고 10가지 조합에서 겹침 0을 테스트로 고정.
- 그리드 칸이 글자 길이만큼 늘어나 겹침이 가려졌다 → `minmax(0, 1fr)`로 칸 폭을 고정해 실제 겹침이 보이게 했다.

## 6주차 후반 — 테스트 기록과 정리

**한 일**
- 참가자 5명(P1~P5, 50~60대)의 시도마다 시안·결과·멈춘 단계·메모를 남기고, 완료율과 단계별 이탈을 보게 했다.
- 메모 정리: Claude `clinicbooking.issues`, 실패하면 낱말 규칙. 진단·처방 같은 의료 판단이 섞인 항목은 버린다.
- 진료과를 모르면 접수처 전화로 넘기는 버튼과 응급 안내를 넣었다.
- 확인 화면·저장·CSV에는 가린 이름과 번호, 참가자 코드만.

**막힌 것 → 해결**
- 저장소에 입력 중인 휴대폰 번호가 그대로 남았다 → 저장할 때 이름·번호 입력값을 비우고, 예약 기록에는 가린 값만 남김.

**결과 (1기 목표치)**
- 50~60대 5명 테스트, 예약 완료율 54% → 86% (처음 시안 13회 중 7회, 고친 시안 14회 중 12회)
