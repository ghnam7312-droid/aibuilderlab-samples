# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 이 서비스가 서버에 등록하는 원문([ai-task.json](ai-task.json))입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 6주 | 최신본 | 자료 목록에서 같은 문서를 묶어 줘. 이름 끝의 (개정), _최종, v2는 무시하고, 개정일이 가장 늦은 것만 남기고 나머지는 왜 뺐는지 같이 남겨. 개정일이 없으면 자동으로 남기지 말고 따로 모아 줘. |
| 6주 | 질문 묶기 | 신입 질문을 비슷한 것끼리 묶고 몇 개 부서에서 나왔는지 세어 줘. ‘~하나요’, ‘어디서’ 같은 말과 ‘신청’ 같은 흔한 낱말은 비교에서 빼. |
| 6주 | 사람에게 넘기기 | 급여, 근로계약, 징계 같은 말이 들어간 질문은 자료를 연결하지 말고 ‘인사 담당자 답변’으로 표시해 줘. AI가 문서를 골라 와도 지워. |
| 6주 | 확산 계획 | 부서 × 4단계 표를 만들어 줘. 칸을 누르면 예정 → 진행 → 완료로 바뀌고, 네 칸 모두 완료면 그 부서는 적용. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### onboarding.faq
```
신입 사원들이 부서마다 물어본 질문(input.questions: id, dept, text)을 뜻이 같은 것끼리 묶는다.
groups의 question은 묶음을 대표하는 질문 한 문장(신입이 묻는 말투), category는 2~6자 분류
(근태, 경비, 계정, 복리후생 등), ids는 그 묶음에 들어가는 질문 id 전부(한 질문은 한 묶음에만).
docId는 input.docs 중 이 질문의 답이 있을 만한 문서 id 하나, 없으면 빈 문자열.
문서 내용은 모르므로 답을 쓰지 않고 문서만 고른다.
input.docs에 없는 문서·규정·숫자를 지어내지 않는다.
급여·근로계약·징계처럼 사람이 답해야 하는 질문은 docId를 비운다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"groups":[{"question":"","category":"","ids":[0],"docId":""}]}
```
- 입력: `{ minDepts, questions: [{ id, dept, text }], docs: [{ id, title, date }] }` — docs는 **최신본만** · 최대 1500토큰
- 화면 검사: `normalizeFaq()` — 질문 번호 한 번씩, 최신본 id만, 빠진 질문은 따로 붙임 → `finish()`에서 급여·계약 질문은 자료 비움

## 3. 왜 이렇게 썼나

- **최신본만 보낸다** — 구버전을 아예 보내지 않으면 AI가 고를 수도 없다. 화면에서 한 번 더 막는다.
- **답을 쓰지 않는다** — 문서 본문 없이 쓴 답은 그럴듯한 지어낸 규정이 된다. 신입에게는 “어느 최신 문서를 보라”까지만 준다.
- **사람이 답할 질문을 분명히** — 급여·계약은 개인마다 다르고 잘못 안내하면 문제가 된다. AI 판단과 상관없이 규칙으로 넘긴다.

## 4. 실패했던 이전 버전

```
신입들이 자주 묻는 질문에 대해 회사 규정을 참고해서 FAQ 답변을 만들어 줘. (질문 + 자료 목록 전체)
```
- 문서 본문이 없는데 “경비는 매달 5일까지 처리합니다”처럼 규정 내용을 지어냄.
- 2022년 경비 규정과 2025년 경비 규정을 둘 다 근거로 붙임.
- “수습 기간 급여는 100%입니다”처럼 사람이 답해야 할 질문에 답함.
→ 최신본 목록만 보내고, 답 대신 문서만 고르게 하고, 급여·계약 질문은 규칙으로 넘기게 바꿨다.
