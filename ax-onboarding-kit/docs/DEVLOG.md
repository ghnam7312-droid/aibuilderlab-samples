## 6주차 전반 — 자료부터 한 줄로

**한 일**
- 4개 부서(영업 · 재무 · 개발 · 마케팅)의 온보딩 폴더 목록을 부서 · 문서명 · 종류 · 개정일로 모았다. 22건.
- 신입들이 첫 2주 동안 물어본 질문을 부서 담당자에게 받아 34건을 모았다. 같은 질문이 부서마다 반복됐다.
- 질문을 비슷한 것끼리 묶는 규칙을 만들었다. 2개 부서 이상에서 나온 질문을 공통 질문으로.

**막힌 것 → 해결**
- 목록을 모아 보니 **오래된 규정 문서가 섞여** 있었다. 취업규칙만 3개(2023 · 2024 · 2026 개정), 영업팀은 2022년 경비 규정을 신입에게 주고 있었다.
- 그대로 공통 질문에 연결하면 신입이 옛 규정을 보게 된다 → 공통 질문보다 먼저 **개정일 기준으로 최신본만 남기기**로 순서를 바꿨다.
  - `취업규칙(개정)`, `경비 처리 규정_최종`, `… v2`는 같은 문서로 본다.
  - 개정일이 없는 문서는 최신인지 알 수 없어 자동으로 남기지 않고 ‘확인 필요’로 두고, 담당자가 인정해야 쓴다.
- ‘연차 신청’과 ‘명함 신청’이 같은 질문으로 묶임 → 흔한 낱말 ‘신청’은 비교에서 뺐다.

## 6주차 후반 — 연결과 확산

**한 일**
- 공통 질문마다 답이 있을 최신본 자료를 연결. 최신본 목록 안에서만 고르게 했다.
- 수습 급여, 근로계약서 같은 질문은 자료 링크로 답하면 오해가 생길 수 있어 **인사 담당자 답변**으로 따로 표시.
- Claude(`onboarding.faq`)로 뜻이 같은 질문을 다시 묶게 했다. 문서 본문은 보내지 않으므로 답을 쓰지 않고 문서만 고른다.
- 확산 계획: 부서 × 4단계(최신본 확인 → 공통 질문 공유 → 담당자 지정 → 신입 첫 주 적용). 영업팀부터 시작.
- 온보딩 키트를 마크다운으로 복사해 사내 위키에 붙일 수 있게 했다. 테스트 12개.

**막힌 것 → 해결**
- AI가 묶음에서 질문 몇 개를 빠뜨릴 수 있다 → 어느 묶음에도 없는 질문은 한 개짜리 묶음으로 붙여 사라지지 않게 했다.
- AI가 구버전 문서를 고를 수 있다 → 최신본 id가 아니면 연결을 지운다.

**결과 (1기 목표치)**
- 공통 질문 30개 정리, 4개 부서 적용
