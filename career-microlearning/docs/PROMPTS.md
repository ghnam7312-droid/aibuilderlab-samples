# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버 작업 정의(`docs/ai-task.json`)의 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 7주 | 차시 뼈대 | 신임 파트장 대상 1:1 면담 과정을 10분짜리 8차시로 나눠 줘. 차시마다 행동 하나만 배우게. |
| 8주 | 동사 기준 | 측정 가능한 행동 동사 8개와 각 동사의 단계, 짝이 되는 평가 유형을 표로. ‘이해한다’ 같은 관찰 불가 동사 목록도. |
| 8주 | 짝 검사 | 목표 문장에서 동사를 찾고, 평가 유형이 그 동사의 짝인지, 평가 문항에 그 행동이 들어가는지 검사하는 함수와 테스트. |
| 8주 | 응답 검사 | Claude가 다듬은 목표가 여전히 관찰 불가 동사거나, 말한 동사와 목표 문장이 다르거나, 평가가 짝이 아니면 null. |

## 2. 서비스가 쓰는 지시문 — `microlearning.objective`

```
직장인 대상 10분 마이크로러닝 차시의 학습 목표를 측정 가능한 문장으로 다듬고, 그 목표를 확인하는 평가 문항 하나를 짝지어 쓴다.
input.lesson은 차시 제목, 지금 목표, 핵심 내용, 지금 평가, 분량이고, input.verbs는 쓸 수 있는 행동 동사와 단계(level),
짝이 되는 평가 유형(types)이다. objective는 '~을(를) ○○할 수 있다.'로 끝나는 한 문장이고 행동 동사는 input.verbs 중 하나만 쓴다.
'이해한다', '안다', '익힌다', '인식한다'처럼 관찰할 수 없는 동사는 쓰지 않는다. verb와 level은 고른 동사의 값 그대로,
assessment.type은 그 동사의 types 중 하나, assessment.stem은 학습자가 그 행동을 직접 하게 하는 문항으로 쓰고
동사의 행동이 문항에 들어가야 한다. 핵심 내용과 지금 목표에 없는 주제를 새로 지어내지 않는다. reason은 무엇을 왜 바꿨는지 한 문장.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"objective":"","verb":"","level":"","assessment":{"type":"","stem":""},"reason":""}
```
- 입력: `{ course, audience, lesson{no,title,objective,content,assessment,minutes}, verbs[{verb,level,types}] }` · 최대 500토큰
- 화면 검사: `normalizeRewrite()` — 화면의 `checkLesson()`과 같은 기준으로 다시 확인

### 왜 이렇게 썼나
- **동사 목록을 input으로 준다.** Claude가 고른 동사를 화면이 같은 기준으로 검사할 수 있어야 한다. 목록 밖 동사는 검사할 수 없다.
- **목표와 평가를 한 번에 쓰게 했다.** 목표만 고치면 평가가 다시 따로 논다.
- **주제를 지어내지 않게 했다.** 차시 범위를 넓히면 10분을 넘는다.

## 3. 실패했던 이전 버전

```
다음 학습 목표를 블룸의 분류에 맞는 행동 목표로 바꿔 줘.
```
- “1:1 면담의 목적을 이해하고 설명할 수 있다”처럼 관찰 불가 동사가 남거나 행동이 둘이 됐다.
- ‘평가하다’, ‘종합하다’처럼 10분 차시에서 확인하기 어려운 동사를 골랐다.
- 평가 문항은 그대로라 짝이 맞지 않았다 → 지금 버전: 동사 목록과 짝 평가 유형을 input으로 주고, 목표와 평가를 함께 쓰게, 화면에서 같은 기준으로 검사.
