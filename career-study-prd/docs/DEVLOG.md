# 하루치 개발 일지 (커리어 트랙 1~2주차 + 8주차 보완)

> **1기 목표 모델**: 가상의 수강생 ‘새벽기획자’가 이렇게 진행하는 것을 목표로 쓴 일지입니다. 실제 수강생의 기록이 아닙니다.
> 숫자는 COVI 학습 기록 기준입니다. 포트폴리오 합계(31 · 2 · 4h)는 1~2주차 기획 프로젝트이고, 8주차 보완은 따로 적었습니다.

| 시기 | 만든 것 | 프롬프트 | 디버깅 | 시간 |
|---|---|---|---|---|
| 1주차 | 문제 정의, 인터뷰 요약, 기능 12개 → 5개 | 11 | 1 | 1.5h |
| 2주차 | 화면 7개 흐름, 프롬프트 v1~v3 평가표, 프로토타입 | 20 | 1 | 2.5h |
| **포트폴리오 합계** | | **31** | **2** | **4h** |
| 8주차 보완 | 프로토타입에 Claude 연결, 계획 검사, 테스트 | 9 | 2 | 1.5h |

---

## 1주차 — 무엇을 뺄지 먼저

**한 일**
- 스터디원 7명 인터뷰. 5명이 “계획표는 첫 주에 예쁘고 둘째 주에 버려진다”고 말했다.
- 그래서 목표를 ‘계획을 잘 짜는 것’이 아니라 **‘하루 밀려도 다시 따라잡게 하는 것’**으로 바꿨다.
- 기능 아이디어 12개를 ‘계획을 끝까지 지키게 돕는가’ 기준으로 걸러 5개만 남겼다(D1).

**막힌 것 → 해결**
- 요구사항이 섞여 범위가 계속 커짐(캘린더, 알림, 채팅…) → 필수 5개만 남기고 나머지는 ‘2차로 미룬 것’에 이유와 함께 적어 둠.

---

## 2주차 — 화면 흐름과 프롬프트 평가

**한 일**
- 화면 7개 와이어프레임: 시작 → 주간 계획 → 오늘 할 몫 → 밀린 일 다시 나누기 → 진행률 → 코치 → 설정.
- 같은 입력으로 프롬프트 v1~v3을 돌려 5개 기준(정확성·구체성·실행 가능성·개인화·말투)으로 채점. 11점 → 17점 → 24점.
- v2가 하루 4~5과목을 넣는 것을 보고 ‘하루 2과목 이하’ 규칙을 넣었다(D2).
- 리드 빌더 리뷰: “밀린 일을 다시 나누는 기능이 이 서비스의 이유”라는 의견에 1차 기능으로 올림(D3, v1.2).
- 규칙으로 도는 프로토타입: 체크하면 형광펜, 진행률 고리, 코치 한마디.

**막힌 것 → 해결**
- 밀린 일을 다음 날에 몰아 넣으니 그날이 또 밀림 → 가장 가벼운 날부터 채우는 방식으로 변경.

## 8주차 보완 — 프로토타입을 진짜 AI로

**한 일**
- 웹 서비스 프로젝트(한마디함)에서 쓴 방식으로 `study.plan`을 Claude에 연결.
- Claude 계획은 **검사를 통과해야만** 쓴다: 7일 연속 날짜, 하루 시간 이하, 하루 2과목 이하(D4).
- 검사에 걸리면 규칙 계획으로 바꾸고, 왜 걸렸는지 화면에 보여 준다.
- 프롬프트 평가 탭의 v3을 서비스가 실제로 쓰는 지시문으로 바꾸고, 그 자리에서 실행해 볼 수 있게 했다.
- 로직을 `logic.js`로 분리, 테스트 16개.

**막힌 것 → 해결**
- 시험 중 Claude가 하루 2시간인데 228분짜리 날을 넣음 → 검사 규칙으로 잡히는 것을 확인하고 테스트로 고정.
- 1.5시간 ÷ 2과목 = 0.75시간이 “0.8시간”으로 보임 → 30분 단위가 아니면 “72분”처럼 분으로 표기.

**결과**
- 1차 기능 5개 정의, 화면 7개 설계 (포트폴리오)
- 프로토타입: Claude 계획 + 규칙 검사, 오프라인에서도 끝까지 동작
