# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 5개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 3주 | 항목 정하기 | 노무 상담 첫 통화에서 늘 묻는 사실을 7개 항목으로 정리해 줘. 판단이 들어가는 항목은 빼고, 의뢰인이 말한 그대로 옮길 수 있는 것만. |
| 3주 | 규칙 정리기 | 상황 설명을 문장으로 나누고 날짜·금액·근무 시간·계약서 유무를 읽는 함수를 만들어 줘. '오전 9시부터 오후 6시까지'는 9시간, '210만 원'은 2100000. 오늘 날짜는 인자로. |
| 4주 | 판단 막기 | 정리 결과에서 '위법이다, 받을 수 있다, 해당한다' 같은 단정형 판단 문장을 찾는 함수를 만들어 줘. '받을 수 있나요?' 같은 질문은 걸리면 안 돼. |
| 4주 | 응답 검사 | Claude 응답에서 정해진 key가 아니거나, quote가 원문 문장과 거의 안 겹치거나, value가 판단 문장이면 버리고, 판단 문장은 따로 모아 줘. 쓸 게 없으면 null. |
| 4주 | 메모 | 상담 준비 메모를 텍스트로 만들어 줘. 이름은 가운데 글자 가리기, 전화번호·이메일 가리기, 질문은 '노무사 상담에서 확인' 아래에. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### laborintake.facts
```
노무 상담 전에 의뢰인이 쓴 상황 설명(input.story)에서 사실관계만 정리한다. facts의 key는 input.fields의 key 중 하나(start, end, wage, hours, contract, size, issue)만 쓴다. value는 의뢰인이 말한 사실을 짧게 쓰고(날짜는 YYYY-MM-DD, 금액은 원 단위), quote에는 그 사실이 나온 원문 문장을 그대로 옮긴다. input에 없는 사실은 지어내지 않는다. 설명에 없는 항목은 facts에서 빼고 missing에 그 key를 넣는다. 위법 여부, 받을 수 있는지, 청구할 수 있는지 같은 법적 판단이나 조언은 쓰지 않는다. 그런 판단은 노무사 상담에서 확인한다. note는 상담 준비에 도움이 되는 사실 메모 한 문장. 모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"facts":[{"key":"","value":"","quote":""}],"missing":[""],"note":""}
```
- 입력: `{ story(전화번호·이메일 가림, 4,000자까지), side, today, fields }` · 최대 900토큰 · 이름·연락처는 보내지 않음
- 화면 검사: `normalizeAi()` → `merge()`

### 왜 이렇게 썼나
- **‘사실만’을 첫 문장에** — 무엇을 하지 말라는 말보다 무엇을 하는지가 먼저 와야 결과가 흔들리지 않았다.
- **quote를 받는 이유** — 값마다 원문 근거가 있어야 노무사가 바로 확인할 수 있고, 근거가 원문에 없으면 화면에서 버릴 수 있다.
- **판단 금지 문장 + 화면 검사를 함께** — 지시문만으로는 가끔 “해당합니다”가 섞였다. 지시문은 확률을 낮추고, `isJudgement()`가 마지막 문을 막는다.

## 3. 실패했던 이전 버전

```
의뢰인의 상황을 읽고 정리한 뒤, 노무사 입장에서 쟁점과 예상 결과를 알려 줘.
출력 형식: {"summary":"","issues":[""],"opinion":""}
```
- `opinion`에 “퇴직금 청구가 가능합니다”, “부당해고로 볼 여지가 큽니다” 같은 판단이 그대로 나왔다. 의뢰인 화면에 보이면 상담 전에 결론을 믿게 된다.
- `summary`는 줄글이라 어느 사실이 어디서 나왔는지 확인할 수 없었다.
- → 항목별 사실 + 근거 문장 형식으로 바꾸고, 의견 칸을 없앴다.
