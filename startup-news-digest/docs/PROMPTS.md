# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 5개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 1주 | 같은 소식 | 매체가 달라도 같은 소식인 기사를 묶어 줘. 제목 말고 본문에 같은 숫자(단위 포함)가 2개 이상 있고 글이 많이 겹치면 같은 소식. |
| 2주 | 요약 | 고른 기사들을 한 번에 보내고 기사마다 제목·핵심 2~3문장·실무 의미를 JSON으로 받게 해 줘. id는 그대로 돌려받아. |
| 2주 | 규칙 요약 | AI가 안 될 때는 원문에서 숫자가 든 문장, 제목과 겹치는 문장을 골라 그대로 써 줘. 지어 쓰지 말고 고르기만. |
| 3주 | 숫자 대조 | 요약 문장 속 숫자를 뽑아 원문에 같은 숫자가 있는지 확인해 줘. 쉼표는 무시하고, 단위가 다르면 다른 숫자. ‘42만 건’과 ‘42만 명’도 구분. |
| 3주 | 발송 잠금 | 사람이 문장을 고쳐도 같은 검사를 하고, 원문에 없는 숫자가 하나라도 있으면 발송 버튼을 잠가 줘. 무엇이 틀렸는지도 보여 주고. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### `newsdigest.summarize`
```
물류 업계 뉴스 기사 여러 건(input.articles)을 아침 뉴스레터용으로 요약한다. items에는 기사마다 하나씩, id는 input의 id를 그대로 쓴다. headline은 30자 이내 제목, points는 핵심 2~3문장, why는 물류 실무자에게 주는 의미 한 문장. 수량·비율·금액·날짜 같은 숫자는 원문에 적힌 표기 그대로 옮기고, 단위를 바꾸거나 계산하거나 반올림하지 않는다. 원문에 없는 사실과 숫자는 만들지 않는다. intro는 오늘 호 전체를 한 문장으로 소개하되 숫자는 넣지 않는다. 모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"intro":"","items":[{"id":"","headline":"","points":[""],"why":""}]}
```
- 입력: `{ articles: [{ id, title, body }] }` (본문은 기사당 900자까지) · 최대 1500토큰
- 화면 검사: `normalizeDigest()` → 문장마다 `checkNumbers()`로 원문 대조

## 3. 왜 이렇게 썼나

- **“원문에 적힌 표기 그대로”** — ‘18%’를 ‘20% 가까이’로 다듬는 것은 요약으로서는 자연스럽지만, 업계 독자는 그 숫자를 회의 자료에 그대로 옮긴다. 다듬지 말라고 못 박았다.
- **“단위를 바꾸거나 계산하거나 반올림하지 않는다”** — 실패 유형 세 가지(42만 → 420,000, 두 숫자 합산, 반올림)를 각각 막는다.
- **intro에는 숫자를 넣지 않는다** — 여러 기사를 한 문장으로 묶으면 숫자를 섞기 쉬워서, 숫자는 기사별 문장에만 둔다.
- **지시문만 믿지 않는다** — 그래도 틀릴 때가 있어서, 화면에서 숫자를 원문과 대조해 다르면 그 문장을 버린다.

## 4. 실패했던 이전 버전

```
물류 뉴스 기사들을 바쁜 실무자가 아침에 읽기 좋게 쉽고 짧게 요약해 줘. 핵심 숫자는 기억하기 쉽게 정리해 줘.
```
- “기억하기 쉽게”가 반올림 지시로 읽혀 ‘18%’ → ‘약 20%’, ‘312만 TEU’ → ‘300만 TEU 넘게’가 나왔다.
- 기사 id 없이 받아서 어떤 요약이 어느 기사인지 맞추기 어려웠다.
- → id를 그대로 돌려받고, 숫자는 원문 표기 그대로, 화면 대조를 붙인 지금 버전으로 바꿨다.
