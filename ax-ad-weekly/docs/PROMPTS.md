# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 5주 | 열 이름 통일 | 채널 4곳 파일의 열 이름이 달라. 노출·클릭·광고비·구매·장바구니·회원가입·본 뒤 구매·매출로 맞추는 표를 만들어 줘. |
| 5주 | 기준표 | 채널마다 전환에 넣는 사건이 달라. 리포트 기준을 고르면 채널마다 그 사건만 다시 세고, 채널에 자료가 없는 사건은 경고로 알려 주는 함수를 만들어 줘. |
| 6주 | 숫자 대조 | AI 요약 문장에서 숫자를 모두 뽑아서, 리포트에 있는 숫자(원·만 원·소수 1자리)가 아니면 그 요약을 버리게 해 줘. |
| 6주 | 중복 발행 | 발행 기록에 같은 주가 있으면 다시 발행하지 않고, 끊기지 않은 연속 주 수를 세 줘. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### adweekly.summary
```
채널별 광고 성과 숫자로 주간 리포트 요약을 쓴다. lines는 3문장: 1) 전체 광고비와 기준 전환, 지난주 대비 증감,
2) 전환 1건당 비용(CPA)이 가장 낮은 채널과 가장 높은 채널, 3) 채널 보고 전환 합계(reported)와 기준을 맞춘
전환(conv)의 차이와 그 이유(채널마다 전환 기준이 다름). action은 다음 주에 검토할 일 한 문장으로, 단정하지 말고
'검토한다'처럼 쓴다. 숫자는 input에 있는 값만 그대로 쓰고, input에 없는 사실·원인·숫자는 지어내지 않는다.
금액은 원 또는 만 원 단위로 쓴다. 모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"lines":[""],"action":""}
```
- 입력: `{ week, prevWeek, standard, total, change, channels[] }` — 화면 리포트와 같은 숫자, 개인정보 없음 · 최대 700토큰
- 화면 검사: `normalizeSummary()` — lines 2~4개, action 필수, 문장 속 숫자가 모두 리포트 숫자일 것

## 3. 왜 이렇게 썼나

- **문장마다 할 일을 정했다.** 매주 같은 순서(전체 → 채널 비교 → 기준 차이)로 읽혀야 팀이 지난주와 비교하기 쉽다.
- **3번 문장에 기준 차이를 넣었다.** 리포트를 받는 사람이 “채널 화면에서는 460건인데?”라고 묻기 전에 답하게.
- **할 일은 ‘검토한다’로.** 예산 이동은 팀장이 정한다. AI가 단정하면 리포트가 결정처럼 읽힌다.
- **숫자는 input에 있는 것만.** 그래도 계산해 넣는 경우가 있어 화면에서 한 번 더 대조한다.

## 4. 실패했던 이전 버전

```
이번 주 광고 성과를 분석해서 인사이트를 알려 줘.
```
- 결과: 다섯 문단 줄글. “전환율이 개선되어 브랜드 인지도가 상승했습니다” 처럼 데이터에 없는 원인을 붙였고, 전환율을 직접 계산해 input에 없는 숫자(4.2%)를 넣었다. 매주 길이와 순서가 달라 리포트에 붙일 수 없었다.
- 고친 점: 문장 수와 각 문장의 내용을 고정, JSON 형식 지정, “input에 없는 사실·원인·숫자는 지어내지 않는다” 추가, 화면 숫자 대조.
