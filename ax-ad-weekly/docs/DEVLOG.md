# 광고한장 개발 일지 (직장인 AX 트랙 5~6주차)

> **1기 목표 모델**: 가상의 수강생 ‘보고서는자동’(마케팅팀 주임)이 이렇게 진행하는 것을 목표로 쓴 일지입니다. 실제 수강생의 기록이 아닙니다.
> 숫자는 COVI 학습 기록 기준이며, 포트폴리오에 적은 합계와 같습니다.

| 시기 | 만든 것 | 프롬프트 | 디버깅 | 시간 |
|---|---|---|---|---|
| 5주차 전반 | 월요일 오전 쪼개기, 채널 원본 모으기 | 10 | 1 | 1.5h |
| 5주차 후반 | 합계가 틀린 이유 찾기, 전환 기준표 | 11 | 2 | 1.5h |

| 6주차 후반 | 원본 검사, 메일·CSV, 자동 발행, 테스트 | 8 | 1 | 1.5h |
| **합계** | | **38** | **6** | **6h** |

## 5주차 전반 — 월요일 오전이 어디로 가는지

**한 일**
- 주간 리포트 3시간을 재 보니: 채널 4곳 로그인·내려받기 50분, 시트에 붙여 넣고 열 맞추기 60분, 합계·증감 계산 30분, 요약 쓰기 40분.
- 채널 파일마다 열 이름이 달라서(‘비용’, ‘광고비’, ‘지출’) 노출 · 클릭 · 광고비 · 사건별 전환 · 매출로 이름을 통일했다.

**막힌 것 → 해결**
- 광고비에 원 단위 쉼표와 소수점이 섞여 시트가 글자로 읽음 → 붙여 넣을 때 숫자로 바꾸고, 바뀌지 않으면 빨간 칸으로 표시.

---

## 5주차 후반 — 합계가 틀린 이유

**한 일**
- 자동으로 모은 첫 리포트의 전환 합계가 쇼핑몰 주문 수보다 2배 넘게 많았다.
- 채널 도움말을 하나씩 읽어 보니 채널마다 ‘전환’에 넣는 것이 달랐다. 검색광고는 장바구니까지, SNS광고는 클릭 없이 본 뒤 7일 안 구매까지, 동영상광고는 회원가입까지.
- **채널 × 사건 전환 기준표**를 만들고, 리포트 기준(기본: 클릭 후 구매)을 정한 뒤 채널마다 기준 사건만 다시 세어 더했다. 샘플 주: 채널 보고 합계 946건 → 기준 합계 364건.

**막힌 것 → 해결**
- 채널 ‘전환’ 칸을 그대로 더해 합계가 틀림 → 채널별 기준을 표로 맞춘 뒤 합산 (`stdConv`, `standardTable`).
- 기준에 장바구니를 넣었더니 장바구니 자료가 없는 채널이 조용히 0으로 들어감 → ‘자료 없음’ 칸과 경고 문장을 따로 보여 줌.

## 6주차 전반 — 리포트 한 장과 요약

**한 일**
- 광고비 · 기준 전환 · CPA · ROAS, 지난주 대비, 채널별 표를 한 장에. 채널 보고 전환은 지운 선으로 옆에 남겨 차이가 보이게 했다.
- `adweekly.summary`로 Claude가 요약 3문장 + 다음 주 할 일을 쓰게 했다. 규칙 요약이 먼저 나오고 Claude 결과가 오면 덮어쓴다.

**막힌 것 → 해결**
- Claude가 “전환율 4.2%” 처럼 input에 없는 숫자를 계산해 넣음 → 문장 속 숫자를 모두 뽑아 리포트 숫자와 대조하고, 없는 숫자가 하나라도 있으면 버리고 규칙 요약 유지.
- 같은 숫자를 ‘739만 원’과 ‘7,390,000원’으로 써서 대조가 실패 → 원 · 만 원 · 소수 1자리 모두 허용 목록에 넣음.

## 6주차 후반 — 매주 알아서

**한 일**
- 원본 숫자 검사(빈 칸 · 음수 · 클릭>노출 · 구매>클릭). 오류가 있으면 발행 버튼을 막는다.
- 메일 본문 복사, 채널별 표 CSV.
- 실제 버전은 Apps Script 시간 트리거로 매주 월요일 09:00 발행. 데모는 발행 기록과 연속 주 수만 남긴다.
- 로직을 `logic.js`로 분리하고 테스트 13개.

**막힌 것 → 해결**
- 트리거가 두 번 돌아 같은 주가 두 번 발행됨 → 같은 주가 기록에 있으면 발행하지 않는 `publish()` 검사.

**결과 (1기 목표치)**
- 주간 리포트 3시간 → 20분
- 8주 연속 자동 발행
