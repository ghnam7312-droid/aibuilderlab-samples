# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 4주 | 집계 | 설문 CSV(이름, 부서, 5문항 1~5점, 사전·사후 자가진단, 추천 0~10, 의견)를 읽어 문항 평균, 사전→사후 변화, NPS를 계산해 줘. 의견 안 쉼표도 지켜 줘. |
| 5주 | 익명 처리 | 응답자 명단으로 의견 속 이름을 가려 줘. 성+이름, 이름+호칭(팀장님, 님), 성+직함(김 팀장)까지. 전화·이메일도. 리포트를 다 만든 뒤 화면 글자에서 이름을 다시 찾아 남으면 복사를 막아 줘. |
| 5주 | 작은 집단 | 부서별 평균은 응답 5명 이상만 보여 주고, 작은 부서는 ‘기타’로 합쳐. 합쳐도 5명 미만이면 숨겨. |
| 6주 | 응답 검사 | Claude 요약에서 headline이 없거나 잘된 점·보완할 점이 둘 다 비면 버리고, 이름이 섞여 있으면 다시 가려 줘. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### trainingreport.summary
```
기업 교육이 끝난 뒤 받은 설문의 집계와 익명 의견으로 교육 담당자가 윗선에 올릴 결과 요약을 쓴다.
input의 숫자(n, overall, questions, selfAssessment, nps)와 comments만 근거로 쓰고, input에 없는 사실이나 숫자는 지어내지 않는다.
사람 이름, 부서, 연락처는 쓰지 않는다(의견 속 ○○○는 가린 이름이므로 그대로 둔다).
headline은 응답 수와 전체 만족도, 역량 변화를 담은 한 문장. strengths와 improvements는 각각 최대 3개로 문항 점수나 의견 수를 근거로 든다.
commentThemes는 의견을 주제별로 묶어 많은 순서 최대 4개, example은 comments에 있는 문장을 그대로 짧게 인용한다.
nextSteps는 다음 차수나 후속 관리에서 할 구체적 조치 최대 3개.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"headline":"","strengths":[""],"improvements":[""],"commentThemes":[{"theme":"","count":0,"example":""}],"nextSteps":[""]}
```
- 입력: `{ course, client, n, overall, questions, selfAssessment, nps, comments }` — 집계와 가린 의견(최대 60건, 건당 200자)만 · 최대 900토큰
- 화면 검사: `normalizeSummary()` (형식 검사 + 명단으로 다시 가림) → 실패하면 규칙 요약 유지

## 3. 왜 이렇게 썼나

- **근거를 input으로 묶음** — 윗선 보고에 들어가는 문장이라 숫자가 하나라도 틀리면 신뢰가 깨진다. “input에 없는 숫자는 지어내지 않는다”와 “점수나 의견 수를 근거로”를 함께 넣었다.
- **이름 금지 + ○○○ 유지** — 가린 자리를 Claude가 ‘복원’하려 하지 않도록 ○○○의 뜻을 알려 주었다. 그래도 화면에서 한 번 더 가린다.
- **배열 형식** — 담당자가 항목을 골라 보고서에 옮기기 쉽게 잘된 점·보완할 점·다음 단계를 나눴다.

## 4. 실패했던 이전 버전

```
설문 결과 CSV를 줄 테니 교육 결과 보고서를 써 줘.
```
- 원문 CSV(이름 포함)를 그대로 보냈더니 “김도현 팀장님은 사례가 좋았다고 했습니다”처럼 **이름을 인용한 보고서**가 나왔다. 5주차 이름 노출 사고와 같은 문제를 AI가 다시 만든 셈이라, 입력을 집계와 가린 의견으로 바꾸고 이름 금지 문장을 넣었다.
