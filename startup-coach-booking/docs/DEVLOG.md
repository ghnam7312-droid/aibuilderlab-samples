# 한자리 개발 일지 (창업 트랙 4~5주차)

> **1기 목표 모델**: 가상의 수강생 ‘이직나침반’(전 HR 담당자 · 커리어 코치)이 이렇게 진행하는 것을 목표로 쓴 일지입니다. 실제 수강생의 기록이 아닙니다.
> 숫자는 COVI 학습 기록 기준이며, 포트폴리오에 적은 합계와 같습니다.

| 시기 | 만든 것 | 프롬프트 | 디버깅 | 시간 |
|---|---|---|---|---|
| 4주차 | 예약 폼, 빈 시간 · 중복 막기, 결제 링크 | 8 | 1 | 1.5h |

| **합계** | | **27** | **5** | **4h** |

## 4주차 — DM 대신 예약 폼

**한 일**
- 하루 30분이 어디 가는지 보니: “이번 주 언제 돼요?” 답하기, 입금 확인, 상담 전날 다시 알리기.
- 7일 × 3개 시간의 예약 폼. 이미 잡힌 시간은 회색으로 막았다.
- 예약하면 결제 대기 상태로 자리를 잡고, 결제 링크를 보낸다(데모는 모의 결제).

**막힌 것 → 해결**
- 두 사람이 같은 시간을 동시에 잡음 → 저장 직전에 한 번 더 `taken()`으로 확인하고 “방금 다른 분이 예약한 시간”으로 막음.

## 5주차 전반 — 사람이 하던 안내를 자동으로

**한 일**
- 결제 요청 · 결제 리마인드(6시간 뒤) · 예약 확정 · 하루 전 · 2시간 전 메일을 예약마다 계획(`planMails`).
- 결제 대기 12시간이 지나면 자리를 푼다(`expire`). 환불 규정은 24시간 전 전액, 이후 50%.
- 데모에서 시간을 확인하려고 시뮬레이션 시계(`+6시간`, `+1일`)를 붙였다.

**막힌 것 → 해결**
- 시계를 두 번 돌리면 같은 메일이 또 나감 → 예약+메일 종류로 처리 기록을 남기고 한 번만.
- 결제 기한이 지난 자리가 폼에서 계속 막혀 있음 → 시계가 움직일 때마다 만료부터 처리하고 폼을 다시 그림.

## 5주차 후반 — 취소했는데 왜 메일이 와요?

**한 일**
- 고객 한 분이 “취소했는데 내일 상담 안내가 왔다”고 알려 줬다. 메일을 **예약할 때 미리 줄 세워 두고**, 보낼 때는 상태를 보지 않았던 것이 원인.
- 보낼 시각이 되면 그 순간의 예약 상태를 다시 보고(`shouldSend`), 결제 완료가 아니면 보내지 않고 ‘보류 · 취소된 예약’으로 남기게 고쳤다. 결제 요청 메일은 반대로 결제 대기일 때만.
- 확정 메일은 고객이 남긴 말을 반영해 Claude가 쓰게 했다(`coachbooking.mail`). 보낼지 말지는 AI가 정하지 않는다.
- 로직을 `logic.js`로 분리하고 테스트 13개.

**막힌 것 → 해결**
- Claude 확정 메일이 요일을 틀리게 씀(10/30(목)) → 지시문에 “input.when을 글자 그대로”, 화면에서는 본문에 정확한 일시가 없으면 버리는 `normalizeMail`.
- 패키지 금액을 ‘회당 7만 원’처럼 나눠 쓴 적이 있음 → 결제 금액과 다른 금액이 보이면 버림.

**결과 (1기 목표치)**
- 예약 응대 하루 30분 → 5분, 노쇼 22% → 6%
