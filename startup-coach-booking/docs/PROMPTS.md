## 2. 서비스가 쓰는 지시문 (`coachbooking.mail`)

```
커리어 코칭 예약이 결제까지 끝난 고객에게 보낼 '예약 확정 안내' 메일을 쓴다. input.product는 상품,
input.price는 결제 금액, input.when은 상담 일시, input.firstName은 고객 이름(성 뺀 것), input.note는
고객이 상담에서 다루고 싶다고 남긴 말(비어 있을 수 있음), input.coach는 보내는 코치,
input.refundRule은 환불 규정이다. subject는 40자 이내로 일시를 넣는다. body는 5~7문장: 확정 사실과
일시(input.when을 글자 그대로), 결제 금액, note가 있으면 그 주제를 준비하겠다는 한 문장, 상담 전에
사전 설문을 남겨 달라는 요청, 환불 규정, 마지막 줄은 'input.coach 드림'. 일시·금액·규정은 input 값을
바꾸지 말고 그대로 쓰고, input에 없는 혜택이나 약속(합격, 연봉 상승 등)은 만들지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"subject":"","body":""}
```
- 입력: `{ product, price, when, firstName, note, coach, refundRule }` — 이메일은 보내지 않음 · 최대 600토큰
- 화면 검사: `normalizeMail()` — 일시가 그대로 있는지, 다른 금액이 없는지, 길이

## 3. 왜 이렇게 썼나

- **일시를 글자 그대로** — 날짜를 다시 쓰게 두면 요일이 틀린다. 화면이 같은 글자를 찾아 검사할 수 있게.
- **보낼지 말지는 묻지 않는다** — 상태 판단은 규칙(`shouldSend`)이 하고, AI는 문장만 쓴다. 그래서 취소 예약 버그가 AI 때문에 다시 생길 수 없다.
- **없는 혜택·약속 금지** — 확정 메일에 “합격까지 함께”, “연봉 상승” 같은 문장이 붙으면 안 된다.

## 4. 실패했던 이전 버전

```
예약한 고객에게 보낼 친절한 확정 메일을 써 줘. 상담 정보: {예약 전체}
```
- 결과: 예약 전체(이메일 포함)를 그대로 보냄, 요일을 틀림, “첫 상담 할인” 같은 없는 혜택을 붙임. 결제 대기 예약에도 확정 메일을 쓰게 됨.
- 고친 것: 결제 완료 예약에만 부르고, 필요한 값만 보내고, 일시·금액은 그대로 쓰게 + 화면 검사.
