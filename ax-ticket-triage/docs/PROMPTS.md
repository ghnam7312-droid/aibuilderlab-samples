# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 담아 서버 작업 목록에 넣는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 5개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 3주 | 분류 규칙 | 고객 문의를 7개 분류로 나누는 함수를 만들어 줘. 분류마다 낱말 목록이 있고, 제목에 나온 낱말은 두 번 세. 아무것도 안 맞으면 ‘기타’로 매니저에게. |
| 3주 | 문의함 | 문의 목록에 접수 시각, 채널, 대기 시간을 보여 줘. 목표가 40분이니까 30분부터 노랑, 40분 넘으면 빨강. |
| 4주 | 선 긋기 | 환불·보상 분류는 답변 초안을 만들지 말고 팀장에게 바로 넘겨. 다른 분류도 초안에 ‘환불해 드리겠습니다’, ‘무료로’, ‘전액’ 같은 약속 표현이 있으면 초안을 버리고 넘겨. |
| 4주 | 응답 검사 | Claude 응답의 category가 목록에 없으면 null. confidence는 0~1로 자르고, 규칙이 사람에게 넘긴 문의는 AI 결과가 와도 넘김을 풀지 마. |
| 4주 | 개인정보 | 문의 글에서 휴대폰 번호, 이메일, 카드번호, 고객 이름을 [연락처] 같은 표시로 바꿔 줘. AI에 보낼 때와 CSV에 이걸 써. |

## 2. 서비스가 쓰는 지시문 (`triage.classify`)

```
고객 문의 한 건을 분류하고 답변 초안을 쓴다. category는 input.categories 중 하나를 글자 그대로 쓴다.
confidence는 0~1이며, 두 분류 사이에서 애매하면 0.6 미만으로 둔다. reason은 판단 근거 한 문장.
urgent는 고객이 오늘·당장 같은 기한을 말했거나 다친 일이 있으면 true.
draft는 고객에게 보낼 3문장 이내의 답변 초안으로, 솔담리빙 고객지원팀 인사, 확인할 내용, 고객이 할 다음 단계를 담는다.
환불·보상·배상·무료 처리·쿠폰 지급은 약속하지 않는다.
category가 환불·보상이거나 다친 일·신고·소송이 언급되면 draft는 빈 문자열로 둔다.
문의에 없는 주문 정보·날짜·금액은 지어내지 않는다. [이름], [연락처]처럼 가린 부분은 그대로 둔다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"category":"","confidence":0.0,"reason":"","urgent":false,"draft":""}
```
- 입력: `{ subject, body, channel, categories }` — subject·body는 **개인정보를 가린 글** · 최대 600토큰
- 화면 검사: `normalizeTriage()` (분류가 목록에 있는지, 약속 표현) → `applyAi()`

### 왜 이렇게 썼나
- **분류 이름을 입력으로 준다** — 지시문에 분류를 박아 두면 화면과 어긋난다. 화면이 가진 목록을 그대로 보내고 “글자 그대로” 쓰게 해서 검사를 단순하게 했다.
- **환불·보상이면 draft를 비우라고 지시 + 화면에서도 강제** — 지시문은 확률이다. 지시를 어겨도 `normalizeTriage()`가 초안을 버린다.
- **가린 글만 보낸다** — 분류에 이름·연락처는 필요 없다.

## 3. 실패했던 이전 버전

```
고객 문의에 친절하게 답변 초안을 써 줘. 고객이 만족할 수 있도록 해결 방법을 제시해 줘.
출력 형식: {"category":"","draft":""}
```
- “만족할 수 있도록 해결 방법을 제시”가 문제였다. 파손 문의에 “불편을 드려 죄송합니다. **무료로 교환해 드리고 배송비도 저희가 부담하겠습니다**”처럼 확정되지 않은 약속을 썼다.
- 지시문에 “약속하지 마”를 넣은 뒤에도 환불 문의에서는 가끔 “환불 처리해 드리겠습니다”가 나왔다 → 환불·보상은 **초안을 만들지 않는 쪽**으로 결정(위 지시문 + 화면 검사).
