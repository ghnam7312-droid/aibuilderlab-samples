# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버 작업 정의(`docs/ai-task.json`) 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 1일 | 금액 읽기 | 메모에서 ‘3,200만 원’, ‘1억 2천만’, ‘1.5억’, ‘450,000원’을 원 단위 숫자로 바꾸는 함수를 만들어 줘. 사람 수나 ‘2곳’은 금액이 아니야. |
| 2일 | 칸 채우기 | 미팅 메모를 고객사·담당자·단계·금액·미팅일·다음 연락일·다음 할 일·요약 칸으로 나눠 줘. 규칙 결과를 먼저 보여 주고 AI 결과가 오면 덮어써. |
| 3일 | 숫자 관문 | 금액과 날짜 칸은 사람이 ‘원문과 맞음’을 누르거나 직접 고쳐야 저장 버튼이 열리게 해 줘. AI가 준 숫자가 메모에 없으면 빨갛게 표시하고 확인 버튼을 잠가. |
| 4일 | CSV | 고객 목록을 CSV로 내보내 줘. 엑셀에서 한글 안 깨지게, 수식으로 읽히는 글자 막고, 전화·메일은 빼고. |

## 2. 서비스가 쓰는 지시문 (`meetingcrm.extract`)

```
영업 미팅 메모 한 건을 CRM 입력 칸으로 옮긴다. company는 고객사 이름(input.customers에 있으면 그 표기 그대로),
contact는 고객 측 담당자 '이름 직함', stage는 input.stages 중 하나. amount는 메모에 적힌 예상 거래 금액을
원 단위 정수로 바꾼다('3,200만'→32000000, '1억 2천만'→120000000). 금액이 여러 개면 최종·확정된 금액을 고르고,
판단이 어려우면 0으로 둔다. meetingDate와 nextDate는 YYYY-MM-DD (오늘 날짜 input.today 기준으로 '다음 주 화요일',
'내일' 같은 표현을 날짜로 바꾼다; 없으면 빈 문자열). nextAction은 우리 쪽이 다음에 할 일 한 문장, summary는
미팅 내용 2문장 이내. 메모에 없는 금액·날짜·이름은 절대 지어내지 않는다. 전화번호·메일 주소는 옮기지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"company":"","contact":"","stage":"","amount":0,"meetingDate":"","nextDate":"","nextAction":"","summary":""}
```
- 입력: `{ memo(전화·메일 가린 뒤 6,000자까지), today, weekday, customers, stages }` · 최대 600토큰
- 화면 검사: `normalizeAi()` → 숫자 칸 원문 대조(`inSource`) → `mergeAi()` → 사람 확인(`canSave`)

## 3. 왜 이렇게 썼나

- **금액 예시를 지시문에 넣었다** — ‘3,200만’을 3200으로 돌려주는 일이 있어서, 원 단위 정수와 바꾸는 예를 적었다.
- **“판단이 어려우면 0”** — 금액이 두 개일 때 아무거나 고르기보다 비워 두는 편이 낫다. 0이면 화면이 규칙 값과 후보를 보여 주고 사람이 고른다.
- **연락처는 옮기지 않는다** — 보내기 전에 이미 가리지만, 혹시 남아도 CRM 칸으로 넘어오지 않게 두 번 막았다.

## 4. 실패했던 이전 버전

| 버전 | 지시문 | 결과 |
|---|---|---|
| v1 | “미팅 메모를 CRM 형식으로 정리해 줘. 금액과 날짜도 넣어 줘.” | 금액이 `"3,200만 원"`(글자)·`3200`(만 원 단위)으로 섞여 옴. 처음 말한 예산을 최종 금액으로 넣고, ‘다음 주 화요일’을 이번 주로 계산. 메모에 없는 날짜를 지어 넣기도 함 |
| v2 (지금) | 원 단위 정수 · YYYY-MM-DD · 오늘 날짜 함께 보냄 · “지어내지 않는다” · 애매하면 0 | 형식은 안정. 그래도 숫자는 틀릴 수 있어 화면에서 원문 대조 + 사람 확인을 붙임 |
