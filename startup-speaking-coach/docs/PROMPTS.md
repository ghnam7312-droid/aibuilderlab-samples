# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버에 넣을 원문([ai-task.json](ai-task.json))입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 2주 | 받아쓰기 | 버튼을 누르면 영어 음성 인식을 시작하고 말한 길이를 재 줘. 음성 인식이 없거나 권한이 막히면 이유를 보여 주고 직접 입력으로 같은 흐름을 쓰게. |
| 3주 | 규칙 첨삭 | 내가 수업에서 자주 고치는 실수 11개를 규칙으로 만들어 줘. 지난 일 이야기일 때만 과거 시제를 보고, 같은 실수는 묶어서 몇 번인지 세게. |
| 3주 | 2개 제한 | 찾은 실수를 뜻이 달라지는 것 → 반복 → 먼저 나온 순서로 줄 세우고 위의 2개만 학생에게 보여 줘. 나머지는 튜터만 보는 칸으로. |
| 4주 | 응답 검사 | Claude 첨삭에서 wrong이 받아쓴 문장에 없으면 버리고, 몇 개를 주든 2개까지만 남겨. 전부 버려지면 null. |

## 2. 서비스가 쓰는 지시문

### speakingcoach.feedback
```
영어 말하기 숙제를 받아쓴 문장(input.transcript)을 읽고 학생에게 돌려줄 첨삭을 쓴다.
fixes는 뜻이 달라지거나 여러 번 반복된 실수부터 최대 2개(input.maxFixes)만 고른다.
wrong은 transcript에 실제로 있는 표현을 글자 그대로 옮기고, better는 그 부분만 고친 표현,
why는 학생이 이해할 이유 한 문장, title은 10자 안팎의 요약이다.
나머지 실수는 later에 짧은 제목으로만 최대 5개.
good은 잘한 점 한 문장이며 목표 표현(input.target)을 썼으면 그 부분을 인용한다.
retry는 fixes만 고치고 나머지는 그대로 둔 전체 문장이다.
transcript에 없는 말을 지어내지 않고, 받아쓴 글로 알 수 없는 발음·억양은 판단하지 않는다.
wrong·better·retry는 영어 그대로 쓴다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"good":"","fixes":[{"title":"","wrong":"","better":"","why":""}],"later":[""],"retry":""}
```
- 입력: `{ homework, target, level, transcript, seconds, maxFixes }` (문장 2,000자까지) · 최대 900토큰
- 화면 검사: `normalizeFeedback()` — 말하지 않은 표현은 버림, 2개까지, `good`이 없으면 버림

## 3. 왜 이렇게 썼나

- **2개를 지시문과 코드 양쪽에서** — 이 서비스의 핵심 결정이라 모델이 어겨도 학생 화면에서는 지켜지게 했다.
- **wrong은 글자 그대로** — 받아쓴 문장에서 위치를 찾아 번호로 표시하고, 지어낸 지적을 걸러 내는 기준이 된다.
- **later는 제목만** — 학생에게 가지 않는 정보라 짧게 받아 토큰을 아낀다.
- **발음은 판단하지 않는다** — 받아쓴 글만으로는 알 수 없는 것을 그럴듯하게 말하지 않게.

## 4. 실패했던 이전 버전

```
학생의 영어 문장을 첨삭해 줘. 틀린 곳을 모두 찾아서 고친 문장과 설명을 줘.
```
- 결과: 문장마다 6~8개의 지적, 표현 다듬기까지 섞여 학생이 무엇부터 고칠지 몰랐다. 베타 학생 일부가 다음 숙제를 내지 않았다.
- 학생이 하지 않은 말을 고쳐 주는 경우도 있었다(받아쓰기 오류를 문법 실수로 봄).
- → ‘최대 2개 + 우선순위 + 글자 그대로 인용’으로 바꾸고, 화면 검사를 붙였다.
