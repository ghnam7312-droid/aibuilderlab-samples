## 3주차 전반 — 한 문구만 올리던 습관부터

**한 일**
- 학회 홍보 글을 다시 보니 문구가 늘 하나였다. 비교할 대상이 없으니 ‘잘 됐다’의 기준도 없었다.
- 방문자마다 A·B 중 하나를 고정해서 보여 주기로 했다(같은 사람이 두 문구를 다 보면 비교가 흐려진다). 방문자 번호를 해시해서 짝/홀로 나눔.
- 노출(view)과 클릭(click)을 따로 기록.

**막힌 것 → 해결**
- 처음엔 무작위로 나눠서 새로고침할 때마다 문구가 바뀜 → 방문자 번호 기반 해시로 바꾸고 “같은 방문자는 늘 같은 문구” 테스트 추가.
- 클릭률을 소수점 없이 반올림해 1.8%와 2.4%가 둘 다 2%로 보임 → 표시는 소수 둘째 자리까지.

## 3주차 후반 — 클릭이 두 번씩 잡힌다

**한 일**
- 첫 대결에서 B 클릭률이 7%가 넘게 나와서 이상했다. 기록을 한 줄씩 보니 같은 방문자의 클릭이 1~2분 간격으로 두 번씩 있었다.
- 원인: 신청 페이지에서 뒤로 가기·새로고침을 하면 같은 기록이 다시 전송됨.
- **같은 방문자·같은 문구·같은 종류가 30분 안에 다시 오면 한 번만 세는 조건**을 추가. 노출 기록 없이 들어온 클릭도 빼기로 함.
- 화면에 ‘새로고침 중복 막기’ 스위치를 두어 고치기 전/후 숫자를 나란히 볼 수 있게 함.

**막힌 것 → 해결**
- 기록이 시간순으로 오지 않아 중복을 놓침 → 세기 전에 시각으로 정렬.
- 30분이 지난 재방문까지 지워짐 → 마지막으로 ‘센’ 시각 기준으로 창을 재도록 수정하고 경계 테스트(31분) 추가.

## 4주차 전반 — 언제 ‘이겼다’고 말할까

**한 일**
- 하루 이틀 숫자는 들쭉날쭉해서 판정이 매일 바뀌었다.
- 문구마다 노출 300회가 모이기 전엔 판정하지 않고 “노출 ○회 더 필요”라고만 보여 준다.
- 300회가 넘으면 두 비율 z검정(유의수준 5%). 차이가 없으면 새 문구를 남기지 않고 원래 문구(A)를 유지.

**막힌 것 → 해결**
- 정규분포 누적값을 직접 구현하다 부호를 반대로 써서 p값이 1을 넘음 → 알려진 값(1.96 → 0.975)으로 테스트를 먼저 쓰고 고침.
- 노출 0회인 새 대결에서 0으로 나누기 → 노출이 없으면 p=1로 처리.

## 4주차 후반 — AI는 후보만, 판정은 숫자로

**한 일**
- `abcopy.suggest`로 남긴 문구에 맞설 후보 3개를 받는다. 후보는 바로 게시하지 않고 ‘다음 대결’의 B로만 올라간다.
- AI가 꺼져 있으면 행사 정보(일시·장소·혜택·정원)를 다시 배치하는 규칙 후보.
- 결과 CSV는 방문자 번호 없이 대결별 집계만.
- 로직을 `logic.js`로 분리하고 테스트 14개.

**막힌 것 → 해결**
- Claude가 “지난 학기 신입 95%가 남은 학회”처럼 없는 숫자를 씀 → 지시문에 “input에 없는 숫자는 지어내지 않는다”, 화면에서는 입력에 없는 숫자가 든 후보를 버리는 검사(`inventedNumbers`).
- ‘무조건’, ‘역대급’ 같은 과장 표현 → 지시문 + 과장 표현 검사로 이중으로 거름.

**결과 (1기 목표치)**
- 문구 6쌍 테스트, 클릭률 1.8% → 3.1%
- 문구 작성 2시간 → 20분
