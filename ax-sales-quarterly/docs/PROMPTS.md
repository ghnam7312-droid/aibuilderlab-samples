# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버 작업 정의(`docs/ai-task.json`) 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 6주 | 양식 | 분기 영업 리포트 양식을 하나로 정해 줘. 숫자 6칸, 요약 4문장, 담당별 표, 큰 수주 3건. 팀이 바뀌어도 칸 순서는 같게. |
| 6주 | 점검 | 거래 행에 빈칸, 분기 밖 날짜, 같은 거래 두 번이 있으면 빨갛게 표시하고 계산에서 빼 줘. 진행 중 거래는 다음 분기 날짜여도 괜찮아. |
| 7주 | 검산 | AI가 쓴 요약 문장에서 ‘3억 2,000만 원’, ‘91.7%’, ‘7건’ 같은 숫자를 읽어서 우리가 계산한 숫자와 다르면 그 문장을 버려 줘. |
| 7주 | 가이드 | 처음 쓰는 팀원용 사용 가이드를 1장으로 만들어 줘. 4단계, 단계마다 화면을 줄여 그린 그림 한 장과 두 줄 설명. 가이드만 인쇄할 수 있게. |

## 2. 서비스가 쓰는 지시문 (`salesq.summary`)

```
영업팀 분기 리포트의 요약 4문장을 쓴다. 1) 수주액과 목표 대비(achievePct), 2) 지난 분기 대비(qoqPct,
prevWon이 '기록 없음'이면 비교하지 않는다고 쓴다), 3) 수주·실주 건수와 승률, 담당별(byOwner)에서 눈에 띄는 점 하나,
4) 진행 중 거래(pipeline)로 본 다음 분기 할 일. 숫자는 input에 있는 값을 표기 그대로만 쓰고, 새로 계산하거나
반올림을 바꾸거나 input에 없는 숫자·원인·거래처를 지어내지 않는다. 팀원을 평가하거나 탓하는 말은 쓰지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"lines":[""]}
```
- 입력: `{ team, quarter, prevQuarter, won, target, achievePct, prevWon, qoqPct, wonCount, lostCount, winRatePct, avgDeal, pipeline, pipelineCount, byOwner[] }` (금액은 ‘2억 7,500만 원’처럼 표기된 글자) · 최대 700토큰
- 화면 검사: `normalizeSummary()`(3문장 이상) → `checkNumbers()`(문장 속 숫자 = 계산 숫자)

## 3. 왜 이렇게 썼나

- **금액을 글자로 보낸다** — 원 단위 숫자(275000000)를 주면 Claude가 ‘2.75억’, ‘약 2억 8천’처럼 제각각 바꿔 씁니다. 리포트와 같은 표기를 그대로 주고 “표기 그대로만”이라고 적었습니다.
- **원인을 지어내지 않게** — “경기 회복으로 늘었다” 같은 문장이 붙곤 해서, input에 없는 원인은 쓰지 않게 했습니다.
- **팀원 평가 금지** — 팀 공용 리포트라, 담당별 숫자를 두고 누구를 탓하는 문장이 나오지 않게 했습니다.

## 4. 실패했던 이전 버전

| 버전 | 지시문 · 입력 | 결과 |
|---|---|---|
| v1 | “이번 분기 거래 목록으로 영업 리포트 요약을 써 줘.” + 거래 행 전체 | Claude가 수주액을 직접 더해 계산이 틀림(2억 7,500만 → ‘약 2억 9천만 원’). 실주 건까지 수주에 넣음 |
| v2 (지금) | 계산한 숫자만 표기 그대로 입력 · 4문장 순서 지정 · 지어내지 않기 · 화면 숫자 검산 | 숫자가 리포트와 일치. 혹시 다르면 화면이 버리고 규칙 요약 사용 |
