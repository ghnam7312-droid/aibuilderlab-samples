# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 7주 | 규칙 분류 | 리뷰를 칭찬 말·불만 말 개수와 별점으로 긍정/중립/부정으로 나누고, 주제 7개 중 하나와 확신도 0~1을 붙여 줘. |
| 7주 | 사람 확인 | 칭찬 말투에 불만이 섞이거나 별점과 글이 어긋나거나 확신도가 0.6 미만이면 자동 분류하지 말고 '사람 확인'으로 보내. AI가 확신해도 이 신호는 지우지 마. |
| 7주 | 안전 | 다침·화상·발열·연기 같은 말이 있으면 분류하지 말고 담당자에게 넘기는 칸으로 보내 줘. |
| 7주 | 개인정보 | 리뷰 본문의 전화번호·이메일·주문번호를 가리는 함수를 만들고, AI에 보낼 때는 작성자 이름을 빼 줘. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### reviewsort.classify
```
쇼핑몰 고객 리뷰 여러 건을 한 건씩 분류한다. id는 input의 id 그대로. sentiment는 긍정, 중립, 부정 중 하나.
칭찬하는 말투라도 불만 내용(늦은 배송, 파손, 샘 등)이 있으면 반어로 보고 부정으로 하고 confidence를 0.6 미만으로 둔다.
category는 배송, 품질·불량, 사이즈·규격, 포장, 설명·조립, 가격, 기타 중 하나. request는 상품팀이 고칠 수 있는
개선 요청을 리뷰 문장 그대로 짧게(없으면 빈 문자열). confidence는 0~1. 별점과 글이 어긋나거나 판단이 애매하면
confidence를 0.6 미만으로 둔다. 다침·화상·발열·연기 같은 안전 관련 내용은 판단하지 말고 confidence를 0으로 둔다.
reason은 판단 근거 한 문장. 리뷰에 없는 사실은 지어내지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"items":[{"id":"","sentiment":"","category":"","request":"","confidence":0.0,"reason":""}]}
```
- 입력: `{ reviews: [{ id, rating, product, text }] }` — 작성자 이름 없음, 본문 연락처 가림, 40건 · 건당 300자까지 · 최대 1,500토큰
- 화면 검사: `normalizeAi()` — 없는 id · 목록 밖 값 · 0~1 밖 확신도는 버림, 절반 넘게 틀리면 전부 버림. `mergeAi()` — 규칙이 잡은 반어 · 어긋남 · 안전 신호는 유지

## 3. 왜 이렇게 썼나

- **반어를 지시문에 직접 적었다.** 예시 없이 “감정 분류”라고만 하면 말투를 따라 긍정으로 기운다.
- **애매하면 확신도를 낮추라고 했다.** AI가 애매함을 숫자로 말해 줘야 화면이 사람에게 넘길 수 있다.
- **안전은 판단하지 말라고 했다.** 다침 · 발열은 마케팅팀이나 AI가 정할 문제가 아니다.
- **주제는 목록에서만.** 상품팀이 쓰는 말과 같아야 집계가 묶인다.

## 4. 실패했던 이전 버전

```
리뷰를 긍정/부정으로 분류하고 주제를 붙여 줘.
```
- 결과: “배송 진짜 빠르네요^^ 열흘 만에 왔어요”가 긍정, 주제는 ‘빠른 배송’. 주제 이름이 매번 달라(‘배송 속도’, ‘배송’, ‘택배’) 묶이지 않았고, 확신도가 없어 애매한 리뷰를 골라낼 방법이 없었다.
- 고친 점: 반어 처리 문장 추가, 주제를 목록으로 고정, confidence와 0.6 기준, 안전 관련은 판단하지 않기, 화면에서 규칙 신호와 합치기.
