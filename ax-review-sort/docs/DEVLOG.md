## 7주차 1회 — 무엇으로 나눌지부터

**한 일**
- 지난달 리뷰 800건을 관리자 화면에서 내려받았다. 다 읽는 데 이틀이 걸렸다는 걸 먼저 적어 두었다.
- 상품팀이 실제로 쓰는 말로 주제 7가지를 정했다: 배송 · 품질·불량 · 사이즈·규격 · 포장 · 설명·조립 · 가격 · 기타.
- 칭찬 말 · 불만 말 개수와 별점으로 감정을 정하는 규칙 분류기를 만들었다.

**막힌 것 → 해결**
- “뚜껑이 새요”가 품질로 안 잡힘 → 띄어쓰기 · 어미가 다른 표현(새요 · 새서 · 샙니다 · 새네)을 모두 넣고 테스트로 고정.

## 7주차 2회 — 반어적 칭찬

**한 일**
- `reviewsort.classify`로 Claude가 리뷰 여러 건을 한 번에 분류하게 했다. 규칙 결과가 먼저 나오고 Claude 결과가 오면 덮어쓴다.
- 결과를 표본 50건으로 맞춰 보니 별점 5에 “배송 진짜 빠르네요^^ 열흘 만에 왔어요”가 **긍정**으로 들어가 있었다.

**막힌 것 → 해결**
- 반어적 칭찬을 긍정으로 분류 → 애매한 리뷰는 ‘사람 확인’으로 따로 모음. 반어 신호(`^^`, `기가 막히`, `덕분에` + 불만 말), 별점과 글이 어긋남, 확신도 60% 미만이면 자동으로 끝내지 않는다. Claude가 확신해도 규칙이 잡은 신호는 지우지 않는다(`mergeAi`).
- 같은 기준으로 “탄 냄새가 나고 뜨거워졌어요” 같은 안전 관련 리뷰도 따로 뺐다. AI는 판단하지 않고 품질안전 담당에게 넘긴다.

## 7주차 3회 — 상품팀이 받아 볼 것

**한 일**
- 개선 요청을 상품 · 주제로 묶어 많은 순 상위 5개. 사람 확인이 남은 리뷰는 넣지 않고 “미반영 n건”을 같이 적는다.
- 상품팀 전달 글 복사.
- 로직을 `logic.js`로 분리하고 테스트 13개.

**막힌 것 → 해결**
- 전달 글 대표 문장에 고객 전화번호가 그대로 따라 나옴 → 본문의 전화번호 · 이메일 · 주문번호를 가리는 `maskPII`를 화면 · AI 입력 · 전달 글에 모두 거치게 하고, 작성자 이름은 아예 보내지 않음.

**결과 (1기 목표치)**
- 분류 월 2일 → 1시간
- 개선 요청 상위 5개 상품팀 전달
