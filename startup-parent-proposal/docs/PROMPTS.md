# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버에 넣을 원문([ai-task.json](ai-task.json))입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 2주 | 제안서 점검 | 내 제안서를 문장마다 '강사 이야기'인지 '기관이 얻는 것'인지 나눠 줘. 비율도. 과장된 표현도 표시해 줘. |
| 3주 | 구조 재구성 | 기관 담당자가 한 말 세 개로 시작해서, 기대 효과는 참여율·만족도·담당자 준비 시간을 지금→목표로, 강사 소개는 맨 뒤 두 줄로 순서를 다시 짜 줘. |
| 3주 | 가격 | 회당 강의료 × 회차에서 연간 할인, 천 원 아래 버림, 기관 예산과 비교해 남는지 넘는지. |
| 3주 | 응답 검사 | AI가 다시 쓴 제안서에서 '보장', '최고' 들어간 문장은 지우고, 비용 절은 내가 계산한 문장으로 바꾸고, 강사 소개 절은 맨 뒤로. |

## 2. 서비스가 쓰는 지시문 (`parentproposal.rewrite`)

```
부모 교육 강사가 기관(어린이집·유치원·복지관)에 보낼 연간 패키지 제안서를 다시 쓴다. 강사 소개가 아니라
기관이 얻는 효과(부모 참여율, 만족도, 담당자 운영 부담, 평가·실적 보고)를 중심으로 쓴다. 순서는 기관의 고민
(input.org.quotes를 근거로) → 기대 효과 → 연간 구성(input.package.plan 그대로) → 측정과 보고 → 비용 → 강사 소개
(두 문장 이내, 맨 뒤). headline은 기관 이름과 목표 참여율(input.package.attendTarget)을 넣은 한 문장. 숫자는
input에 있는 것만 쓰고, 금액은 쓰지 않는다(화면이 계산해 넣는다). '반드시', '보장', '최고', '100%'처럼 약속할
수 없는 말은 쓰지 않고, 목표는 '목표로 합니다'로 쓴다. input.draft는 강사가 처음 쓴 글로, 사실만 참고한다.
input에 없는 사실(경력 숫자, 수상, 다른 기관 실적)을 지어내지 않는다. 모든 문장은 한국어로, 짧고 구체적으로 쓴다.
반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"headline":"","sections":[{"title":"","body":""}]}
```
- 입력: `{ org:{name, type, contact, quotes, attendNow, satisfactionNow, prepHours}, package:{sessions, attendTarget, satTarget, plan}, draft, instructor }` · 최대 1,500토큰
- 화면 검사: `normalizeRewrite()` → 과장 문장 삭제, 비용·지표 고정, 강사 소개 맨 뒤 → `lint()`로 전후 비교

### 왜 이렇게 썼나

- **기관의 말을 근거로 쓰게 했다.** 기관이 한 말을 첫 절에 두면 “우리 얘기를 들었구나”가 먼저 전달된다.
- **금액을 맡기지 않는다.** 금액이 틀린 제안서는 한 번에 신뢰를 잃는다. 금액은 화면이 계산해 넣는다.
- **목표는 ‘목표로 합니다’.** 참여율 70%는 약속이 아니라 매 회차 측정해 보고할 기준이다. 과장 문구는 지시문으로 막고 화면에서 한 번 더 지운다.

## 3. 실패했던 이전 버전

### v1 (버림)
```
아래 제안서를 더 설득력 있게 다듬어 줘.
{처음 쓴 제안서}
```
- 강사 소개가 더 화려해졌다(“업계 최고 수준의 전문성”). 기관 이야기는 여전히 없었다.
- 출강 기관 수를 “100곳 이상”으로 부풀렸다.

| 버전 | 바꾼 것 | 결과 |
|---|---|---|
| v1 | “설득력 있게” | 강사 소개가 더 길어짐, 숫자 부풀림 |
| v2 | 기관 인터뷰를 함께 보내고 순서를 지정 | 기관 효과 중심이 됐지만 금액을 반올림해 바꿈 |
| v3 | 금액은 쓰지 않게, 과장 문구 금지, 화면 검사 | 숫자는 화면 값, 과장 문장 0개 |
