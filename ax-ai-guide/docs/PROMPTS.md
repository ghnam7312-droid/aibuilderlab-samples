# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다. 팀 공용 프롬프트 12개 원문은 `logic.js`의 `PROMPTS`에 있습니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 8주 | 사용 조사 정리 | 팀원 6명이 AI에 보낸 요청 40개야. 업무 종류별로 묶고, 고객 정보나 내부 숫자가 들어간 요청을 따로 표시해 줘. |
| 8주 | 금지 목록 | 마케팅팀이 AI에 넣으면 안 되는 정보를 '막을 것'과 '조심할 것'으로 나눠서, 항목마다 한 줄 예시를 붙여 줘. |
| 8주 | 공용 프롬프트 | 이 리뷰 답글 요청을 역할·목적·대상·형식·분량·조건이 다 들어간 공용 프롬프트로 바꿔 줘. 바뀌는 부분은 {{ }} 빈칸으로. |
| 8주 | 검수표 | AI 결과물을 내보내기 전에 확인할 항목을 8개 이내로. 기계로 확인할 수 있는 것과 사람이 봐야 하는 것을 나눠 줘. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### aiguide.review
```
팀원이 쓰려는 업무용 프롬프트를 점검한다. input.parts(역할, 목적, 대상, 출력 형식, 분량, 조건·금지)를 기준으로
score는 0~100 정수, missing은 빠진 요소 이름. improved는 원래 목적을 바꾸지 않고 빠진 요소를 채운 프롬프트 전문.
[고객], [전화번호] 같은 자리표시는 그대로 두고 실제 이름·연락처·주소를 만들어 넣지 않는다. 원문에 없는 상품 정보나
숫자는 지어내지 않고 '[확인 필요]'로 둔다. 법률·의료·안전 판단을 요청하는 프롬프트라면 improved 끝에
'최종 판단은 담당자가 확인한다'를 붙인다. 모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"score":0,"missing":[""],"improved":""}
```
- 입력: `{ prompt, parts }` — `prompt`는 `mask()`를 거친 프롬프트(4,000자까지) · 최대 900토큰
- 화면 검사: `normalizeReview()` — 점수 0~100, improved 필수, improved를 다시 `scan()` 해서 금지 정보가 있으면 버림

## 3. 왜 이렇게 썼나

- **점검 기준을 input으로 같이 보낸다.** 화면의 규칙 점검과 같은 6요소로 봐야 점수가 서로 비교된다.
- **자리표시를 지키라고 적었다.** 가린 `[고객]`을 그럴듯한 이름으로 채워 돌려주면 가린 의미가 없다.
- **모르는 건 `[확인 필요]`.** 고친 프롬프트에 없는 장점이나 숫자가 들어가면 그대로 광고 문구가 된다.
- **법률 · 안전은 담당자.** 가이드 첫 장의 ‘AI에 판단을 맡기지 않는 일’과 같은 원칙.

## 4. 실패했던 이전 버전

```
이 프롬프트를 더 좋게 고쳐 줘.
```
- 결과: 매번 세 배 길이로 늘어났고, 원래 목적(리뷰 답글)이 ‘브랜드 스토리 작성’으로 바뀌기도 했다. 가린 자리표시 `[고객]`을 ‘김민수 고객님’으로 채워 돌려준 적이 있었다.
- 고친 점: 6요소 기준과 JSON 형식 지정, “원래 목적을 바꾸지 않고”, 자리표시 유지, 화면에서 금지 정보 재검사.
