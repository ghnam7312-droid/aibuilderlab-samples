# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 담아 서버 작업 목록에 넣는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 1일 | 항목 정리 | 팀장이 4.5점 이상 준 상담 응답 20개를 붙일게. 공통으로 지킨 점을 10개 이하 항목으로 묶고, 항목마다 왜 필요한지 한 줄로 써 줘. 응답에 없는 기준은 넣지 마. |
| 2일 | 정책 대조 | 답변에서 반품·교환 기한, 환불 기간, 배송비 숫자를 찾아 회사 정책(7일, 영업일 3~5일, 왕복 6,000원, 파손은 무료)과 다르면 그 문장과 정책을 돌려줘. 수거 일정 같은 다른 날짜는 반품 기한으로 보지 마. |
| 2일 | 실제 예시 | 항목마다 예시를 고르는 함수: source가 real이고 평가 4.5점 이상이고 정책과 다르지 않은 응답 중, 그 항목을 지킨 문장을 점수 높은 순으로. AI가 만든 답안은 절대 고르지 마. |
| 3일 | 응답 검사 | Claude 점검 결과에서 모르는 항목 id, pass가 불리언이 아닌 것은 버리고, evidence가 답변에 없는 문장이면 지워. 정책·약속·쉬운 말 항목은 규칙 결과를 그대로 둬. |

## 2. 서비스가 쓰는 지시문 (`cschecklist.review`)

```
신입 상담원이 쓴 고객 응대 답변(input.answer)을 상담 품질 체크리스트 항목(input.items)마다 점검한다.
고객 문의는 input.inquiry, 회사 정책은 input.policy.
items에는 input.items의 id마다 하나씩, 그 항목을 지켰으면 pass를 true로 둔다.
evidence는 판단 근거가 된 문장을 답변에서 글자 그대로 옮기고, 해당 문장이 없으면 빈 문자열로 둔다.
tip은 지키지 못한 항목에 대해 고칠 방향 한 문장(60자 이내).
모범 답안이나 고쳐 쓴 전체 답변은 쓰지 않는다.
정책 판단은 input.policy에 있는 내용만 기준으로 하고, 답변에 없는 말을 근거로 지어내지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"items":[{"id":"","pass":true,"evidence":"","tip":""}]}
```
- 입력: `{ inquiry, answer, items: [{ id, label, why }], policy: ["반품·교환 신청: …"] }` · 최대 1,200토큰
- 화면 검사: `normalizeReview()` → `mergeReview()` (정책·약속·쉬운 말, 해당 없음은 규칙 그대로)

### 왜 이렇게 썼나
- **판단만 받고 모범 답안은 받지 않는다** — 예시는 실제 우수 응답에서만 나온다. 지시문에서 막고, 응답에 다른 칸이 와도 화면이 버린다.
- **근거는 글자 그대로** — 신입에게 “이 문장 때문에 통과”를 보여 주려면 답변 속 문장이어야 한다. 화면이 답변에 실제로 있는지 확인한다.
- **정책은 input.policy만** — Claude가 알고 있는 일반적인 쇼핑몰 정책으로 판단하지 않게.

## 3. 실패했던 이전 버전

```
상담 품질 체크리스트 10항목마다 신입 교육용 모범 답안 예시를 하나씩 써 줘. 친절하고 고객이 만족할 수 있게.
```
- 그럴듯한 문장이 나왔지만 **회사 정책과 달랐다**. “반품은 받으신 날부터 14일 이내 언제든 가능하며, 배송비는 무료로 처리해 드립니다”처럼 기한과 배송비가 틀렸고, 확정되지 않은 약속도 섞였다.
- 그래서 Claude에게 예시를 만들게 하는 대신 **우리 팀의 실제 우수 응답에서 예시를 고르고**, Claude는 신입 답변을 점검하는 일만 하게 바꿨다.
