# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 1일 | 대상 고르기 | 개정 항목마다 안내 대상 조건(시급제 직원 있음, 교대·연장 근무 있음, 전체)을 두고, 고객사 정보로 대상인지와 이유를 돌려주는 함수를 만들어 줘. |
| 2일 | 틀 초안 | 개정 항목과 고객사로 안내문 틀을 만들어 줘. 시행일은 '2027년 1월 1일(금)'처럼, 변경 전·후 금액, 확인할 일 2개, 마지막 줄에 근거 링크. |
| 3일 | 대조 | 안내문 안의 날짜를 여러 표기로 모두 찾아서 고시 시행일과 다르면 오류, 고시에 없는 금액도 오류, 링크가 없으면 오류로 돌려줘. 사람이 대조 확인을 안 했으면 보낼 수 없게. |
| 3일 | 내보내기 | 발송 대기 목록을 텍스트로 내보내 줘. 담당자 이름은 가리고, 고객사마다 시행일 대조 기록과 근거 링크를 적어 줘. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### labornotice.draft
```
노무사 사무소(input.office)가 고객사에 보낼 법령 개정 안내문 초안을 쓴다. input.amendment는 개정 항목, input.client는 고객사의 업종·인원·시급제 직원 수·교대/연장 근무 여부·담당 직함, input.link는 공식 고시 링크다. 시행일은 input.amendment.effective를 'YYYY년 M월 D일'로 그대로 쓰고 다른 날짜는 쓰지 않는다. 금액은 input.amendment의 before·after만 쓰고 새 숫자를 만들지 않는다. 본문 끝에 '근거: 공식 고시 '와 input.link를 그대로 붙인다. 고객사 상황에 맞춰 확인할 일 2~3개를 쓴다. 위반·과태료 같은 법적 판단은 쓰지 않고, 조정이 필요한지는 사무소 상담에서 함께 확인한다고 쓴다. input에 없는 사실은 지어내지 않는다. checks는 발송 전에 사람이 고시 원문과 대조할 점. 모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"subject":"","body":"","checks":[""]}
```
- 입력: `{ amendment, client(담당자 이름 없이 직함만), link, office }` · 최대 900토큰
- 화면 검사: `normalizeDraft()` → `ensureLink()` → `checkDraft()`

### 왜 이렇게 썼나
- **시행일을 ‘그대로’ 쓰게** — 날짜를 계산하거나 다시 쓰게 두면 연도가 바뀌는 일이 생겼다. 받은 값을 형식만 바꿔 쓰게 하고, 다른 날짜는 아예 쓰지 말라고 했다.
- **링크는 받은 것만** — AI가 그럴듯한 고시 주소를 만들 수 있어서, 링크는 사람이 넣은 값만 쓴다. 빠지면 화면이 붙인다.
- **판단은 상담으로** — 안내문은 사실(무엇이 언제 바뀌는지)과 확인할 일까지만. 조정이 필요한지는 노무사가 상담에서 본다.

## 3. 실패했던 이전 버전

```
다음 법령 개정 내용을 고객사에 알리는 친절한 안내문을 써 줘. 개정 내용: {개정 설명 글}
출력 형식: {"subject":"","body":""}
```
- 개정 설명 글 속 공포일과 시행일을 섞어, 시행일이 다른 날짜로 적힌 초안이 나왔다.
- “미지급 시 과태료가 부과됩니다”처럼 사무소가 검토하지 않은 단정 문장이 들어갔다.
- 근거 링크가 없어 받는 쪽이 확인할 방법이 없었다.
- → 시행일·금액·링크를 따로 넣고 그대로 쓰게 했으며, 화면에서 대조해 다르면 막도록 바꿨다.
