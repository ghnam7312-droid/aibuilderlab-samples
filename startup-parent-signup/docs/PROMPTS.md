# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버에 넣을 원문([ai-task.json](ai-task.json))입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 4주 | 메모 정리 | 전화·문자 메모를 한 줄에 한 사람으로 읽어서 이름, 휴대폰 번호, 강의(기관 이름으로 찾기), 아이 나이를 뽑아 줘. 못 읽은 줄은 버리지 말고 이유와 함께 따로. |
| 5주 | 중복 확인 | 같은 사람이 두 번 신청해. 번호 모양이 달라도(띄어쓰기, 점, +82) 같은 번호로 보고, 번호+강의가 같으면 한 명으로 합쳐. 순서는 먼저 신청한 쪽, 빈 값만 채우고. |
| 5주 | 번호 가리기 | AI에 보내기 전에 메모 속 번호를 [전화1], [전화2]로 바꾸고, 돌아온 표시를 원래 번호로 되돌리는 함수. 표에 없는 표시는 버려. |
| 5주 | 안내 문자 | {이름} {강의} {일시} 칸을 채우는 문자 템플릿. 모르는 칸이 있으면 목록으로 돌려줘. |

## 2. 서비스가 쓰는 지시문 (`parentsignup.parse`)

```
부모 교육 강의 신청을 전화·문자로 받아 적은 메모(input.memo)를 신청 항목으로 정리한다. 한 사람이 한 항목이다.
name은 메모에 적힌 이름 그대로(어머님·아버님·님 같은 호칭은 뺀다), phone은 메모에 있는 [전화1] 같은 표시를
그대로 옮긴다(숫자로 바꾸지 않는다). session은 input.sessions 중 메모가 가리키는 강의의 id. kids는 아이 나이
표현(예: 4세, 30개월), note는 부모가 물어본 내용 한 문장, line은 메모의 몇 번째 줄인지. 이름·전화 표시·강의 중
하나라도 메모에 없으면 그 사람은 넣지 않는다. 같은 사람이 두 번 나와도 합치지 말고 둘 다 넣는다(중복 확인은
화면이 한다). input에 없는 사실을 지어내지 않는다. 모든 문장은 한국어로, 짧고 구체적으로 쓴다.
반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"entries":[{"name":"","phone":"[전화1]","session":"s1","kids":"","note":"","line":1}]}
```
- 입력: `{ memo(번호 가림, 6,000자까지), sessions:[{id, org, title}] }` · 최대 1,200토큰
- 화면 검사: `normalizeParse()` — 번호표에 없는 표시·없는 강의 id는 버림 → 미리 보기 → `merge()`/`dedupe()`

### 왜 이렇게 썼나

- **번호는 표시 그대로 옮기게 했다.** Claude는 번호를 보지 못한다. 표시만 옮기면 번호를 잘못 옮겨 적을 일도 없다.
- **합치지 말라고 했다.** 중복 판단은 규칙이 정확하고 테스트할 수 있다. Claude가 합치면 왜 합쳤는지 확인할 수 없다.
- **없으면 넣지 않는다.** “번호는 못 받음” 줄에 Claude가 이름을 만들어 넣던 문제를 막고, 그런 줄은 화면이 ‘확인 필요’로 남긴다.

## 3. 실패했던 이전 버전

### v1 (버림)
```
아래 신청 메모를 정리해서 중복은 빼고 명단으로 만들어 줘.
{메모 원문}
```
- 전화번호가 그대로 AI로 나갔다(개인정보).
- ‘김하은’과 ‘하은 어머님’을 다른 사람으로, 번호가 다른 두 ‘박서윤’을 한 사람으로 합쳤다. 기준을 알 수 없었다.
- 번호를 못 받은 줄에 `010-0000-0000`을 채워 넣었다.

| 버전 | 바꾼 것 | 결과 |
|---|---|---|
| v1 | 정리 + 중복 제거를 한 번에 | 번호 노출, 기준 없는 합치기, 지어낸 번호 |
| v2 | 번호를 `[전화n]`으로 가림, 합치기는 화면 규칙 | 노출·합치기 해결, 번호 없는 줄에 사람을 만들어 넣음 |
| v3 | “하나라도 없으면 넣지 않는다” + 번호표 검사 | 확인이 필요한 줄만 사람에게 남음 |
