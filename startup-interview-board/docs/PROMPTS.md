# 들어보니 · AI 활용 기록

> 1기 목표 모델 예시입니다. 개발하며 쓴 프롬프트(가상의 창업자 기준)와, 서비스가 실행 중에 Claude에게 보내는 실제 지시문을 함께 적었습니다.

## 1. 서비스 안에서 Claude가 하는 일

| 작업 | 언제 | 받는 것 | 사람이 하는 일 |
|---|---|---|---|
| `interview.analyze` | 인터뷰를 붙이거나 고칠 때, 카드의 ‘Claude로 읽기’ | 핵심어 3~5개, 핵심 문장(메모 안에서 그대로), 가설별 입장과 이유 | 점선 제안을 눌러 **확정** |
| `interview.question` | 질문 점검기에 유도 질문을 적고 0.9초 멈추면 | 유도 여부, 이유, 고쳐 쓴 질문 | ‘이 질문으로 바꾸기’ |

**AI는 제안만 합니다.** 가설 도장은 사람이 확정한 근거로만 바뀝니다. Claude에 연결할 수 없으면 기록된 숫자(리포트 시간·낼 금액)로 규칙 제안을 만들고, 질문은 규칙으로 고쳐 씁니다.

## 2. 실제 지시문 (서버)

```text
[interview.analyze]
고객 인터뷰 메모 한 건을 분석한다. keywords는 3~5개 핵심어.
quote는 메모 안의 문장 중 가장 의미 있는 한 문장을 그대로.
evidence는 input.hypotheses 각각에 대해 stance(지지, 반증, 무관)와 근거 한 문장.
메모에 없는 사실은 만들지 않는다.
출력 형식: {"keywords":[""],"quote":"","evidence":[{"id":"H1","stance":"","why":""}]}

[interview.question]
고객 인터뷰 질문 하나를 점검한다. 답을 유도하거나(좋을까요, 하시겠어요, 원하세요),
미래 가정을 묻거나, 두 가지를 한꺼번에 묻는지 본다.
leading은 true/false, reason은 한 문장, rewrite는 '지난달 실제로 한 행동'을 묻는 질문으로 고쳐 쓴 것.
출력 형식: {"leading":false,"reason":"","rewrite":""}
```

(공통: 모든 문장은 한국어로, 짧고 구체적으로. 반드시 JSON 하나만.)

### 응답 검사
- `normalizeAnalyze` — 메모에 없는 인용은 버림, 입장은 지지/반증/무관만 받아 y/n/x로, 없는 가설 id는 버림, 16자 넘는 핵심어는 버림
- `normalizeQuestion` — `leading`이 true/false가 아니거나 이유가 없으면 버림 → 규칙 고쳐 쓰기(`ruleRewrite`)

## 3. 만들면서 쓴 프롬프트 (주차별 대표)

| 주차 | 프롬프트 | 바뀐 것 |
|---|---|---|
| 1 | "원장 인터뷰 질문지. 미래 의향 대신 지난달 실제 행동과 시간·돈" | 질문지 v1 |
| 2 | "‘쓰시겠어요?’ 같은 유도 질문을 찾는 규칙과 고쳐 쓰는 예시 4쌍" | 질문 점검기 · 바꾼 질문 4쌍 |
| 2 | "자동 판단은 제안으로만, 사람이 확정해야 세는 태그 UI" | 점선 제안 → 확정 |
| 3 | "Claude가 인용을 지어내지 못하게 막는 방법" | 메모 대조 검사 |
| 3 | "가격 응답을 구간으로 나눠 결정 근거를 보여 주는 화면" | 가격 응답 · 리포트 |
