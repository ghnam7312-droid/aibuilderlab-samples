# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버에 넣을 원문([ai-task.json](ai-task.json))입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 1주 | 돌아보기 | 이 인터뷰 질문지에서 듣는 사람이 ‘네’라고 하기 쉬운 질문을 골라 주고, 지난 행동을 묻는 질문으로 바꿔 줘. |
| 1주 | 검사기 | 질문을 미래 가정, 동의 유도, 가격 직접 묻기, 지난 행동, 보통으로 나누는 규칙을 만들어 줘. 바꿀 안은 주제(가격·숙제·앱·수업)에 맞게. |
| 2주 | 실험 설계 | 12명에게 가격 3안을 한 사람당 하나만 보여 주는 배정표와, 예약금으로 결제 의사를 확인하는 마무리 질문을 만들어 줘. |
| 2주 | 집계 | 선결제만 결제로 세서 안별 결제율과 100명당 기대 매출을 계산하고, 관심까지 셀 때와 비교해 줘. |

## 2. 서비스가 쓰는 지시문

### pricetest.questions
```
고객 인터뷰 질문 목록(input.questions)을 검사한다. 인터뷰 목표는 input.goal.
items는 질문 순서와 개수 그대로 하나씩 만든다.
kind는 '미래 가정'(앞으로 쓸지·살지 묻기), '동의 유도'(답을 정해 둔 질문),
'가격 직접 묻기'(얼마면 내겠는지 묻기), '지난 행동'(이미 한 일을 묻기), '보통' 중 하나.
leading은 앞의 세 가지면 true. reason은 왜 그런지 한 문장.
rewrite는 같은 주제를 '지난번에 실제로 한 일'(언제, 무엇을, 얼마를, 왜 그만뒀는지)로 묻는 질문 한 개이며,
지난 행동 질문이면 빈 문자열. rewrite도 미래를 가정하거나 답을 유도하면 안 된다.
질문에 없는 서비스 기능이나 가격을 지어내지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"items":[{"leading":true,"kind":"","reason":"","rewrite":""}]}
```
- 입력: `{ goal, questions }` · 최대 1,200토큰
- 화면 검사: `normalizeCheck()` — 개수가 질문 수와 같아야 하고 `leading`은 불리언. 바꾼 질문을 규칙으로 다시 분류해 또 유도형이면 규칙의 안으로(`byRule` 표시).

## 3. 왜 이렇게 썼나

- **kind를 다섯 개로 고정** — 화면 색과 개수 세기가 이 값에 달려 있다. 모르는 값이 오면 규칙으로 다시 분류한다.
- **순서와 개수 그대로** — 질문과 결과를 번호로 맞추기 때문. 하나라도 빠지면 전체를 버린다.
- **rewrite도 검사** — 바꾼 질문이 ‘매일 하시겠어요?’처럼 또 미래를 물으면 의미가 없다.
- **가격은 AI에게 맡기지 않는다** — 결정은 실제 선결제 숫자로만 계산한다.

## 4. 실패했던 이전 버전

```
이 인터뷰 질문들을 더 좋게 고쳐 줘.
```
- 결과: 문장만 부드럽게 다듬어 왔고 ‘이런 서비스가 있다면 이용해 보실 의향이 있으신가요?’처럼 여전히 미래를 묻는 질문이 많았다.
- 무엇이 왜 문제인지 설명이 없어 다음 질문지에서도 같은 실수를 했다.
- → 분류 기준(다섯 가지)과 ‘지난번에 실제로 한 일’이라는 바꾸는 방향을 명시하고, 바꾼 질문도 다시 검사하게 했다.
