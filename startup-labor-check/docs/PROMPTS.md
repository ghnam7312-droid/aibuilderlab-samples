# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 전반 | 인터뷰 질문 | 소상공인 사장님께 노무 점검 경험을 묻는 인터뷰 질문 8개를 써 줘. '쓰시겠어요?' 같은 유도 질문 말고, 지난달 실제로 한 일을 묻는 질문으로. |
| 중반 | 줄이기 | 체크 항목 40개를 인터뷰 언급 수, 상담에서 문제가 된 빈도, 사장님이 바로 답할 수 있는지, 답하는 데 드는 시간으로 점수를 매겨 12개만 골라 줘. 한 영역에서 2개까지만. |
| 중반 | 결과 문구 | 진단에서 '아니오·모름'이 나온 항목을 위반처럼 보이지 않게, 상담에서 함께 확인할 항목으로 보여 주는 문구를 써 줘. |
| 후반 | 가격 | 체크만 / 체크 + 분기 상담 / 체크 + 서류 대행 세 안을 인터뷰 응답 수와 계약 수로 비교하는 표를 만들어 줘. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### laborcheck.plain
```
소상공인 노무 진단표 항목(input.items: id, question은 노무사 표현, draft는 초안 질문)을 사장님이 바로 예/아니오로 답할 수 있는 쉬운 질문으로 다듬는다. 한 항목에 한 질문, 40자 안팎, '~나요?'로 끝낸다. 법률 용어는 일상어로 바꾸되 뜻을 바꾸지 않는다. 위반·과태료·의무 같은 판단 표현은 쓰지 않는다. input에 없는 항목이나 사실은 지어내지 않고, id는 받은 그대로 쓴다. 모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"items":[{"id":"","plain":""}]}
```
- 입력: `{ items: [{ id, question, draft }] }` (고른 항목만) · 최대 1200토큰
- 화면 검사: `normalizePlain()` — 아는 id, 60자 이하, 질문형, 판단 표현 없음만 받는다

### 왜 이렇게 썼나
- **예/아니오로 답할 수 있게** — 인터뷰에서 사장님이 멈춘 곳은 ‘무슨 뜻인지 모르는 질문’과 ‘서류를 찾아야 하는 질문’이었다.
- **draft를 함께 보낸다** — 사람이 먼저 쓴 쉬운 말을 기준으로 다듬게 하면 뜻이 덜 바뀐다.
- **판단 표현 금지** — 질문에 “위반인가요?”가 들어가면 진단이 판정처럼 읽힌다.

## 3. 실패했던 이전 버전

```
소상공인이 꼭 점검해야 할 노무 항목을 빠짐없이 체크리스트로 만들어 줘.
```
- 40개가 넘는 항목이 나왔고, 노무사 기준으로는 맞지만 사장님은 끝까지 답하지 못했다(인터뷰 9명 중 0명).
- 항목마다 “위반 시 과태료” 같은 문장이 붙어 겁을 주는 표가 됐다.
- → AI에게 항목을 고르게 하지 않고, 사람이 점수로 12개를 고른 뒤 AI는 말만 다듬게 바꿨다.
