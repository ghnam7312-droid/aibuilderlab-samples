# 열두칸

> 소상공인 노무 진단 상품을 기획하는 판. 후보 항목 40개 중 **사장님이 끝까지 답할 핵심 12개**를 고르고, 사장님 화면 미리보기와 가격 실험으로 **월 정기 진단 상품**을 구성한다

> **알림** AI 빌더랩 스타트업 트랙 **1기 목표 모델(가상의 수강생 ‘노무한눈’)** 의 예시 프로젝트입니다. 인터뷰 수치·가격은 가상의 샘플 값이고, 결과 숫자는 1기 목표치입니다. 진단 결과는 위반 판정이 아니라 노무사 상담에서 확인할 목록입니다.

## 문제 → 해결

| 문제 | 해결 |
|---|---|
| 사장님들은 문제가 터진 뒤에야 찾아왔다 | 미리 점검하는 **월 정기 진단 상품**을 기획 |
| 체크 항목이 40개라 아무도 끝까지 안 했다 | 점수(인터뷰 언급·상담 빈도·바로 답할 수 있는지·답하는 시간)로 **핵심 12개**만, 한 영역 최대 2개 |
| 몇 개까지 괜찮은지 감으로 정했다 | 항목 수·예상 시간·서류 확인 항목·끝까지 답할 사람(인터뷰 추정)을 바로 보여 주고 12개를 넘으면 막는다 |
| ‘아니오’가 위반처럼 보일까 걱정 | 진단은 판정하지 않는다. ‘아니오·모름’은 **노무사 상담에서 확인할 항목**이 된다 |
| 얼마를 받아야 할지 몰랐다 | 실험가 3안과 인터뷰 응답 → 결과(목표치) **사장님 9명 인터뷰, 3곳 계약** |

## 주요 기능

- **후보 항목 40개** — 8개 영역 × 5개, 점수·인터뷰 언급 수·‘서류 확인’ 표시. 영역별 거르기, 체크로 넣고 빼기.
- **핵심 12개 추천 / 40개 전부(처음 버전)** — 두 버전을 오가며 검사 결과 비교, 되돌리기.
- **진단표 검사** — 항목 수, 예상 분, 다루는 영역, 끝까지 답할 사장님(9명 중 추정)과 막음·주의·참고.
- **사장님 화면 미리보기** — 예/아니오/모름으로 답해 보면 상담에서 확인할 항목이 모인다. 인쇄용 진단표.
- **가격 실험** — 실험가 3안(샘플), ‘쓰겠다’ 응답·계약 수·예상 월 매출. 고른 안으로 상품 기획안(마크다운) 복사.

## AI는 이렇게 동작합니다

| 상황 | 동작 | 화면 표시 |
|---|---|---|
| Claude 연결됨 | `laborcheck.plain` → `normalizePlain` 검사(아는 id, 60자 이하, 질문형, 판단 표현 없음) → 통과한 질문만 바꿈 | `Claude로 다듬음 · 1.8초` |
| AI 키 없음 · 한도 초과 · 알 수 없는 작업 · 네트워크 오류 | 미리 써 둔 쉬운 말 그대로 | `규칙 기반 · (이유)` |
| 응답 형식이 틀림 · 전부 걸러짐 | 버리고 미리 써 둔 말 유지 | `규칙 기반 · 응답 형식이 맞지 않음` |

항목 고르기(추천)는 AI가 아니라 점수 규칙이 합니다. 기획 판단은 사람이 하고, AI는 질문을 사장님 말로 다듬는 일만 맡습니다. 지시문 원문은 [docs/PROMPTS.md](docs/PROMPTS.md), 서버 작업 정의는 [docs/ai-task.json](docs/ai-task.json).
