# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 이 서비스가 서버에 등록하는 원문([ai-task.json](ai-task.json))입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 3주 | 표 읽기 | 시트에서 복사한 표를 붙여 넣으면 탭이든 쉼표든 칸으로 나눠 줘. 첫 줄이 머리글이면 건너뛰고, 읽지 못한 줄은 몇 번째 줄인지와 이유를 돌려줘. |
| 4주 | 사번 기준 | 신청과 출석을 이름 말고 사번으로 맞춰 줘. 사번은 소문자·하이픈·공백이 섞여 있어도 같게 보고, 사번이 빈 출석은 같은 이름이 딱 한 명일 때만 연결해. 둘 이상이면 합치지 말고 따로 모아 줘. |
| 4주 | 확인 필요 | 사번 없는 출석 후보 중 그 회차에 이미 출석한 사람은 뒤로 보내고 표시해 줘. 담당자가 고른 연결은 출석 줄 번호 → 사번으로 저장해서 다시 계산할 때 쓰게. |
| 4주 | 검산 | AI가 쓴 보고 문장 속 숫자가 내가 보낸 집계 숫자에 다 있는지 확인하고, 하나라도 없으면 응답을 버리는 함수를 만들어 줘. 회차 번호는 허용. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### trainattend.report
```
사내 교육 출결 집계 숫자로 교육 담당자의 결과 보고 문장을 쓴다. lines는 3문장:
1) 신청 인원·이수 인원·이수율, 2) 회차별 출석 흐름과 가장 적었던 회차,
3) 확인이 필요한 기록(unresolved)·신청 없이 참석(walkIns)·동명이인(homonyms) 중 해당하는 것.
followups는 담당자가 할 후속 조치 최대 3개(각 30자 이내).
숫자는 input에 있는 값만 그대로 쓰고 계산해서 새 숫자를 만들지 않는다.
input에 없는 사실(원인 추정, 개인 이름)을 지어내지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"lines":[""],"followups":[""]}
```
- 입력: `{ course, applied, pass, fail, passPct, walkIns, perSession, unresolved, homonyms, late, byDept }` — 이름·사번 없음 · 최대 500토큰
- 화면 검사: `normalizeReport()` — 문장 2개 이상, 모든 숫자가 입력에 있어야 통과

## 3. 왜 이렇게 썼나

- **숫자는 그대로, 계산 금지** — 보고서는 숫자가 하나만 틀려도 전체를 못 믿게 된다. 계산은 규칙이 하고, AI는 문장만 쓴다. 그래서 검산이 가능하다.
- **이름을 보내지 않는다** — 보고 문장에 개인 이름이 필요 없다. 보내지 않으면 지어낼 수도 없다.
- **원인 추정 금지** — “3회차는 월말이라 적었다” 같은 문장은 그럴듯하지만 근거가 없다. 원인 확인은 후속 조치로 넘긴다.

## 4. 실패했던 이전 버전

```
아래 출석부를 보고 교육 결과 보고서를 써 줘. (출석부 전체 — 이름·사번 포함)
```
- 이름으로 사람을 세서 동명이인 김민준 두 명을 한 명으로 씀(“16명 중 …”).
- 이수율을 스스로 계산하며 반올림이 달라 76%가 75%로 나옴.
- 출석이 적은 회차의 이유를 지어냄.
→ 사람 판단은 사번 규칙으로 먼저 끝내고, AI에는 집계 숫자만 보내도록 바꿨다.
