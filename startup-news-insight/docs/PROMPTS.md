# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 4주 | 지표 | 글별 클릭과 끝까지 읽은 사람 수가 있어. 호마다 열람자가 다르니까 클릭률·완독률·열람자 100명당 끝까지 읽은 사람을 계산해 줘. |
| 4주 | 낚시 의심 | 클릭률은 높은데 완독률이 낮은 글을 찾아 줘. 기준은 클릭률이 중앙값의 1.3배 이상이고 완독률 30% 미만. 클릭률 낮은 글은 빼고. |
| 4주 | 순위 비교 | 클릭 수 순위와 완독 반영 순위를 오갈 때 글마다 몇 칸 움직였는지 ▲▼로 보여 줘. |
| 4주 | 추천 | 주제별 평균 완독 점수로 다음 호 주제 3개를 골라 줘. Claude에게는 원문 말고 계산이 끝난 합계만 보내고, 돌아온 주제가 입력에 없으면 버려. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### `newsinsight.recommend`
```
뉴스레터 주제별 반응 합계(input.topics: 글 수, 평균 클릭률, 평균 완독률, 열람자 100명당 끝까지 읽은 사람 per100, 낚시 의심 글 수 bait, 가장 잘 읽힌 글 bestTitle)를 보고 다음 호에 쓸 주제 3개를 고른다. 클릭률보다 완독률과 per100을 우선한다. topic은 input에 있는 주제 이름 그대로, reason은 근거 한 문장(숫자는 input에 있는 값만), titleIdea는 내용이 드러나는 제목 한 줄(충격·비밀·꿀팁 같은 낚시성 표현 금지). caution은 낚시 의심 글이 많은 주제에 대한 주의 한 문장, 없으면 빈 문자열. input에 없는 사실은 만들지 않는다. 모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"topics":[{"topic":"","reason":"","titleIdea":""}],"caution":""}
```
- 입력: `{ topics: [{ topic, articles, clickRate, readRate, per100, bait, bestTitle }] }` · 최대 600토큰
- 화면 검사: `normalizeRecommend()` — 입력에 있는 주제만, 이유 속 숫자는 입력에 있는 값만, 낚시 표현이 든 제목 아이디어는 비움

## 3. 왜 이렇게 썼나

- **“클릭률보다 완독률과 per100을 우선한다”** — 이 서비스를 만든 이유 그대로. 이 문장이 없으면 Claude도 클릭률이 높은 주제를 먼저 골랐다.
- **합계만 보낸다** — 글 원문이나 구독자 기록을 보내지 않으니 개인정보가 나가지 않고, 숫자를 다시 계산하다 틀릴 일도 줄었다.
- **topic은 input에 있는 이름 그대로** — ‘라스트마일 물류’처럼 이름을 바꿔 오면 표와 연결이 끊겨서.
- **낚시성 표현 금지** — 추천 제목이 다시 낚시로 돌아가면 이 도구를 만든 의미가 없다.

## 4. 실패했던 이전 버전

```
지난 8호 글 목록과 클릭 수야. 반응 좋은 주제를 분석해서 다음 호 주제를 추천해 줘.
```
- 클릭 수만 보고 ‘택배·라스트마일’을 1순위로 추천했다(그 주제의 상위 글 2개가 낚시 의심 글).
- 추천 제목이 ‘모르면 손해 보는 택배 꿀팁 2탄’.
- → 완독률을 함께 넘기고, 완독 우선·낚시 표현 금지·입력 숫자만 쓰기를 넣은 지금 버전으로 바꿨다.
