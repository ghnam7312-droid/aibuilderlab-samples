# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 `docs/ai-task.json`의 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 2주 | 경력 계산 | 이력서에서 `2018.03 - 현재 회사 · 직무` 줄을 읽어 총 경력을 개월로 세 줘. 겹치는 기간은 한 번만, 끝이 시작보다 앞이면 버려. 오늘 날짜는 인자로. |
| 2주 | 주의 신호 | 고민 글에 마음 건강이나 해고·위로금 같은 표현이 있으면 AI가 판단하지 말고 ‘코치가 직접 확인’ 표시만 띄워 줘. |
| 3주 | 리포트 | 상담 메모에서 `→`로 시작하면 할 일, `#`이면 코치 전용으로 빼고 고객용 요약을 만들어 줘. 연락처는 가리고 이름은 성만. |
| 3주 | 권한 | 이력서 파일은 본인과 담당 코치만 열게 하고, 열 때마다 10분짜리 주소를 줘. 주소에 이름이 들어가면 안 돼. 테스트도. |

## 2. 서비스가 쓰는 지시문 (`coachbrief.diagnose`)

```
커리어 코칭 상담 전에 코치가 읽을 사전 진단을 쓴다. input.target은 고객의 희망 직무, input.worry는
고객이 남긴 고민, input.resume은 이름·연락처를 가린 이력서다. summary는 경력과 희망 직무의 거리를
2문장으로. strengths는 이력서의 실제 업무 줄 중 희망 직무로 옮겨 갈 수 있는 경험 최대 3개(이력서
표현을 살려서). gaps는 희망 직무에 필요하지만 이력서에서 보이지 않는 경험 최대 4개. questions는
상담 첫 20분에 물어볼 질문 3~4개, 고민에 나온 걱정을 하나 이상 다룬다. 이력서와 고민에 없는
사실(회사, 숫자, 자격)은 만들지 않는다. 마음 건강, 해고·위로금 같은 노무·법률 문제는 판단하거나
조언하지 않고 언급하지 않는다(코치가 직접 다룬다). 합격 가능성이나 연봉을 예측하지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"summary":"","strengths":[""],"gaps":[""],"questions":[""]}
```
- 입력: `{ target, worry, resume }` — 이름은 ‘고객’, 전화·이메일은 가린 뒤 · 최대 900토큰
- 화면 검사: `normalizeDiagnose()` (요약·질문 없으면 버림) → `mergeDiagnose()` (경력 계산·주의 신호는 규칙 유지)

## 3. 왜 이렇게 썼나

- **이력서 표현을 살려서** — 코치가 상담 중 “이력서에 ‘채용 공고 운영’이라고 쓰셨죠”라고 바로 짚을 수 있게.
- **노무·법률은 언급하지 않는다** — 코치도 판단할 자격이 없는 영역. 화면의 주의 신호가 사람에게 넘긴다.
- **합격 가능성·연봉 예측 금지** — 근거 없는 숫자가 고객 기대를 만든다.

## 4. 실패했던 이전 버전

```
이 고객의 이력서와 고민을 읽고 커리어 컨설팅을 해 줘. 합격 가능성도 알려 줘.
```
- 결과: 긴 줄글 조언, “합격 가능성 70%” 같은 근거 없는 숫자, 권고사직 고객에게 위로금 액수 판단까지 씀. 이력서 원문(이름·전화)을 그대로 보냄.
- 고친 것: 코치가 읽을 진단 JSON으로 좁히고, 없는 사실·예측·노무 판단을 금지, 입력은 가린 뒤 전송.
