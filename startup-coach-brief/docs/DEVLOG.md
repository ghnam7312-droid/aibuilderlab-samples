## 2주차 전반 — 50분이 어디서 새는지부터

**한 일**
- 상담 1건 준비를 재 보니: 이력서 읽고 경력 정리 20분, 희망 직무와 비교 15분, 질문 만들기 10분, 고민 글 다시 읽기 5분.
- 사전 설문(희망 직무 · 고민)과 이력서를 한 화면에 받게 했다.
- `2018.03 - 현재 회사 · 직무` 줄을 읽어 총 경력을 계산.

**막힌 것 → 해결**
- 두 곳을 겹쳐 다닌 기간이 두 번 더해져 경력이 부풀려짐 → 기간을 합쳐 한 번만 세는 `totalMonths()`와 테스트.
- ‘자격·교육’ 아래 줄까지 마지막 직장의 업무로 들어감 → 새 제목 줄이 나오면 경력 읽기를 끝내도록.

## 2주차 후반 — 코치의 점검표를 규칙으로

**한 일**
- HR 담당자 시절 쓰던 직무별 점검표(핵심어 10개)를 그대로 옮겼다. 겹치는 업무 줄 = 강점, 빠진 핵심어 = 채울 부분.
- 고민에 ‘연봉’, ‘나이’가 있으면 그에 맞는 질문을 앞에 둔다.
- 고민 글에 ‘잠을 못 자’, ‘권고사직’, ‘위로금’이 섞여 오는 경우가 있어 주의 신호를 만들었다. 이 부분은 코치가 직접 다루고 전문가를 안내한다.

**막힌 것 → 해결**
- 핵심어 ‘교육’이 ‘교육 일정 운영’ 같은 행정 업무에도 걸림 → 핵심어가 여러 개 겹치는 줄을 먼저 보여 주도록 정렬.
- 대소문자 때문에 `sql`이 `SQL`로 안 잡힘 → 소문자로 맞춰 비교.
- 주의 신호가 고객 목록에 안 보여 놓침 → 고객 칩에 ‘확인할 신호 있음’ 점 표시.

## 3주차 전반 — Claude 진단과 상담 뒤 리포트

**한 일**
- `coachbrief.diagnose`로 요약 · 강점 · 채울 부분 · 질문을 다듬게 했다. 규칙 결과가 먼저 나오고 Claude 결과가 오면 덮어쓴다.
- Claude에게는 이름을 ‘고객’으로 바꾸고 전화·이메일을 가린 뒤 보낸다(`aiInput`).
- 상담 메모 → 고객용 리포트. `→` 줄은 할 일, `#` 줄은 코치 전용으로 빠진다.

**막힌 것 → 해결**
- Claude가 고민 속 ‘권고사직’에 대해 위로금 조언을 씀 → 지시문에서 노무·법률은 언급하지 않게 하고, 주의 신호는 규칙 것을 그대로 쓰게(`mergeDiagnose`).
- 질문이 문자열 하나로 오는 경우 → `normalizeDiagnose`에서 버리고 규칙 유지.

## 3주차 후반 — 이력서는 누구나 열 수 있으면 안 된다

**한 일**
- 점검하다 보니 이력서 파일이 **누구나 열리는 공개 주소**로 저장돼 있었다. 주소에 고객 이름까지 들어 있었다.
- 비공개 저장소로 옮기고, **본인과 담당 코치만** 열 수 있게 권한을 수정(`canOpen`). 열 때마다 10분 뒤 만료되는 주소를 발급(`issueLink`·`verifyLink`), 주소에는 파일 번호만.
- 화면에서 담당 코치 · 본인 · 다른 코치 · 방문자로 열어 보는 시험 상자와 열람 기록(역할만)을 만들었다.
- 로직을 `logic.js`로 분리하고 테스트 12개.

**막힌 것 → 해결**
- 코치에게 발급된 주소를 고객 본인이 그대로 쓰면 열림 → 주소에 받는 사람을 묶어 서명하고, 다른 사람이면 ‘다른 사람에게 발급된 주소’로 거절.

**결과 (1기 목표치)**
- 유료 고객 37명(회당 8만 원), 상담 준비 50분 → 10분
