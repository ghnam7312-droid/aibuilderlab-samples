# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버에 넣을 원문([ai-task.json](ai-task.json))입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 1일 | 메모 나누기 | ‘이름: 내용’ 줄은 그 학생, ‘공통:’은 모두, 이름 없는 줄은 바로 위 학생에게 붙여서 학생별 메모로 나눠 줘. 명단에 없는 이름은 따로 알려 줘. |
| 2일 | AI 초안 | 학생마다 따로 AI를 부르고, 그 학생 메모만 보내. 보호자면 ‘○○ 학생 보호자님’, 성인이면 ‘○○ 님’으로 시작해. |
| 3일 | 확인 단계 | 메시지에 명단의 다른 학생 이름이 있으면 빨갛게 표시하고 보내기를 막아. 튜터가 카드마다 ‘미리보기 확인’을 눌러야 보낼 수 있고, 확인 뒤 고치면 확인이 풀리게. |
| 4일 | 발송 기록 | 보낸 기록에는 시간, 이름, 가운데를 가린 번호, 글자 수만 남겨. 본문은 저장하지 마. |

## 2. 서비스가 쓰는 지시문

### lessonreport.draft
```
영어 회화 수업이 끝난 뒤 학생 한 명에게 보낼 수업 리포트 메시지를 쓴다.
받는 사람은 input.recipient(보호자면 '안녕하세요, {이름} 학생 보호자님.', 본인이면 '{이름} 님,'으로 시작).
message는 오늘 배운 것(input.common), 이 학생에 대한 관찰(input.notes), 다음 수업 전까지 할 일 순서로 6~9줄,
끝에 '— {input.tutor} 드림'. 학생 이름(input.student)을 반드시 넣는다.
input.notes와 input.common에 있는 내용만 쓰고, 없는 칭찬·점수·진도를 지어내지 않는다.
다른 학생 이름이나 다른 학생과의 비교는 넣지 않는다.
결석이면 결석 안내와 오늘 다룬 내용만 쓴다.
highlights는 이 학생의 잘한 점 최대 3개를 짧게, next는 다음 수업 전까지 할 일 한 줄.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"message":"","highlights":[""],"next":""}
```
- 입력: `{ student, recipient, className, common, notes, tutor }` — **그 학생 메모만** · 최대 700토큰
- 화면 검사: `normalizeDraft()` — 20~900자, 학생 이름 포함, 메모에 없던 다른 학생 이름이 있으면 버림. 통과해도 `checkMessage()`와 미리보기 확인을 거친다.

## 3. 왜 이렇게 썼나

- **학생 한 명씩, 그 학생 메모만** — 반 전체 메모를 한 번에 주면 섞일 수 있다. 입력에서부터 막는다.
- **다른 학생 이름·비교 금지** — 보호자에게 다른 아이 이야기가 가면 안 된다. 그래도 지시문만 믿지 않고 화면 검사와 확인 단계를 둔다.
- **인사 형식을 정해 줌** — 화면 검사가 ‘받는 학생 이름이 있는지’로 잘못 쓴 메시지를 걸러 낼 수 있게.

## 4. 실패했던 이전 버전

```
아래 수업 메모로 학생별 카톡 피드백을 써 줘. (반 전체 메모를 한 번에)
```
- 결과: 한 번에 5명분이 와서 편했지만, 짝 활동 이야기가 양쪽 학생 메시지에 모두 들어갔고, 한 학생 문단에 다른 학생의 숙제 이야기가 섞였다.
- 메모에 없는 칭찬을 덧붙였다.
- → 학생별로 따로 부르고, 그 학생 메모만 보내고, 지어내기·다른 학생 언급을 금지하고, 보내기 전 확인 단계를 붙였다.
