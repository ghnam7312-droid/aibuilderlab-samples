# 값매김

> 플랫폼 수수료·결제 수수료·재료비·작가 시간까지 **끝까지 빼고** 수강생 1명당 남는 돈을 계산하고, 사전 신청 테스트로 2기 클래스의 가격과 구성을 정하는 계산표

> **알림** AI 빌더랩 스타트업 트랙 **1기 목표 모델(가상의 수강생 ‘그림한스푼’)** 의 예시 프로젝트입니다. 수수료율·재료비·사전 신청 숫자는 모두 가상의 클래스 샘플이며(실제 플랫폼의 요율이 아님), 결과 숫자는 1기 목표치입니다.

## 문제 → 해결

| 문제 | 해결 |
|---|---|
| 1기는 가격을 감으로 정해서 남는 게 거의 없었다 | 구성별로 1인당 남는 돈 · 남는 비율 · 손익분기 인원을 바로 계산 |
| 플랫폼 수수료를 빼먹은 계산 (1인당 27,500원 남는 줄 알았는데 실제 14,735원, 60명이면 손해) | **수수료·재료비 포함해 다시 계산.** 빠진 비용이 있으면 경고하고, ‘1기 계산 방식’으로 켜서 차이를 비교 |
| 비싼 구성이 1인당 더 남아도 안 팔리면 소용없다 | 사전 신청 테스트(가격 카드별 방문·신청)로 **방문자 1명당 남는 돈**을 비교해 추천 |

결과 (1기 목표치) · 사전 신청 64명 · 객단가 6.9만 → 9.9만 원

## 주요 기능

- **1기 돌아보기** — 그때 계산(수수료 빠짐) → 다시 계산 → 2기 정한 구성을 한 줄로.
- **비용 설정** — 플랫폼·결제 수수료(%), 재료 키트·배송, 작가 시간 1시간 값, 기수 고정비, 모집 페이지 방문자. 빠진 비용·팔수록 손해인 구성 경고.
- **구성 3가지** — 가격·작가 시간·키트 포함을 고치면 비용 막대와 1인당 남는 돈, 손익분기 인원이 바로 바뀐다.
- **사전 신청 테스트** — 방문·신청을 고치면 신청률, 방문자당 남는 돈, 예상 수강생·이익을 다시 계산하고 추천이 바뀐다.
- **추천 → 이 구성으로 정하기 (되돌리기)**, **계산표 내보내기 (.csv)**, 샘플로 되돌리기.

## AI는 이렇게 동작합니다

| 상황 | 동작 | 화면 표시 |
|---|---|---|
| Claude 연결됨 (‘추천 다시 받기’, 처음 열 때) | `classpricing.review` → 구성 id · 숫자 검사 → 추천 이유 덮어쓰기 | `Claude로 정리 · 2.0초` |
| AI 키 없음 · 한도 초과 · 알 수 없는 작업 | 방문자당 남는 돈이 가장 큰 구성을 규칙으로 추천 | `규칙 기반 · (이유)` |
| 없는 구성 · 입력에 없는 숫자 · 형식 오류 | 버리고 규칙 추천 유지 | `규칙 기반 · 입력에 없는 숫자·형식 오류라 버림` |
| Claude 추천 뒤 숫자를 고침 | 규칙 추천으로 돌아감 | `규칙 기반 · 숫자가 바뀌어 규칙으로 다시 계산` |

계산 자체(수수료·남는 돈·손익분기)는 늘 `logic.js`가 하고, AI는 추천 이유만 씁니다. 자세한 흐름은 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), 지시문은 [docs/PROMPTS.md](docs/PROMPTS.md), 서버용 작업 정의는 [docs/ai-task.json](docs/ai-task.json).

## 기술 스택

| 구분 | 사용 |
|---|---|
| 화면 | HTML · CSS · JavaScript (프레임워크·빌드 없음) |
| 계산 | 수익 계산표 (`logic.js`, 원 단위 정수) |
| AI | Claude API — 서버 `aibuilderlab.kr/api/demo/ai`가 호출 |
| 테스트 | Node 내장 `node:test` |
