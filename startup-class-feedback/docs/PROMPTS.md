# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 서버용 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 2주 | 대기열 | 과제 목록을 오래 기다린 순으로 정렬해 줘. 오늘 날짜는 인자로 받고, 3일 넘은 과제 수와 평균 대기일도 계산해 줘. |
| 2주 | 그림 분석 | 캔버스 밝기 배열만 받아서 명암 대비, 그림 중심이 가운데서 벗어난 정도, 그림이 차지한 넓이를 계산하는 함수를 만들어 줘. 바탕은 네 귀퉁이에서 읽어. |
| 3주 | 예시 기준 | 내가 쓴 피드백 예시 30개를 줄게. AI 초안은 이 예시 안에서만 쓰고, 근거로 쓴 예시 번호를 같이 돌려주게 해 줘. |
| 3주 | 응답 검사 | AI 응답에서 근거 번호가 보낸 예시 밖이거나, 내가 안 쓰는 표현 목록에 걸리면 null을 돌려주는 검사 함수와 테스트를 써 줘. |

## 2. 서비스가 쓰는 지시문 (`classfeedback.draft`)

공통 꼬리말: `모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.`

```
그림 수업 과제에 줄 피드백 초안을 쓴다. 반드시 input.examples(작가가 직접 쓴 피드백 예시)의
내용과 말투 안에서만 쓰고, 예시에 없는 조언·도구·평가는 넣지 않는다. good은 좋은 점 한두 문장,
next는 input.tags 항목에 대한 다음에 해 볼 것 한두 문장. 존댓말 '~요' 체로, 단정하거나 나무라는
말은 쓰지 않는다. basis에는 근거로 쓴 예시 id를 그대로 넣는다(예시에 없는 id 금지). input에 없는
사실(그림 내용, 수강생 사정)을 지어내지 않는다. 마지막 한 줄은 작가가 쓰므로 맺음말은 쓰지 않는다.
출력 형식: {"good":"","next":"","basis":["E01"]}
```
- 입력: `{ title, note, tags, analysis, examples:[{id, tag, kind, text}] }` — examples는 고른 항목의 예시와 좋은 점 예시만 · 최대 500토큰
- 화면 검사: `normalizeDraft()` — 길이, 근거 번호가 보낸 예시 안에 있는지, 평소 쓰지 않는 표현(`OFF_STYLE`)이 없는지

## 3. 왜 이렇게 썼나

- **예시를 입력으로 보낸다.** 지시문에 “작가 말투로”라고만 쓰면 AI가 생각하는 ‘좋은 미술 선생님’ 말투가 나온다. 실제 문장을 보여 주는 쪽이 정확했다.
- **근거 번호를 받는다.** 번호가 있으면 화면에서 기계적으로 검사할 수 있고, 작가는 번호를 눌러 원래 문장과 비교할 수 있다.
- **맺음말을 쓰지 않게 한다.** 마지막 한 줄은 작가의 몫이라 AI가 인사로 끝내면 겹친다.

## 4. 실패했던 이전 버전

```
이 그림 과제에 대해 친절한 미술 선생님처럼 피드백을 써 줘. 명암 대비는 21%, 그림이 가운데서 19% 벗어나 있어.
```
- 결과: “포토샵의 레벨 기능으로 대비를 높여 보세요”, “기초부터 다시 연습하시는 것을 추천드립니다.”
- 문제: 수업에서 쓰지 않는 도구를 권하고, 수강생을 나무라는 말투. 작가가 매번 다 지우고 다시 썼다.
- 고친 점: 예시 30개를 입력으로, 근거 번호 필수, 화면에서 말투 검사.
