# 오답지도 · AI 활용 기록

> 1기 목표 모델 예시입니다. 개발하며 쓴 프롬프트(가상의 창업자 기준)와, 서비스가 실행 중에 Claude에게 보내는 실제 지시문을 함께 적었습니다.

## 1. 역할 나누기: 규칙과 Claude

| 단위 | 누가 | 왜 |
|---|---|---|
| 문항 하나의 오답 유형 | **규칙** (`classify`) | 40명 × 12문항 = 480칸. 매번 AI를 부를 필요가 없고, 결과가 늘 같아야 선생님이 검수할 수 있다 |
| 학생 한 명의 진단·학부모 코멘트·처방 | **Claude** (`wrong.coach`) | 오답 묶음을 읽고 문장을 쓰는 일. 규칙으로는 학생마다 비슷한 문장만 나온다 |

둘 다 선생님 검수 결과와 비교해 **일치율**을 화면에 보여 줍니다.

## 2. 실제 지시문 (서버)

```text
한 학생의 오답 목록(문항 단원, 유형 태그, 고른 답, 정답)을 보고
오답 유형을 개념 부족, 계산 실수, 문제 이해 중 가장 큰 하나로 판단하고,
학부모에게 보낼 2문장 코멘트와 다음 수업 처방 1개를 쓴다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"main":"","comment":"","prescription":""}
```

### 보내는 입력 예

```json
{
  "student": "이지유", "score": 2, "total": 12, "classAvg": 7.5,
  "wrongs": [
    { "no": 1, "unit": "유리수와 순환소수", "tag": "개념형", "chosen": 2, "answer": 3, "trapChoice": true, "teacherLabel": "계산 실수" },
    { "no": 6, "unit": "다항식의 계산", "tag": "서술·활용형", "chosen": 4, "answer": 3, "trapChoice": false, "teacherLabel": "" }
  ]
}
```

`teacherLabel`은 선생님이 검수에서 고친 유형입니다. Claude는 선생님 판단을 근거로 씁니다.

### 응답 검사 (`normalizeCoach`)
- `main`이 개념 부족·계산 실수·문제 이해가 아니면 버림
- 코멘트 8자 미만, 처방이 비면 버림 → 규칙 코칭(`ruleCoach`)

## 3. 만들면서 쓴 프롬프트 (주차별 대표)

| 주차 | 프롬프트 | 바뀐 것 |
|---|---|---|
| 4 | "손글씨 풀이 사진에서 학생이 틀린 이유를 뽑아 줘" → 인식 오류 많음 | 방향 전환: 고른 번호만 입력 |
| 4 | "40명 × 12문항 히트맵. 색은 오답 유형에만." | 오답 지도 |
| 5 | "고른 보기 번호만으로 오답 유형을 판단하는 규칙" | 문항표의 ‘계산 실수 보기’ 칸 |
| 5 | "검수를 빠르게: 한 번에 한 건, 키보드로" | 검수 카드 `Y` `N` `S` `Z` |
| 6 | "AI 진단이 맞는지 선생님 검수와 비교하는 지표" | Claude 진단 일치율 (학생 단위) |
| 6 | "학생마다 A4 한 장 오답 노트 인쇄 CSS" | `@media print` + `break-after` |

## 4. 디버깅 기록 (7건 중 대표)

| 증상 | 원인 | 고친 방법 |
|---|---|---|
| 손글씨 인식 결과가 엉뚱함 | 사진 품질·필체 | 입력을 고른 번호로 바꿈 |
| 일치율이 100%로만 나옴 | 건너뛴 건까지 ‘맞음’으로 셈 | 확인한 건만 세도록 `agreement` 분리 + 테스트 |
| Claude 유형 이름이 코드로 안 바뀜 | "계산 실수(부주의)"처럼 덧붙임 | 지시문 강화 + `normalizeCoach` |
| 인쇄 시 두 학생이 한 장에 | 페이지 나눔 없음 | `break-after: page` |
