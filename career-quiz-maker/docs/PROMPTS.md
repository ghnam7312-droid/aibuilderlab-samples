# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버 작업 정의(`docs/ai-task.json`)의 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 5주 | 규칙 문항 | 수업 자료를 ‘## n차시’ 줄로 나누고, “A를 B라고 한다” 문장에서 B를 정답으로 하는 객관식을 만들어 줘. 오답 선지는 같은 차시에서 가까이 나온 용어로. |
| 5주 | 응답 검사 | Claude가 준 문항에서 없는 차시, 선지 수가 4개(OX 2개)가 아닌 것, 정답 번호가 범위 밖인 것은 버리고 남는 게 없으면 null. |
| 6주 | 자동 확인 | 근거 문장이 자료에 있는지(띄어쓰기 무시), 근거에 정답이 있는지, 다른 선지도 근거에 나오는지 검사하는 함수와 테스트. |
| 6주 | 검토표 | 문항마다 통과 · 고치기 · 제외 버튼. 고치면 다시 자동 확인하고 ‘고쳐서 통과’로, 제외는 되돌리기. |

## 2. 서비스가 쓰는 지시문 — `quizmaker.generate`

```
수업 자료로 차시별 확인 퀴즈를 만든다. input.lessons는 차시(no, title, text), input.perLesson은 차시당 문항 수다.
문항은 그 차시 text에 있는 내용으로만 만들고, 자료에 없는 사실을 지어내지 않는다.
객관식은 options 4개(서로 다르게), OX는 options ["O","X"]. answer는 정답 선지 번호(0부터).
evidence는 정답의 근거가 되는 문장을 그 차시 text에서 한 글자도 바꾸지 않고 그대로 옮긴다.
정답 낱말은 evidence 안에 있어야 하고, 오답 선지는 evidence만 읽어도 틀렸다고 알 수 있게 고른다.
근거 문장을 찾을 수 없는 문항은 만들지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"questions":[{"lesson":1,"stem":"","options":[""],"answer":0,"evidence":""}]}
```
- 입력: `{ lessons[{no,title,text}], perLesson }` (차시당 3,000자까지) · 최대 1,500토큰
- 화면 검사: `normalizeGenerated()` → 문항마다 `checkQuestion()` → 사람 검토

### 왜 이렇게 썼나
- **근거를 ‘그대로 옮기게’ 했다.** 요약한 근거는 자료와 비교할 수 없다. 원문 그대로여야 화면이 자료에서 찾아볼 수 있다.
- **정답 낱말이 근거 안에 있어야 한다**고 못 박았다. 그래야 “근거에 정답이 없음” 검사가 정답 오류를 잡는다.
- **근거가 없으면 만들지 않는다.** 문항 수를 채우려고 자료 밖 지식을 끌어오는 것을 막는다.

## 3. 실패했던 이전 버전

```
다음 수업 자료로 차시별 확인 퀴즈 5문항씩 만들어 줘. 객관식 4지선다, 정답 표시.
```
- 정답 표시가 틀린 문항이 섞였다. 근거가 없어 왜 그 답인지 확인하려면 자료를 처음부터 다시 읽어야 했다.
- 자료에 없는 내용(다른 교과서 내용)으로 만든 문항이 나왔다.
- 문항 수를 맞추려고 같은 내용을 말만 바꿔 두 번 냈다 → 지금 버전: 근거 문장을 원문 그대로, 근거가 없으면 만들지 않기, 화면 자동 확인 + 사람 검토.
