# 차곡퀴즈 개발 일지 (커리어 트랙 5~6주차)

> **1기 목표 모델**: 가상의 수강생 ‘배움설계자’가 이렇게 진행하는 것을 목표로 쓴 일지입니다. 실제 수강생의 기록이 아닙니다.
> 숫자는 COVI 학습 기록 기준이며, 포트폴리오에 적은 합계와 같습니다.

| 시기 | 만든 것 | 프롬프트 | 디버깅 | 시간 |
|---|---|---|---|---|
| 5주차 전반 | 퀴즈 쓰는 시간 재기, 차시 나누기 · 규칙 문항 | 9 | 1 | 1.0h |
| 5주차 후반 | Claude 문항 생성 + 형식 검사 | 10 | 1 | 1.5h |
| 6주차 전반 | 정답 근거 문장 + 자동 확인 + 검토표 | 8 | 1 | 1.5h |
| 6주차 후반 | 내보내기 · 인쇄, 테스트 | 7 | 1 | 1.0h |
| **합계** | | **34** | **4** | **5h** |

## 5주차 전반 — 1시간이 어디로 가나

**한 일**
- 한 차시 확인 퀴즈를 쓰는 데 걸린 1시간을 나눠 보니: 자료 다시 읽기 15분, 문항·선지 쓰기 30분, 정답 확인 15분.
- 자료를 `## 1차시` 줄로 나누고, “○○을 □□라고 한다”, “□□는 ○○이다” 문장에서 객관식을 만드는 규칙을 먼저 만들었다. 오답 선지는 같은 차시에서 가까이 나온 용어로.

**막힌 것 → 해결**
- “온도을(를) 무엇이라고” 같은 어색한 조사 → 마지막 글자 받침으로 을/를을 고르는 `josa()`.

---

## 5주차 후반 — Claude에게 맡기기

**한 일**
- `quizmaker.generate`로 차시별 문항을 Claude가 만들게 했다. 규칙 문항이 먼저 뜨고, Claude 문항이 오면 덮어쓴다.
- 차시 번호가 자료에 없거나, 선지가 4개(OX는 2개)가 아니거나, 정답 번호가 범위를 넘으면 버리는 `normalizeGenerated()`.

**막힌 것 → 해결**
- 선지 배열이 문자열 하나로 올 때가 있음 → 서버가 풀어 주고, 화면은 형식이 다르면 그 문항만 버림.

---

## 6주차 전반 — 정답이 틀린 문항

**한 일 · 막힌 것 → 해결**
- **정답이 틀린 문항이 섞임** → 생성된 문항을 그대로 풀어 보니 정답 표시가 틀린 것이 섞여 있었다(‘증발’ 문항의 정답이 ‘기화’로 표시되는 식). 그래서 문항마다 **정답 근거 문장을 자료에서 그대로 옮겨 함께 내게** 하고, 사람이 근거를 읽고 확인하는 검토표를 만들었다.
- 근거를 보는 데도 시간이 들어서, 먼저 볼 문항을 알려 주는 자동 확인 세 가지를 붙였다: 근거가 자료에 있는지, 근거에 정답이 있는지, 다른 선지도 근거에 나오는지(`checkQuestion`).
- 검토표: 통과 · 고치기(고쳐서 통과) · 제외. 손대지 않고 통과한 비율을 ‘통과율’로 본다.

---

## 6주차 후반 — 바로 수업에 쓰게

**한 일**
- 통과한 문항만 내보낸다: 학생용 복사(정답 없음), 교사용 CSV(정답·근거 문장), 학생용 인쇄.
- 로직을 `logic.js`로 분리하고 테스트 12개.

**막힌 것 → 해결**
- 인쇄하면 검토표 버튼까지 찍힘 → 인쇄 때는 학생지만 보이게 `@media print`.

**결과 (1기 목표치)**
- 차시당 퀴즈 1시간 → 12분, 문항 검토 통과율 88%
