## 문제 → 해결

| 전에는 | 이제는 |
|---|---|
| 금요일마다 판매 시스템·엑셀·메일을 오가며 숫자 복사 (**1시간**) | 숫자 7줄만 확인하면 보고서 완성 (**10분**) |
| 증감률·전환율을 계산기로 다시 계산 | 전주 대비 증감·전환율·객단가 자동 계산 |
| 요약 문장을 매번 새로 씀 | Claude가 요약을 쓰고, **숫자는 금요보고가 검산** |
| 차트 날짜가 하루씩 밀림 | 모든 날짜를 **한국 시간(KST)** 으로 고정 |

## AI를 믿되, 숫자는 검산한다

요약 문장은 Claude(`report.summary`)가 씁니다. 그런데 보고서의 숫자가 틀리면 안 되니까, 금요보고는 문장 속 숫자를 **하나하나 뽑아 실제 데이터와 맞춰** 봅니다.

```
이번 주 매출은 [3,612만 원✓]으로 지난주보다 [12.2%✓] 늘었고 …
가장 좋았던 날은 [10/9(금)✓]으로 매출 [640만 원✗], 지난주보다 [52.4%✗] 높았습니다.
                                        ↑ 데이터에 없는 숫자 → 빨간 표시, 발송 전 경고
```

- 맞는 숫자는 초록 밑줄, 마우스를 올리면 **출처**(예: “10/9(금) 매출”)가 보입니다.
- 데이터에 없는 숫자가 있으면 보고서에 ‘확인 필요’가 뜨고, 메일 미리 보기의 보내기 버튼이 **‘확인했고 보내기’** 로 바뀝니다. 그래도 보내면 발송 기록에 ‘검산 경고’로 남아요.
- 입력 숫자를 고치면 Claude 문장은 그대로 두고 **검산만 다시** 합니다. 바뀐 숫자가 바로 빨갛게 드러나요.
- Claude가 안 되면(키 없음·한도·오류) 규칙으로 요약을 씁니다. 규칙 문장도 같은 검산을 거칩니다.
- 한계: 숫자가 데이터 **어딘가에 있는지**만 봅니다. 맞는 숫자를 엉뚱한 지표에 붙인 경우는 못 잡아요. 그래서 보내기 전 사람이 한 번 읽는 단계를 남겼습니다.

## 주요 기능

- **숫자 입력** — 쉼표·단위 허용, 글자·빈칸·소수·‘주문 > 방문’은 그 자리에서 거름, Enter로 아래 칸
- **보고서 만들기** — 머리 → 핵심 숫자(올라가며 세기) → 막대 → 전환율 선 → 요약 순서로 한 장이 채워짐
- **일별 차트** — 직접 그린 SVG, 매출/주문/방문 전환, 한글날 표시, 같은 요일 비교 말풍선
- **요약 + 검산** — Claude 4문장, 숫자마다 ✓/✗, ‘요약 다시 쓰기’·‘규칙 문장으로 바꾸기’
- **메일 미리 보기** — 실제 메일처럼: 보낸·받는 사람, 제목, 핵심 지표 표, 차트, 요약, PDF 첨부
- **발송 설정** — 받는 사람(형식 검사·되돌리기), 매주 금 17:00 예약(데모: 기록만), 발송 기록
- **PDF로 저장** — A4 한 장에 맞춘 인쇄 스타일

| HTML · CSS · JavaScript (빌드 없음), SVG 직접 그리기 | 판매 시스템 내보내기 파일 자동 읽기 |

| `node --test` 단위 테스트 14개 | |

## 폴더 구조

```

├── index.html          화면 뼈대 (메일 미리 보기 창 포함)

├── CHANGELOG.md
```
