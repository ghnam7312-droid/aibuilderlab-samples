# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 9주 | 인터뷰 정리 | 담당자 8명 인터뷰 메모를 요구 5가지(보고 근거, 현업 적용, 리마인드, 팀장 참여, 복습)로 태그하고 몇 명이 원했는지 세 줘. 1인 예산 중앙값도. |
| 9주 | 가격 | 구성 요소마다 1인 가격 또는 고정 가격을 두고, 인원을 넣으면 3개월·월·1인 금액을 천 원 단위로 내 줘. 50명 이상 10%, 100명 이상 15% 할인. |
| 10주 | 문구 검사 | 제안 문구에서 ‘보장’, ‘반드시’, ‘100%’, ‘성과가 오릅니다’ 같은 표현을 찾아 위치와 이유를 알려 줘. ‘보장하지 않습니다’ 같은 부정문은 빼고. |
| 10주 | 측정 약속 | 걸린 문장을 “시점에 지표를 방법으로 재서 보고합니다” 문장으로 바꿔 줘. 고른 구성의 지표를 차례로 쓰고, 조사는 받침에 맞춰. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### trainingfollowup.copy
```
기업 교육 후 3개월 후속 관리 상품의 제안 문구를 쓴다. input.modules(구성과 각 지표·방법·시점), input.interviews(담당자 요구 요약), input.price, input.draft(초안)만 근거로 쓰고,
input에 없는 성과 수치나 고객 사례는 지어내지 않는다.
효과·성과를 보장하거나 단정하는 말(보장, 반드시, 무조건, 확실히, 100%, 성과가 오른다 등)은 쓰지 않는다. 대신 무엇을(지표) 어떻게(방법) 언제(시점) 재서 보고하는지를 약속한다.
headline은 30자 이내 한 문장. pitch는 담당자 요구와 구성을 이은 2~3문장. promises는 modules마다 하나씩 metric, method, timing을 input 그대로 쓴다.
flags는 draft에서 보장·단정으로 읽히는 표현과 그 이유, 측정 약속으로 고친 문장. 표현이 법적으로 괜찮은지는 판단하지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"headline":"","pitch":"","promises":[{"metric":"","method":"","timing":""}],"flags":[{"phrase":"","reason":"","rewrite":""}]}
```
- 입력: `{ draft, modules, interviews: { n, needs, quotes }, price }` · 최대 1,000토큰
- 화면 검사: `normalizeCopy()` (형식 검사 + 헤드라인·소개·약속에 보장·단정 표현이 있으면 통째로 버림, 고친 문장에 보장 표현이 남으면 비움) → 실패하면 규칙 문구 유지

## 3. 왜 이렇게 썼나

- **금지 낱말을 예로 적음** — “과장하지 말라”만으로는 ‘확실히’, ‘100%’가 남았다. 낱말을 직접 적고, 화면 검사기와 같은 목록을 쓰게 맞췄다.
- **약속 형식을 고정** — promises를 metric·method·timing 세 칸으로 받아, 측정 약속이 빠지면 화면에서 바로 알 수 있게 했다.
- **법적 판단 금지** — AI가 “이 문구는 문제없습니다”라고 쓰면 사람이 확인을 건너뛸 수 있다. 판단은 사람 몫으로 남기고, 화면의 확인 체크로 이어지게 했다.

## 4. 실패했던 이전 버전

```
구독형 교육 후속 관리 상품의 매력적인 제안 문구를 써 줘. 효과를 강조해 줘.
```
- “3개월이면 팀 성과가 확실히 달라집니다”, “만족도 100%를 약속합니다”처럼 **보장·단정 문구**가 나왔다. 인터뷰에서 담당자들이 가장 싫어한 표현이라, ‘효과를 강조’ 대신 ‘무엇을 어떻게 재는지 약속’으로 목표를 바꿨다.
