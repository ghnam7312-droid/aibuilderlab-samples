# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 서버 작업 정의(`docs/ai-task.json`)의 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 3주 | 문항 설계 | 초등 4학년 분수 진단 문항 10개를 만들어 줘. 오답 선지마다 어떤 오개념에서 나오는지 표시하고, 오개념 5가지가 각각 2문항 이상에서 드러나게. |
| 3주 | 채점 | 고른 선지 번호 배열을 받으면 점수와 유형별 오답 수를 돌려주는 함수. 안 푼 문항과 단순 실수는 오개념으로 세지 마. |
| 4주 | 이름 노출 | 학생 화면 주소에 이름 대신 번호만 쓰게 바꿔 줘. 주소나 CSV에 명단 이름이 들어 있으면(URL 인코딩 포함) false를 돌려주는 검사 함수와 테스트도. |
| 4주 | 응답 검사 | Claude 설명에서 type이 유형 목록에 없거나 그 학생 오답 수가 0인 유형은 버리고, 남는 게 없으면 null. |

## 2. 서비스가 쓰는 지시문 — `fractionquiz.explain`

```
초등 분수 진단 퀴즈에서 한 학생이 틀린 문항을 보고 교사에게 오개념을 설명한다.
input.wrong은 틀린 문항(문제, 고른 답, 정답, 규칙이 붙인 유형 tag), input.counts는 유형별 오답 수,
input.types는 유형 목록이다. types에는 counts가 1 이상인 유형만, type은 input.types의 key 그대로 쓴다.
why는 고른 답을 근거로 아이가 어떻게 생각했는지 한 문장, activity는 교실에서 5분 안에 할 수 있는
구체적 활동 한 문장. summary는 점수와 핵심 오개념 한 문장, talk는 아이에게 이유를 말하게 하는 질문 한 문장.
학생 이름은 받지 않으며 쓰지 않는다. input에 없는 사실(가정환경, 성격, 학습 부진 여부)을 지어내지 않고,
진단·판정은 교사가 하도록 단정하지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"summary":"","types":[{"type":"add","why":"","activity":""}],"talk":""}
```
- 입력: `{ no, score, wrong[], counts, types[] }` — 이름 없음 · 최대 700토큰
- 화면 검사: `normalizeExplain()` — 규칙이 근거를 찾은 유형만 남김

### 왜 이렇게 썼나
- **분류는 규칙이, 설명은 Claude가.** 오개념 분류는 선지에 붙인 표시로 이미 정확하게 끝난다. Claude에게는 “왜 그렇게 생각했을지”와 “교실 활동”만 맡겨, 틀린 분류가 나올 여지를 없앴다.
- **이름을 받지 않는다.** 입력에 이름이 없으니 응답에도 나올 수 없다.
- **단정하지 않는다.** 학습 부진·지원 필요 같은 판단은 교사가 아이와 이야기해 보고 한다.

## 3. 실패했던 이전 버전

```
이 학생의 답을 보고 어떤 오개념이 있는지 분석해 줘. 학생 이름: {이름}
```
- 이름을 그대로 보냈다(지금은 번호만).
- Claude가 유형을 스스로 정해서 매번 이름이 달랐다(“분수 덧셈 개념 부족”, “통분 미숙” …). 반 전체 표로 묶을 수 없었다.
- “집중력이 부족해 보인다”처럼 답에 없는 성격 판단이 섞였다 → 유형 목록을 input으로 주고 그 key만 쓰게, 없는 사실은 지어내지 않게 바꿨다.
