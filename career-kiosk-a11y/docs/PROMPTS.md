# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 이 서비스가 서버에 등록해 쓰는 원문입니다([ai-task.json](ai-task.json)).

## 1. 만들 때 쓴 프롬프트 (대표 5개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 9주 | 관찰 정리 | 키오스크 관찰 메모를 명도 대비·글자 크기·누르는 영역·시간 제한·소리 안내·단계·높이 7개로 분류하고, 이용자·심각도·빈도를 붙이는 표 형식을 만들어 줘. |
| 9주 | 대비 계산 | 글자색과 바탕색 hex로 WCAG 명도 대비를 계산하는 함수. 상대 휘도 공식 그대로, 소수 둘째 자리에서 버림. 흑백 21, #767676은 4.54가 나오는지 테스트. |
| 10주 | 기준 확인 | 아래는 W3C WCAG 2.2 원문에서 옮긴 기준이야(1.4.3, 1.4.11, 2.5.8, 2.5.5, 2.2.1, 1.4.4). 네가 앞에서 알려 준 기준과 다른 곳을 표로 짚어 줘. |
| 10주 | 대조 함수 | AI가 말한 기준을 id·수치·큰 글자 수치·버전·등급으로 받아 공식표와 비교하고 일치/다름/사람이 확인을 돌려주는 함수. 다르면 무엇이 다른지 문장으로. |
| 10주 | 제안서 | 관찰 문제를 분류별 개선안으로 묶고 심각도×빈도로 우선순위. 개선안마다 근거 기준 번호를 붙이고, 공식 수치가 없는 건 ‘담당 부서 확인’으로. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### kioska11y.proposal
```
학교 식당 키오스크 현장 관찰 결과로 접근성 개선 제안서를 쓴다. input.observations(문제 번호 id, 분류, 이용자, 심각도·빈도 1~3, 내용)와 input.measured(화면 측정값)만 근거로 쓴다. 같은 원인의 문제를 묶어 개선안 items를 만들고, issues에는 관련 문제 번호를 그대로 넣는다. 모든 문제 번호는 한 개선안에만 넣는다. action은 화면·버튼·글자·소리·순서를 어떻게 바꿀지 한 문장. criterion은 input.criteria의 id 중 하나만 쓰고, 맞는 것이 없으면 빈 문자열. 기준 수치를 말할 때는 claimValue에 숫자로 쓰고, input.criteria의 rule에 없는 수치나 예전 버전 기준은 쓰지 않는다. priority는 높음·보통·낮음(심각도×빈도가 큰 것이 높음). 법적 의무 여부나 위반 여부는 판단하지 않는다. 관찰에 없는 문제나 사실을 지어내지 않는다. summary는 가장 먼저 고칠 것 한 문장. 모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"items":[{"title":"","issues":[""],"action":"","criterion":"","claimValue":0,"priority":""}],"summary":""}
```
- 입력: `{ observations, measured, criteria }` — criteria는 화면의 공식 지침표(OFFICIAL)를 그대로 보냄 · 최대 1400토큰
- 화면 검사: `normalizeProposal()` — 문제 번호·기준 id 검사, `claimValue`를 `verifyClaim()`으로 대조, 법적 판단 문장 제거, 빠진 문제는 규칙으로

## 3. 왜 이렇게 썼나

- **기준을 input으로 준다** — 모델이 기억하는 기준이 오래된 버전일 수 있어서, 공식 지침표를 매번 함께 보내고 그 안에서만 고르게 했습니다.
- **수치는 숫자 칸으로** — 문장 속 숫자는 검사하기 어렵습니다. `claimValue`로 따로 받아 지침표와 기계적으로 비교합니다.
- **문제 번호로 연결** — 개선안마다 관찰 번호를 받아, 근거 없는 개선안을 거르고 화면에서 관찰과 오갈 수 있게 했습니다.
- **법적 판단 금지** — 학교 시설의 법적 의무 여부는 담당 부서가 판단할 일이라 지시문에서 막고, 화면 검사에서 한 번 더 지웁니다.

## 4. 실패했던 이전 버전

| 버전 | 지시문 | 문제 |
|---|---|---|
| v1 | “키오스크 접근성 기준을 알려 주고 개선안을 써 줘” | 기준을 기억에서 꺼내 WCAG 2.0 시절 설명(누르는 영역 44px을 최소 기준처럼)과 ‘큰 글자도 4.5:1’이 섞임. ‘현재 높이는 법 위반’ 같은 판단도 들어감 |
| v2 | 위 지시문 (공식 지침표를 input으로, 수치는 claimValue, 법적 판단 금지) + 화면 대조 | 기준이 지침표 안에서만 나오고, 다른 수치는 ‘다름’으로 표시된 뒤 공식값으로 바뀜 |
