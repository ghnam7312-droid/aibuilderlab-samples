> **1기 목표 모델**: 가상의 수강생 ‘새벽기획자’가 이렇게 진행하는 것을 목표로 쓴 일지입니다. 실제 수강생의 기록이 아닙니다.
> 숫자는 COVI 학습 기록 기준(프롬프트 수 · 디버깅 수 · 작업 시간)으로, 포트폴리오에 적은 합계와 같습니다.

|---|---|---|---|---|
| 5주차 | 문제 정의, 쪽지 화면 | 9 | 1 | 1.0h |

## 5주차 — 문제를 좁히고, 쪽지 한 장부터

**한 일**
- 동아리 운영진 3명 인터뷰. “구글폼은 받는 건 쉬운데, 읽고 나누는 게 반나절”이 공통이었다.
- 범위를 ‘행사 당일 익명 한마디’로 좁혔다. 회원 가입, 설문 문항 만들기는 하지 않는다.
- 쓰는 동안 쪽지 색이 바뀌는 화면을 먼저 만들었다. 분류가 눈에 보여야 믿고 쓴다고 판단했다.

**쓴 프롬프트 (요약)**
> 행사 피드백을 받는 한 페이지 웹을 만들고 싶어. 이름 없이 300자까지 쓰는 쪽지 모양 입력칸, 손글씨 느낌 글꼴, 남기면 벽에 붙는 화면. HTML/CSS/JS 한 폴더로.

**막힌 것 → 해결**
- 한글을 칠 때 글자 수가 한 박자 늦게 바뀜 → `keyup` 대신 `input` 이벤트로 바꿔 해결.

## 6주차 — 규칙으로 시작해 Claude로 올리기

**한 일**
- 단어 사전 규칙으로 칭찬·개선 요청·질문·기타를 나눴다. 키를 칠 때마다 즉시 돈다.
- 남길 때는 Claude가 문맥으로 다시 나누게 했다. (`guestbook.classify`)
- Claude 응답은 바로 쓰지 않고 `normalizeClassify()`로 검사한다. 정해진 범주가 아니면 규칙 결과를 쓴다.

**막힌 것 → 해결**
- “조금 더 짧았으면 좋겠어요”가 **칭찬**으로 분류됨(‘좋’ 때문) → 바람 표현(‘~었으면’, ‘~면 좋겠’)이 있으면 ‘좋’ 계열을 칭찬 근거에서 빼는 규칙 추가. 테스트로 고정.
- Claude가 가끔 JSON 앞에 설명 문장을 붙임 → 지시문에 “JSON 하나만 출력”을 넣고, 서버에서 첫 `{`~마지막 `}`만 읽게 함.
- 응답의 `category`가 “불만”처럼 정해지지 않은 값으로 올 때 → 검사에서 버리고 규칙 결과 사용.

## 7주차 — 폰으로 남기면 벽에 붙는다

**한 일**
- 방문자마다 무작위 방 코드를 만들고, QR로 참가자 화면(`?room=코드&join=1`)을 연다.
- 참가자 글은 서버(`/api/demo/room`)에 저장되고, 벽은 3초마다 새 글만 가져온다(`after=마지막 번호`).
- 서버가 Claude로 분류해 저장한다. Claude가 안 되면 화면이 보낸 규칙 분류를 저장한다.

**막힌 것 → 해결**
- 배포 후 남긴 글이 벽에 안 보임 → 브라우저에서 Supabase를 직접 읽고 있었는데 **RLS 읽기 정책이 없었다**. 정책을 여는 대신, 방 코드 검사와 도배 제한(10분 20건)을 하려고 서버 API로 옮기고 테이블은 서버만 읽게 잠갔다.
- 숨긴 쪽지가 3초 뒤 다시 나타남 → 폴링 기준을 ‘화면에 있는 가장 큰 번호’에서 ‘지금까지 받은 가장 큰 번호(cursor)’로 바꿔 저장.
- 탭을 오래 열어 두면 요청이 계속 나감 → 화면이 숨겨지면 15초, 실패가 이어지면 간격을 늘림.

## 8주차 — 운영진의 할 일까지

**한 일**
- `guestbook.summary`: 세 줄 요약 + 개선 요청을 주제별로 묶은 ‘운영진이 할 일’.
- 새 의견이 쌓이면 “새 의견 N건 반영해 다시 요약” 버튼이 켜진다. 자동으로 계속 부르지 않아 비용을 아낀다.
- 행사 진행 모드: 프로젝터용 큰 QR + 벽. Esc로 끝낸다.
- 로직을 `logic.js`로 분리하고 테스트 18개 작성.

**막힌 것 → 해결**
- 전체 화면에서 Esc를 누르면 전체 화면만 풀리고 진행 모드는 남음 → `fullscreenchange`에서 진행 모드도 함께 끈다.

**결과 (1기 목표치)**
- 동아리 2곳, 사용자 74명, 피드백 212건
- 분류·정리 시간: 반나절 → 5분
