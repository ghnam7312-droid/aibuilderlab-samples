# 프롬프트 기록

> 1기 목표 모델 예시. 만들 때 쓴 프롬프트(COVI 기록 48개 중 주요한 것)와, 서비스 안에서 Claude에 주는 지시문입니다.

## 1. 만들 때 쓴 프롬프트

| 주차 | 목적 | 프롬프트 | 배운 점 |
|---|---|---|---|
| 3 | 첫 분류기 | 메일 제목과 본문을 받아 견적 요청·발주·문의·기타로 나누는 함수. 단어 목록은 밖으로 빼고, 맞은 단어도 돌려줘. | “왜 그렇게 나눴는지”를 같이 받으면 디버깅이 쉬워진다 |
| 3 | 오분류 원인 찾기 | 이 11통이 왜 전부 ‘기타’가 됐는지 점수표를 메일별로 보여 줘. | 끝인사 “감사합니다”가 범인. 데이터를 직접 봐야 보인다 |
| 4 | 사람에게 넘기기 | 1·2등 차이가 1점 이하면 사람에게 넘기고, 왜 애매한지 한 문장으로. | 자동화의 경계를 정하는 게 핵심 |
| 4 | 품목 추출 | 수량(숫자+개/대/박스) 바로 앞에 있는 품목 이름을 뽑아 줘. 짧은 이름보다 긴 이름이 우선. | 예시 3개를 주니 규칙이 정확해졌다 |
| 4 | 날짜 버그 | 서버가 UTC일 때도 한국 날짜로 D-day를 계산하게 고쳐 줘. 테스트도 써 줘. | 시간대 버그는 테스트로 박제 |
| 5 | AI 연결 | 확신 0.6 미만은 확인 필요, AI가 이상하면 규칙으로, 기다리는 동안 화면이 멈추지 않게. | “AI가 실패할 때”를 먼저 설계 |
| 5 | 응답 검증 | AI 응답 JSON에서 허용된 분류만 받고 나머지는 버리는 함수와 테스트. | AI 출력은 입력값처럼 검증한다 |
| 5 | 키보드 | J/K 이동, 1~4 분류, E 확정, ? 도움말. 입력 칸에 있을 때는 동작하지 않게. | 매일 쓰는 도구는 키보드가 빠르다 |

## 2. 서비스 안에서 Claude에 주는 지시문

지시문은 서버(`lib/demo-ai.ts`)에 있고 화면은 작업 이름만 보냅니다. 출력은 JSON 하나로 고정합니다.

### `mail.classify`

```
거래처 메일 한 통을 분류한다. category는 견적 요청, 발주·주문, 문의, 기타 중 하나.
confidence는 0~1. 두 범주 사이에서 애매하면 confidence를 0.6 미만으로.
reason은 근거 한 문장. 견적 요청·발주면 items에 품목명(수식어 포함), 수량(숫자), 납기를 뽑는다.
메일에 없는 것은 만들지 않는다.
출력 형식: {"category":"","confidence":0.0,"reason":"","items":[{"name":"","qty":0,"due":""}]}
```

### `mail.reply`

```
견적 요청 메일에 보낼 회신 초안을 쓴다. 받은 메일의 품목·수량·납기를 확인하는 문장,
단가와 납기 회신 예정 시점(영업일 1일 이내), 추가로 확인할 점 1~2개를 담는다.
정중하지만 짧게. 단가 숫자는 지어내지 않는다.
출력 형식: {"subject":"","body":""}
```

## 3. 지시문을 고친 이력

| 버전 | 바꾼 것 | 이유 |
|---|---|---|
| v1 | 분류만 요청 | — |
| v2 | `confidence` 추가, “애매하면 0.6 미만” | 사람에게 넘길 기준이 필요 |
| v3 | “메일에 없는 것은 만들지 않는다” | 수량이 없는 메일에 수량 1을 넣음 |
| v4 (회신) | “단가 숫자는 지어내지 않는다” | 초안에 가짜 단가가 들어감 |
