# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 7주 | 진단 | 사전 설문(고민 6개 중 복수 선택 + 자유 응답)으로 고민 순위를 % 로 내 줘. 자유 응답은 고르지 않은 항목만 낱말로 더해. |
| 7주 | 사례 틀 | 고민별 사례 틀에 업종 낱말(장소·조직 단위·업무·역할)을 끼워 넣어 줘. 끼운 낱말 뒤 조사는 받침에 맞춰. |
| 8주 | 입력 기준 | 자료마다 출처(공개/설문/내부)와 내용을 보고 사용·확인 필요·제외로 판정해 줘. 대외비, 인사 정보, 직원 실명, 연락처는 제외. 금액·비율은 확인 필요. |
| 8주 | 새어 나감 | 제외한 자료에서 숫자+단위, 실명, 따옴표 이름을 뽑아서, AI 사례에 그 낱말이 있으면(띄어쓰기 달라도) 그 사례를 버려 줘. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### trainingprep.cases
```
기업 교육 강사가 강의 전에 쓸 맞춤 사례 초안을 만든다. input.industry, size, topic, publicFacts(공개 정보), survey(사전 설문 요약)만 근거로 쓴다.
회사 내부 수치, 실명, 연락처, input에 없는 사실은 지어내지 않는다.
diagnosis는 survey.top에서 가장 많이 나온 고민을 비율과 함께 한 문장으로.
cases는 survey.top 순서로 3개, pain은 survey.top의 key 중 하나, title은 15자 이내,
situation은 그 업종 현장에서 일어날 법한 장면 2~3문장(특정 인물 이름 없이 '팀장', '팀원'처럼 역할로), question은 수강생에게 던질 토론 질문 한 개.
opener는 강의 첫 5분에 쓸 질문 한 개.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"diagnosis":"","cases":[{"pain":"","title":"","situation":"","question":""}],"opener":""}
```
- 입력: `{ industry, size, topic, publicFacts, survey: { n, top, quotes } }` — 기준을 통과한 자료와 설문 요약만 · 최대 1,200토큰
- 화면 검사: `normalizeCases()` (형식 검사 + 제외 자료 낱말이 섞인 사례 버림) → 실패하면 규칙 사례 유지

## 3. 왜 이렇게 썼나

- **근거 목록을 이름으로 못 박음** — publicFacts와 survey 말고는 쓰지 말라고 적어, 일반 상식으로 ‘업계 평균 이직률’ 같은 숫자를 붙이지 않게 했다.
- **인물 이름 대신 역할** — 사례 속 인물이 실제 직원처럼 읽히면 담당자가 불편해한다. ‘팀장’, ‘팀원’으로만 쓰게 했다.
- **pain 키 지정** — 사례가 어떤 설문 고민에서 나왔는지 화면에 붙이려고 survey.top의 key를 그대로 돌려받는다.

## 4. 실패했던 이전 버전

```
아래 회사 자료를 참고해서 피드백 리더십 강의 사례 3개 만들어 줘.
(담당자에게 받은 자료 전체 붙여 넣기)
```
- 대외비 실적 자료의 ‘이직률 18%’와 면담 메모 속 실명이 사례에 그대로 들어왔다. 강의 자료로 다른 사람 앞에 띄울 수 없는 결과라, 입력을 공개 정보와 설문 요약으로 제한하는 기준을 먼저 세우고 지시문을 다시 썼다.
