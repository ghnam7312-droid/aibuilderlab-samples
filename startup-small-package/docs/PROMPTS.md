# 프롬프트 기록

> 1기 목표 모델 예시입니다. ‘만들 때 쓴 프롬프트’는 가상의 수강생이 COVI에서 썼다고 가정한 대표 예시이고, ‘서비스가 쓰는 지시문’은 [ai-task.json](ai-task.json)에 있는 원문입니다.

## 1. 만들 때 쓴 프롬프트 (대표 4개)

| 시기 | 목적 | 프롬프트 |
|---|---|---|
| 8주 | 계산표 | 원룸 기본·원룸 플러스·투룸 기본 패키지마다 자재비+인건비+관리비로 원가를 내고, 판매가에서 이익과 마진을 계산해 줘. 목표 마진 아래면 최소 판매가를 10만 원 단위로 올려서. |
| 9주 | 단가 기준일 | 단가를 덮어쓰지 말고 기준일과 함께 기록으로 쌓아 줘. 계산은 기준일 이전 가장 최신 단가로 하고, 더 새 단가가 있는데 옛것을 쓰면 알려 줘. |
| 9주 | 비교 | 작년 단가로 계산했을 때와 최신 단가로 계산했을 때 마진을 카드에 나란히 보여 줘. |
| 9주 | 문구 검사 | AI 소개 문구에서 패키지 구성에 없는 항목은 빼고, 금액이나 '최저가' 같은 과장 표현이 있으면 버리는 함수와 테스트를 만들어 줘. |

## 2. 서비스가 쓰는 지시문 (서버 `/api/demo/ai`)

### smallpkg.pitch
```
소형 평수(원룸·투룸) 리모델링 패키지의 소개 문구를 쓴다. name은 input.name을 그대로 또는 짧게 다듬어 쓴다.
tagline은 누구에게 어떤 점이 좋은지 한 문장으로 쓴다. includes에는 input.includes에 있는 항목 이름만
그대로 쓴다. excludes에는 input.notIncluded 가운데 고객이 헷갈리기 쉬운 것을 고른다. faq는 이 패키지를
처음 보는 고객이 물을 만한 질문 2~3개와 짧은 답을 쓴다. 금액·할인·공사 기간은 쓰지 않는다(가격은
계산표가 따로 보여 준다). '최저가', '업계 최고', '100%', '무조건' 같은 과장 표현을 쓰지 않는다.
input에 없는 사실(자재 브랜드, 보증 기간, 후기 등)을 지어내지 않는다.
모든 문장은 한국어로, 짧고 구체적으로 쓴다. 반드시 JSON 하나만 출력하고 다른 말은 쓰지 않는다.
출력 형식: {"name":"","tagline":"","includes":[""],"excludes":[""],"faq":[{"q":"","a":""}]}
```
- 입력: `{ name, area, includes, notIncluded }` — 가격·원가는 보내지 않음 · 최대 600토큰
- 화면 검사: `normalizePitch()` — 구성에 있는 항목만 남기고, 금액·과장 표현이 있으면 규칙 문구 유지

## 3. 왜 이렇게 썼나

- **가격을 보내지 않는다.** 보내면 문장에 넣고 싶어 하고, 판매가를 고친 뒤에는 문장 속 가격이 틀린 값이 된다. 가격은 화면이 계산값으로 붙인다.
- **포함 항목은 이름 그대로.** “욕실 리모델링”처럼 넓게 바꿔 쓰면 고객은 욕실 전체 교체로 이해한다. 실제 구성 이름만 통과시킨다.
- **과장 금지.** 패키지는 신뢰가 먼저다. ‘최저가’는 확인할 수 없는 주장이다.

## 4. 실패했던 이전 버전

| 버전 | 지시문 | 결과 |
|---|---|---|
| v1 | “이 원룸 리모델링 패키지 홍보 문구를 매력적으로 써 줘. 가격 430만 원.” | “업계 최저가 단돈 430만 원!”, 구성에 없는 ‘욕실 전체 리모델링’과 ‘2년 무상 보증’을 씀 |
| v2 (지금) | 구성 이름만, 가격·과장·없는 사실 금지, 가격은 보내지 않음 + 화면 검사 | 문구가 구성·가격과 어긋나지 않음 |
